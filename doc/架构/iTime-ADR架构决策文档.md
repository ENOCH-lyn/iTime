# iTime ADR 架构决策文档

更新：2026-10-04。依据为[需求规格](../需求/iTime-需求规格说明书.md)。**已确认**表示用户的产品或技术约束；**已采纳（工程）**表示授权开发中的实施选择；**建议**尚未实现或验证；**待决策**须在对应模块实施前确定。当前仅在本地运行，未生产部署。

## ADR-001：统一服务端与分阶段客户端

**状态：边界已确认。**

先交付完整 Web 用户端和 Web 后台，再 Android、iOS。服务端承担身份、持久化、同步、AI 调用和管理员权限；普通客户端只调用业务 API，平台 Key 不下发。

客户端共享业务语义及版本化 API，UI 按平台适配。Web 不做业务提醒；App 原生提醒在后续阶段设计。代价是需从 Web 阶段建立多设备、重连和版本兼容合同，不能依赖单浏览器内存作为唯一事实来源。

## ADR-002：Python、Vue 与框架推荐

**状态：Python/Vue 已确认；FastAPI、Vue 3 + TypeScript + Vite 已采纳（工程）。**

| 层次/候选 | 适配性与代价 | 建议 |
| --- | --- | --- |
| FastAPI | ASGI 异步 I/O、类型化校验、OpenAPI 和事件流适合 AI/API；认证、管理和任务执行需自行组合 | 推荐为后端 API 框架；阻塞识别/CPU 工作放独立执行进程 |
| Django | 账号、ORM、迁移和管理生态完整；异步作业与定制 Vue 后台仍需集成 | 可选，若维护效率和现成功能优先可重新比较 |
| Flask | 轻量、生态成熟；异步流、输入契约和管理功能需要更多组合 | 当前不优先 |
| Vue 3 + TypeScript + Vite | 适合独立响应式前端；配合 Vue Router、Pinia 分离页面与业务状态 | 推荐；公共介绍页的静态输出/SEO在前端初始化时评估 |
| App | 原生或跨平台的背景恢复、推送和分发代价尚待比较 | 后续阶段决定，不默认用 PWA 替代 |

不以框架名字承诺“最快”。选择验证包括普通请求与流式 AI 并发、数据库连接池、取消/超时、客户端重连、构建体积与长期维护成本。

后端已落地 Python 3.13、FastAPI 0.142.2、SQLAlchemy 2.0.54、psycopg 3.3.6、Alembic 1.20.0、Uvicorn 0.54.0；完整版本及哈希见 `server/uv.lock`。前端版本在初始化时锁定。服务基础的真实 HTTP/数据库验证见实施记录，尚不能据此承诺业务容量。

## ADR-003：模块化单体与持久化作业

**状态：模块化单体、PostgreSQL、数据库租约队列已采纳并实现（工程）；生产容量仍待验证。**

推荐一个模块化业务 API、独立 AI/识别执行进程、PostgreSQL 权威存储。账号、对象版本、同步变更、提案应用、额度和审计需要事务与唯一约束；初期 100—1000 注册、日活不超过 100，不要求微服务拆分。

采用 PostgreSQL 管理关系、JSON 输出快照、金额账本和历史版本；SQLAlchemy 异步事务、Alembic 管理迁移。开发环境 PostgreSQL 18 镜像固定摘要；服务器规格和备份部署仍待配置。

首版采用数据库队列，领取使用 `FOR UPDATE SKIP LOCKED`、有界租约、心跳和尝试记录，独立执行进程在事务外调用供应商或外部来源。AI、日历订阅、导出、账号注销和公开链接作业已经分别验证排他领取、租约恢复、晚到结果及失败回滚；相较 Celery + Redis，减少一个常驻服务，代价是需继续监控数据库锁争用和吞吐。若容量实测不满足目标，再迁移投递机制；数据库中的作业、尝试和预算仍是事实来源。

AI 与普通 API 分开限流和连接池；流式连接有资源上限。新增执行进程不会绕过全局预算和账号并发约束。

API 连接池初值 5、溢出最多 5、等待 3 秒；连接 3 秒、语句 5 秒、锁等待 2 秒、空闲事务 10 秒，均由配置集中约束。迁移使用会话级 advisory lock 防并发发布；就绪检查同时检查数据库与迁移版本。20 个真实并发事务共享 2 个测试连接已验证，完整业务负载仍待容量阶段。

## ADR-004：模型与确定性业务校验

**状态：确认式应用及硬约束保护已确认；引擎实现建议。**

模型负责理解、拆解、提出排期和解释；服务端确定性校验对象所有权、时间区间、固定约束、任务工作量、拆分限制和版本。推荐混合方案：先计算可用区间和边界，再让模型提出计划，最后统一校验。

不能用反复模型重试解决无解；超载返回可行部分与未排原因。输入关键缺失追问、普通估计标注。全局助手所有业务修改生成提案，确认后事务应用；聊天持久化不重复弹确认。

## ADR-005：后台 AI 作业与流式恢复

**状态：后台运行、尽可能流式、备用服务、约 3 分钟可配已确认；协议建议。**

推荐持久化作业 + SSE 事件流 + 状态查询。接单、排队、执行、校验、结果完成与提案应用分开。客户端断线只影响展示连接，重连取得持久化状态；不隐式创建第二个模型请求。

连接、首字、流空闲、单次尝试和总作业时长分别限界。重试及备用切换共享总时长、尝试次数和平台成本预算。结果成功后是否立刻扣额须按 ADR-008 中未定的成功边界冻结。

## ADR-006：版本与语义合并

**状态：安全合并、实质冲突人工决定、离线范围已确认；增量协议已选定，待实现验证。**

采用账号绑定的不透明增量游标、无正文 `ChangeEvent` 失效事件和现有类型化业务 API。客户端收到事件后重新读取权威对象；离线步骤勾选与已有专注操作保留原客户端操作 ID 重放，不建立可绕过领域状态机的通用 mutation 接口。不同字段仅在业务不变量不冲突时合并；任务完成与新增步骤、删除与离线编辑不按普通字段合并。

全账号专注排他由数据库事务约束；离线只续已有会话，新的会话需服务端授权。版本过期提案必须重新核验，不能采用全局“最后写入覆盖”。游标过期时先保护本地待传操作，再重建当前页面快照。Web 可见页默认 2 秒轮询，事件默认保留 30 天；这些是可调整工程参数，完整合同见[通用同步设计](../设计/iTime-通用同步设计.md)。

## ADR-007：管理员、密钥与配置版本

**状态：超级管理员、TOTP、可查看正文、草稿/测试/发布/回滚已确认；保管方案建议。**

管理员会话已实现独立 Cookie 和逐请求 TOTP 状态校验；当前 8 小时会话、一次性恢复码及服务器 CLI 重置是可配置工程默认，最终恢复/交接责任和敏感操作重新验证范围仍待确认。Key 写入只返回已设置状态，服务端加密保存，解密根密钥与数据库备份分开保管。

每个 AI 能力绑定配置版本，端点、模型、超时、价格和备用路由一起校验。旧作业保留原版本，新发布只影响新作业；紧急吊销 Key 时旧作业失败并按规则释放预算。授权正文查看、配置发布和额度修改必须审计。

## ADR-008：每日金额额度与平台成本

**状态：已确认并进入实现。**

每日额度以用户 04:00 活动日刷新；成功扣一次，失败/取消不扣，失败重试成本归平台。usage 缺失允许估算且标注。用户金额预算和供应商实际成本分账，不设置现金充值或首版订单系统。

请求接单时按用户时区 04:00 活动日原子预留，结果校验通过且可查看时结算；业务提案后续拒绝或过期仍计费。失败、取消和失败重试释放用户预留并由平台承担成本；实际成功金额超预留和迟到 usage 不追扣用户。跨日作业归接单时冻结的活动日，金额使用整数纳单位，保留价格版本和上报/估算来源。

## ADR-009：公开链接和临时识别资料

**状态：自动读取公开链接和原媒体生命周期已确认；公开链接隔离方案已采纳并实现（工程）。**

公开网页读取与管理员 AI 端点采用不同网络策略。`itime.network.restricted_http` 只接受允许的 URL，校验协议、DNS 全部结果、每次重定向和实际连接 peer，限制压缩/解压体积、压缩比、总时限和跳转，并关闭系统代理与 Cookie；日历订阅和任务公开链接复用传输层，但分别约束媒体类型与错误码。

迁移 `0030_public_task_links` 为任务链接增加 revision、租约、尝试、来源、摘要、正文哈希和失败状态；独立 worker 在事务外读取，按账号限制并发和频率，写回前重验账号、任务、URL 修订与租约。成功快照进入规划输入及普通对话接单快照时明确标记为不可信资料，不能成为工具授权或直接业务写入依据。具体合同见[公开链接读取设计](../设计/iTime-公开链接读取设计.md)。

临时媒体保留独立生命周期，不复用为永久附件；确认前须保存结构化结果，删除原媒体不删除已确认日程。正式公网兼容性、生产出口策略及容量仍需在部署前验证。

## ADR-010：日志、质检与数据生命周期

**状态：期限与用途已确认；账号注销方案已选定，待实现验证。**

业务数据、AI 正文日志（7 天）、质量样本（30 天）与审计元数据分开管理。质检默认参与、可关闭；关闭停止后续采样，既有样本到期清理；不用于训练。账号注销清理优先。

账号注销采用独立持久化作业：申请后账号进入 `pending_deletion`、撤销全部会话并停止在途任务；
7 天内仅凭正确邮箱和密码撤销，到期后由租约 worker 删除用户行并依靠已审计的外键链清理本人
数据。完成后只保留不含邮箱和正文的 HMAC 删除回执；完整合同见
[账号注销设计](../设计/iTime-账号注销设计.md)。

单项删除对日志/样本的即时影响、生产备份删除台账重放及审计元数据期限仍待后续细化。

## ADR-011：用户时区与重复事件展开

**状态：用户时区原则已确认；结构化重复规则及例外模型已采纳（工程）。**

用户时间设置保存 IANA 时区，首次取浏览器报告值；时区变更只影响显示和后续新建内容默认值，不改写既有时间点。定时单次事件保存 UTC 时间点及创建时区，重复系列保存当地墙上时刻和时区；日期型内容保存日历日期，每周从周一开始。活动日仍按当前用户时区 04:00 切换。

重复事件采用结构化规则、按最大 93 天查询范围即时展开，并用独立例外表达取消、移动和覆盖。相比预生成未来实例，该方案避免无限数据和系列修改的大事务；相比仅保存 RRULE 字符串，它允许服务端验证周次、编辑范围和夏令时异常。外部 ICS 原规则作为来源快照保留，确认后转换为领域规则。完整语义及限制见[时间、课表与重复规则设计](../设计/iTime-时间课表与重复规则设计.md)。

## ADR-012：PostgreSQL 物理备份、连续 WAL 与恢复删除台账

**状态：每日备份和 24 小时恢复目标已确认；RPO、工具、保留和恢复流程已采纳为 M8-B 工程基线，待动态验证。**

采用固定版本 pgBackRest 执行 PostgreSQL 物理 full/differential 备份、连续 WAL 归档、仓库加密、
校验、保留和时间点恢复。工程基线为 RPO 不超过 1 小时、每周 full、每日 differential、保留
4 个完整备份集及其依赖 WAL；M8-B 使用独立文件仓库完成真实演练，M8-C 再配置主机外对象存储
或专用仓库主机。相比自写 `pg_basebackup` 归档脚本，该方案减少加密、清单、过期和部分失败的
自有实现；相比托管数据库 PITR，它不依赖尚未选定的生产供应商。

现有账号注销回执和任务、困难、记忆、日历最小墓碑继续作为业务事实来源。恢复系统把这些状态
导出为独立 HMAC 签名快照，在恢复库开放前重放并执行当前时间下的到期清理；不新增第二套业务
删除模型。恢复始终进入新集群，撤销全部恢复出的用户/管理员会话并收敛租约、作业、专注和额度
后，才允许 API 与 worker 接入。完整合同见[M8 备份与恢复设计](../设计/iTime-M8备份与恢复设计.md)。

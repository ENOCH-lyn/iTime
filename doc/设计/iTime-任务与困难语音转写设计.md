# iTime 任务与困难语音转写设计

版本：0.1；更新：2026-10-04。本文细化 `REQ-TASK-01`、`REQ-DIFF-01`、
`REQ-MEDIA-01`、`REQ-AI-01` 和 `REQ-QUOTA-01`，冻结 Web 首版任务名称与困难正文的
语音转写、校对、临时媒体、AI 作业及金额结算合同。方案已获继续推进授权，当前状态为设计完成、
实现待开始；不得仅凭本文将语音功能标为已交付。

## 1. 范围与方案选择

本模块交付：

- 在新建或编辑任务时，可录制一句话并得到可编辑的任务名称草稿。
- 在新建或编辑困难记录时，可录制一句话并得到可编辑的困难正文草稿。
- 转写草稿与原表单内容分开；用户明确选择替换或追加后，才修改浏览器中的表单值，仍须通过原有
  “创建任务”“保存修改”或“记录困难”动作持久化业务对象。
- 服务端持久化转写作业，页面关闭、刷新或短暂断网后可恢复未解决结果。
- 独立 `transcription` AI 能力支持管理员配置、合成测试、发布、回滚、最多两个备用服务、逐尝试
  成本、每日金额额度、正文日志和可关闭的质量采样。
- 录音只作为临时媒体：用户应用或丢弃结果时立即删除，未解决录音与临时文字草稿最迟 24 小时
  清理。

本模块不交付：

- 从一句语音拆成多个任务，或自动推断截止时间、项目、优先级、标签、步骤和困难情绪。
- 自动保存任务或困难、自动发起普通 AI 对话、自动修改计划。
- 长期录音附件、录音历史、回放库、上传已有音频文件、实时字幕、说话人分离或会议转写。
- 浏览器关闭后的后台录音、Web 业务提醒或 App 原生录音能力。

多任务和属性解析属于业务提案：以后实现时必须读取用户校对后的文字，再生成可预览提案，不与本次
原始语音转写合并。这样可以把“听清用户说了什么”和“决定应修改哪些业务对象”分成两个独立校验
边界。

比较过三种方案：

1. **独立服务端转写能力（采用）**：浏览器只采集音频，服务端通过持久作业调用
   OpenAI 兼容 `/audio/transcriptions`。可完整复用配置版本、主备路由、租约、额度、治理和账号
   注销合同。
2. 浏览器 `SpeechRecognition`：开发量较少，但实现和网络去向受浏览器供应商控制，无法使用后台
   配置、统一额度、持久作业和服务端审计，也不能稳定满足 Chrome/Edge 之间的一致恢复语义。
3. 把音频编码进聊天接口：可复用聊天调用形式，但会放大请求体，并把产品绑定到各供应商不同的
   多模态音频消息格式；标准转写端点的兼容性和职责边界更清晰。

不采用同步 HTTP 等待模型。转写可能遇到排队、限流、超时和备用切换；同步请求无法可靠处理离页
恢复、租约接管、取消竞态和一次结算。

## 2. 用户流程

```text
点击麦克风
    ↓
浏览器请求权限并录音（最长 60 秒）
    ↓
本地转换为 16 kHz / 单声道 / 16-bit PCM WAV
    ↓
服务端校验、加密媒体、冻结 AI 路由、预留额度
    ↓
worker 调用 /audio/transcriptions
    ↓
校验文字并展示独立转写草稿
    ↓
用户编辑 → 替换/追加到原字段 → 正常保存任务或困难
        └→ 丢弃
    ↓
应用或丢弃立即删除录音；未处理内容 24 小时到期
```

录音控件状态为：

```text
idle → requesting_permission → recording → preparing → uploading
     → transcribing → ready → resolved
              ├→ error
              └→ cancelled
```

- `requesting_permission` 尚未采集数据；用户可忽略浏览器权限提示，界面不把它表述为失败或已上传。
- `recording` 显示实际经过时长和停止按钮，到 60 秒自动停止。离开组件或页面时必须停止所有媒体
  track 和音频节点。
- `preparing` 只在本机下采样并编码 WAV；不请求 AI、不占额度。
- `uploading` 以后由服务端作业状态决定。未知响应使用同一操作 ID 重试，不能重复创建媒体、作业
  或预留。
- `ready` 展示单独的可编辑草稿。原输入框在转写期间仍可编辑，转写完成不会覆盖用户随后输入的
  内容。
- 空字段提供“应用”；已有内容提供“替换”和“追加”。追加使用一个换行分隔，任务名称仍受
  200 字限制，困难正文仍受 2000 字限制；超限时要求先编辑草稿，不截断。
- “应用”只改变当前浏览器表单并解决转写；业务保存失败时文字仍留在原表单，继续沿用已有
  operation ID、版本冲突和错误恢复合同。
- “丢弃”清除转写草稿和原录音，不修改任务或困难。

## 3. 浏览器录音与音频合同

Web 使用 `navigator.mediaDevices.getUserMedia({audio: true})` 和 Web Audio API。生产必须运行在
HTTPS；本地 `localhost` 继续作为浏览器认可的开发安全上下文。首版优先验证 Chrome 和 Edge，
不依赖浏览器厂商的云端语音识别。

浏览器将采样数据转换为以下唯一上传格式：

| 项目 | 固定值 |
| --- | --- |
| 容器 | RIFF/WAVE |
| 编码 | PCM，little-endian |
| 采样率 | 16,000 Hz |
| 声道 | 单声道 |
| 位深 | 16 bit |
| 最短时长 | 250 ms |
| 最长时长 | 60,000 ms |
| 最大文件 | 2 MiB |
| Content-Type | `audio/wav` |

采用单一 PCM WAV 是为了让服务端使用标准库验证帧数、采样率、声道、位深、实际时长和文件边界，
不在 API 进程中引入对不可信 WebM/MP4 的复杂解码器，也不依赖部署机器额外安装 FFmpeg。60 秒
单声道 16 kHz PCM 正文约 1.92 MB，位于 2 MiB 上限内。

采集层使用独立 AudioWorklet 把浏览器原始采样流转换为单声道，并按输入采样率连续下采样，避免
在主线程长期保存 48 kHz 多声道数据。停止后主线程只负责写固定 WAV 头并组装已经下采样的
PCM16 分片。若浏览器缺少所需 API、权限被拒绝、输入设备消失、音频上下文启动失败或页面失焦
导致流结束，停止所有 track，保留原表单文字并显示对应恢复动作。

服务端不信任浏览器上报的时长或 MIME。`audio_validation` 读取 WAV 结构并确认：

- RIFF/WAVE、PCM format code、单声道、16 kHz、16 bit 与文件名扩展一致。
- 数据帧完整，按帧数计算的时长处于 250 ms—60 s。
- 文件不为空且不超过 2 MiB；不接受视频轨、压缩 WAV、额外拼接音频或声明与实际不符的内容。
- 校验和加密在有界线程工作中完成；正文不写临时公开目录、普通日志或错误响应。

## 4. 数据模型

### 4.1 TemporaryMedia 扩展

`temporary_media` 增加 `purpose=voice_transcription`，并把图片维度与音频元数据改为按用途互斥：

- 图片：`width`、`height` 必填，音频字段为空。
- 录音：`duration_ms`、`sample_rate_hz`、`channel_count`、`sample_width_bits` 必填，图片维度为空。
- 两类媒体都保留所有者、原文件名、规范 MIME、SHA-256、字节数、加密正文、固定
  `expires_at`、删除时间和原因。
- 删除原因增加 `accepted`、`discarded` 和 `cancelled`；原有截图 `confirmed`、统一
  `expired`、`account_deletion` 保持有效。

媒体 ID 与所有者继续使用复合唯一键；AI 作业通过复合外键绑定本人媒体。每份媒体最多关联一个
作业，禁止把同一录音用于多个计费请求。

### 4.2 VoiceTranscription

新增一对一 `voice_transcriptions` 临时结果表：

| 字段 | 语义 |
| --- | --- |
| `id / owner_id / job_id / media_id` | 稳定结果 ID、所有者、唯一作业和唯一录音 |
| `purpose` | `task_title` 或 `difficulty_content`，只决定入口文案和恢复范围 |
| `transcript` | 校验后的文字；处理前、丢弃后或到期清理后为空 |
| `transcript_sha256` | 有文字时保存，用于解决请求核对，不作为正文替代 |
| `language` | 供应商返回且通过格式限制时保存，否则为空 |
| `resolution` | `pending / accepted / discarded / expired` |
| `ready_at / resolved_at / text_purged_at` | 结果可见、用户解决、文字清理时间 |
| `expires_at` | 接单时固定为创建后 24 小时，重试不延长 |
| `version / created_at / updated_at` | 乐观并发和排序 |

数据库约束保证：

- `pending` 可在处理中没有文字；作业成功后必须有文字、哈希和 `ready_at`。
- `accepted` 只能从已经可见的文字进入；其文字可在固定期限后清理。`discarded` 可在排队、执行
  或成功后发生。
- `expired` 不能再恢复；`discarded` 和 `expired` 的文字必须为空。
- `text_purged_at` 存在时文字为空；原录音删除状态不依赖临时文字是否仍在幂等窗口内。
- 结果、作业、媒体三者的 `owner_id` 使用复合外键保持一致。

`AIJob` 能力增加 `transcription`。它和 `calendar_screenshot` 一样必须绑定临时媒体，但只能关联
对应 purpose 的音频；不得关联对话、规划或复盘快照。成功作业输出只保存
`resource_type=voice_transcription` 与结果 ID，不在通用作业 JSON 中长期复制文字。

### 4.3 配置与按时长计价

`transcription` 使用标准音频转写端点，不能把每分钟价格伪装成聊天 Token 价格：

- `AIConfigVersion.max_output_tokens` 对转写能力为空，其他能力继续必填。
- 配置价格增加互斥的 `pricing_basis=token|audio_minute`。
- 现有能力使用币种和输入/缓存输入/输出每百万 Token 价格。
- 转写能力使用币种和 `audio_price_nanos_per_minute`；价格随不可变配置版本冻结。
- 管理后台按能力展示对应字段，历史列表明确显示“每分钟音频”，不显示无意义的最大输出 Token。
- 合成测试向 `/audio/transcriptions` 发送不含用户内容的固定短语 WAV，只要求得到有界非空文字，
  不以标点或大小写完全相同作为可用性判断。
- 发布转写配置时，其币种必须与当前额度策略一致；后续发布新额度策略时，已经发布的转写能力也
  必须具有完整的同币种音频价格。尚未发布该能力时不阻断既有额度策略。

`AIProviderCost` 增加 `billing_basis`、`audio_duration_ms`、
`audio_price_nanos_per_minute` 和 `audio_cost_nanos`。转写尝试在真正发出请求后，按服务端验证的
固定时长和该 attempt 的配置价格计算：

```text
audio_cost_nanos =
    ceil(audio_duration_ms * audio_price_nanos_per_minute / 60_000)
```

未发出请求的尝试为零成本。可重试失败、超时和取消若已经发出请求，仍分别记录平台成本；用户只在
最终成功且文字可查看时结算成功 attempt，失败、取消和失败重试释放预留。接单时按冻结主备路由
中最高的每分钟价格计算同一录音的最大预算；跨 04:00 继续归接单活动日。

供应商返回的 duration 或 Token usage 只按白名单保存在 `usage_details` 供对账，不覆盖服务端
测得时长，不改变已冻结价格。当前 Token 计价记录与接口保持兼容；后台成本页根据
`billing_basis` 分别展示 Token 或音频时长。

## 5. API 与作业执行

### 5.1 用户 API

| 方法与路由 | 输入与输出 |
| --- | --- |
| `POST /api/v1/voice-transcriptions` | 原始 WAV body、`purpose`、`filename`、`X-Operation-ID` → `202` 作业和临时结果快照 |
| `GET /api/v1/voice-transcriptions` | 按 purpose 分页读取本人最近结果，用于刷新或换页恢复 |
| `GET /api/v1/voice-transcriptions/{id}` | 读取本人临时结果和作业状态 |
| `POST /api/v1/voice-transcriptions/{id}/resolve` | `operation_id`、`expected_version`、`action=accept|discard`；accept 另带文字哈希 → 当前结果 |
| `POST /api/v1/ai/jobs/{id}/cancel` | 继续使用通用取消入口；转写作业同时清除录音并把临时结果标为 discarded |

上传接单顺序固定为：

1. 第一次只读鉴权检查账号和 AI 权限。
2. 在事务外完成 WAV 校验和媒体加密。
3. 写事务锁定用户与当日额度，重放同账号 operation ID。
4. 检查本人最多三个排队或执行中的转写作业。
5. 冻结 `transcription` 主备配置路由，按最高音频分钟价格计算预留。
6. 原子写媒体、临时结果、AI 作业、路由、额度预留和操作结果。

相同 operation ID 和相同文件哈希、purpose 返回原结果；相同 ID 携带不同输入拒绝。接单前的
格式、配置、权限或额度失败不保存媒体、作业和预留。

### 5.2 Worker

worker 继续使用共享 `FOR UPDATE SKIP LOCKED`、租约、心跳、总截止时间与最多三次冻结路由：

1. 领取 `transcription` 作业并验证当前租约、本人媒体、未解决结果和 24 小时期限。
2. 解密录音并重新核对 SHA-256；正文日志只准备模型、媒体类型、字节数、时长、哈希和 purpose，
   不包含音频或 base64。
3. 通过 `multipart/form-data` 向
   `{endpoint_url}/audio/transcriptions` 发送 `model`、WAV 文件和 `response_format=json`。
4. 最多读取 256 KiB 响应，只接受 JSON 对象中的非空 `text`；去除首尾空白，拒绝 NUL、控制字符
   和超过 4000 字的结果。可选 language 只允许短文本。
5. 成功事务写临时文字、逐尝试正文日志、质量样本、供应商成本、用户额度结算及 AI 作业终态。
6. 429、5xx、网络错误和超时可在总截止时间内切换下一冻结路由；401/403、端点策略、媒体、
   空文字和结构错误不可重试。

最终失败、总超时或取消事务在结束作业和释放预留时一并清除原录音；这些终态不保留无继续处理
价值的音频到 24 小时。只有成功但等待用户校对的录音保留到用户解决或固定期限。

音频不是提示词。转写端点只把其作为待识别数据；返回文字也不会自动进入任务、困难、对话或提案。

### 5.3 解决与清理

解决请求锁顺序为 `AIJob → VoiceTranscription → TemporaryMedia`：

- `accept` 要求成功作业、尚未过期、当前版本和文字哈希匹配；立即清空录音，保留文字到固定
  `expires_at` 以支持响应未知后的状态核对。
- `discard` 可作用于排队、执行或成功结果；活动作业先按通用取消合同结束并释放预留，再清空录音
  和文字。
- 相同 operation ID 重放返回同一状态；不同设备同时 accept/discard 时只有首个动作生效，另一方
  得到当前状态，不反向覆盖。

共享媒体清理每次先选候选 ID，再按上述锁顺序逐项处理，避免和 worker、取消及账号注销形成反向
锁序：

- 到期的排队或执行作业变为超时并释放预留；晚到上游结果受租约和终态门禁拒绝。
- 到期录音清空密文并记录 `expired`。
- 未解决临时文字清空并标为 `expired`；已 accepted 的文字清空但保留 accepted 元数据。
- 清理失败整项回滚，后续批次重试；不延长原到期时间。

账号注销申请沿用现有顺序，先取消本人活动 AI 作业并清空全部临时媒体；到期删除时结果表随用户
级联删除。原录音和临时转写不进入长期附件库、公开链接或业务同步变更。

## 6. 错误与恢复

| 场景 | 保存/扣额状态与恢复 |
| --- | --- |
| 浏览器不支持或麦克风权限被拒绝 | 未录音、未上传、未扣额；保留文本输入并说明启用权限或继续手工输入 |
| 录音设备中断、过短或本地编码失败 | 未上传、未扣额；停止 track 后可重新录制 |
| WAV 格式、时长或体积非法 | 服务端拒绝，不创建作业和预留；重新录制 |
| 上传响应未知 | 以原 operation ID 重试；返回同一作业 |
| 未发布配置、币种不符或额度不足 | 不保存媒体/作业；保留当前文字，管理员修复或额度刷新后重试 |
| 429、5xx、网络或单次超时 | 在原总截止时间和冻结主备路由内有界重试 |
| 鉴权、端点策略、空文字或非法响应 | 作业失败、释放用户预留；录音立即清除，允许重新录制或手工输入 |
| 用户取消 | 单一取消终态、释放预留、清除录音；晚到结果不能恢复文字或扣额 |
| 页面离开 | 服务端继续处理；再次进入同一入口可恢复最近未解决结果 |
| 转写期间原字段被编辑 | 结果只进入独立草稿，不覆盖原字段；用户选择替换或追加 |
| 应用响应未知 | 保留浏览器草稿，重新查询 resolution；已 accepted 时仍可本地应用 |
| 24 小时到期 | 原录音和临时文字不可恢复，提示重新录制；已经保存的任务/困难不受影响 |

所有服务错误继续返回 `{code, message, request_id, saved, retryable, details}`。界面明确说明录音、
转写草稿和业务对象三者各自是否已保存，以及下一步是重试、检查权限、手工输入还是重新录制。

## 7. Web 组件

新增共享 `VoiceTranscriptionControl`，由任务编辑器和困难面板传入 purpose、字段上限与当前文字，
组件只发出“替换”或“追加”事件，不直接调用任务/困难保存 API。

- 麦克风使用图标按钮和 tooltip；录音中使用停止图标，上传/转写中使用明确状态和取消命令。
- 固定录音控制尺寸，秒数变化、加载图标和错误文本不得推动主表单布局跳动。
- 转写草稿是与原输入并列的普通编辑区，不使用嵌套卡片；显示剩余字数、应用/替换/追加和丢弃。
- 任务标题区域只在对象可编辑时显示；归档、回收站和清理后任务不提供录音入口。
- 困难仅在活动记录表单显示；编辑已有困难时仍可用语音生成新草稿，但不自动覆盖原正文。
- 浏览器权限、录制、上传、作业和解决状态使用 `aria-live`；所有按钮有可访问名称，键盘可完成
  停止、编辑、应用、丢弃和重试。
- 窄屏按单列换行；320px、最大字号和深色主题下不得横向溢出、遮挡字段或让控制文字越界。

页面卸载、组件卸载、用户取消和录音异常都必须断开音频节点并调用每个
`MediaStreamTrack.stop()`。上传完成后不把音频 Blob 写入 localStorage、IndexedDB 或同步队列。

## 8. 安全、隐私与容量

- 所有路由从认证上下文取得 owner；他人 ID 与不存在统一返回 404。
- 麦克风只在用户点击后申请；页面不预热、不后台监听、不在权限拒绝后循环弹窗。
- 服务端以文件内容为准，不信任文件名、MIME、客户端时长、语言或 purpose 之外的任意元数据。
- 在 iTime 可控系统内，原音频只存在于浏览器内存、加密数据库字段和发往已冻结供应商的请求；
  不落公开目录、普通访问日志、正文日志、质量样本、导出压缩包或同步事件。供应商实际处理与
  保留规则须在上线隐私说明中按最终选型披露。
- 技术正文日志默认 7 天保存有界请求元数据和规范化转写文字；质量改进开启时，成功文字可进入
  30 天样本，不包含原音频。该行为沿用现行隐私说明，不用于训练。
- 每个账号最多三个活动转写作业，滚动 10 分钟最多接收 20 次录音；部署级活动转写队列上限默认
  500，可按隔离性能结果调整。达到限制时在保存媒体前拒绝。每份最长 60 秒、2 MiB；结果最多
  4000 字，供应商响应最多 256 KiB。接口继续受全局请求体上限、账号状态和 AI 冻结控制。
- 录音确认删除、24 小时清理、日志 7 天、样本 30 天是不同数据层，不把原音频删除错误表述为
  所有文字痕迹同时删除。
- 本人完整 JSON 导出可包含导出快照时仍未过期的转写文字及状态，便于用户核对服务端持有内容；
  原音频密文、AI Key、租约和内部请求正文不进入导出。转写文字随后仍按原固定期限清理。

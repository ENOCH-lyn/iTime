# iTime 通用同步设计

版本：0.1；更新：2026-10-04。本文细化 `REQ-SYNC-01`、`AUTH-03`、`SYN-01`—`SYN-04`
和 `NFR-PERF-01`。用户已确认安全合并、实质冲突人工选择、约 5 秒在线可见目标，以及离线
只查看、勾选和续已有专注；用户另已授权 goal 模式下由代理自行决定一般实现细节。本文选择的
轮询周期、事件保留期、缓存期限和队列上限均为可演进工程默认，不表述为用户原始决定。

## 1. 范围

本阶段交付：

- 本人增量变更游标 API，覆盖任务/目标、课表与日历来源、当前计划、执行/困难、普通对话、
  复盘/报告/批注、长期记忆和个人业务设置。
- Web 全局同步协调器：可见页面定期拉取、写入成功后立即拉取、跨标签广播、退避和恢复。
- 各主工作区收到相关变更后刷新当前可见数据；编辑中的草稿不被远端内容静默覆盖。
- 已认证且页面仍打开时，可离线查看最近成功读取的业务数据；缓存失败不影响在线功能。
- 普通任务步骤和重复任务实例步骤可离线勾选；现有专注离线队列继续处理暂停、恢复、结束和
  步骤进度。
- `/account/sync` 展示联网状态、最后成功同步、待同步数量、冲突和恢复动作；产品导航提供
  紧凑同步状态入口。
- 增量事件限期清理、游标过期后的安全重建，以及显式退出/切换账号时的本地数据清理。

本阶段不交付：

- 离线新建任务、日历、计划、对话、复盘、AI 请求或新专注。
- 把任意 URL/JSON 保存为通用离线写队列，或新增可绕过领域校验的“万能同步写接口”。
- 多人协作、共享对象、编辑锁、CRDT、WebSocket 基础设施或后台业务提醒。
- 浏览器完全关闭后在未验证会话的情况下展示个人正文；离线冷启动需要后续本地解锁设计。
- 用同步事件代替业务历史、审计、导出或备份。

## 2. 方案选择

比较三种方案：

1. **增量失效事件 + 现有类型化 API（采用）**：服务端只通知“哪个本人对象发生了什么版本
   变化”，客户端按页面重新读取权威资源；离线操作继续调用原领域 API并复用操作 ID。优点是
   不复制权限、状态机和校验，事件不携带正文，能渐进覆盖全部模块。代价是变更后通常多一次
   读取，页面需要注册领域刷新适配器。
2. 完整复制日志 + 通用 mutation API：可构造厚客户端数据库并减少回读，但需要在第二套协议
   中重复任务、日历、规划、AI、额度和生命周期规则，极易造成权限或状态机分叉，首版不采用。
3. WebSocket/SSE 全账号推送：延迟更低，但连接治理、反向代理、重连、背压和多实例广播成本
   高；当前 100—1000 注册、日活不超过 100 的基线下，2 秒可见页轮询更易验证和运维。

## 3. 核心不变量

1. PostgreSQL 业务表和现有领域 API 始终是权威来源；游标事件和浏览器缓存都不是第二份事实。
2. 业务对象、幂等 `UserOperation` 和 `ChangeEvent` 必须在同一事务提交；失败不能留下“有数据
   无事件”或“有事件无数据”。
3. 增量事件只含所有者、类型、对象 ID、动作、版本和服务端时间，不含任务、消息、报告、记忆、
   URL、Key、Cookie 或其他正文。
4. 游标绑定账号并经 HMAC 验签；客户端不能从游标推断其他账号活动，也不能把一个账号的游标
   用于另一个账号。
5. 不使用最后写入覆盖。普通版本冲突继续由领域 API 返回；只有步骤完成布尔值这种独立字段，
   才由专用端点按当前服务端状态安全收敛。
6. 本地队列按账号和对象隔离，保留原操作 ID，严格顺序重放；遇到不可安全处理的第一项即停止，
   保留该项及后续项供用户处理。
7. 游标过期或数据库恢复导致游标超前时，先保留本地待同步操作，再刷新当前页面权威快照；
   不通过清缓存丢弃用户操作。
8. 显式退出或切换账号先提示未同步数量；用户确认退出后清理该账号的同步游标、缓存和队列。
   会话意外失效不把旧账号数据暴露给新账号。

## 4. 服务端数据与游标

### 4.1 复用并修正 ChangeEvent

现有 `change_events.sequence` 是全局单调 `BIGINT`，并已有 `(owner_id, sequence)` 索引。本阶段
继续复用该表，不复制事件：

- ORM 检查约束补齐数据库已支持的 `review_session`、`review_report`、`review_annotation`、
  `memory`、`memory_settings`，并新增 `conversation`。
- 动作继续使用现有稳定集合；会话创建、改名/归档、消息接单及作业终态统一以
  `entity_type=conversation` 发出，不按流式 token 生成事件。
- 导入候选、AI 内部作业、额度预留和导出作业继续使用各自状态查询/轮询，不进入通用业务同步
  事件；候选确认后产生的日历业务对象已有事件。
- 事件只用于失效通知。客户端收到 `step`、`task_occurrence` 或 `review_report` 后重新读取所属
  聚合，不根据事件自行拼装正文。

### 4.2 SyncState

迁移 `0028_sync_feed` 新增每账号一行 `sync_states`：

| 字段 | 语义 |
| --- | --- |
| `owner_id` | 主键并级联到用户 |
| `discarded_through_sequence` | 已因保留期删除的最大本人事件序号，初始 0 |
| `last_cleanup_at` | 最近完成事件清理的服务端时间 |
| `created_at / updated_at` | 运维和恢复核对时间 |

迁移为既有账号回填；普通注册和本机管理员创建同时创建。同步读取缺行视为数据异常并返回可恢复
503，不在只读请求中静默补写。

### 4.3 不透明游标

游标载荷固定为版本、账号 UUID 和最后处理的全局序号，经基础服务密钥 HMAC-SHA256 签名并使用
URL-safe base64 编码。接口只接受自身签发且账号匹配的游标。

无游标表示首次建立基线：

1. 读取本人当前最大事件序号，签发基线游标。
2. 返回 `reset_required=true`、`reset_reason=initial` 和空事件。
3. 客户端保留已加载页面内容并触发一次当前页面权威刷新。

有游标时：

1. 对 `sync_states` 行加共享锁，与清理进程的排他锁排序。
2. 游标序号小于 `discarded_through_sequence` 时返回新的当前基线和
   `reset_reason=cursor_expired`。
3. 游标序号大于本人当前最大事件序号时返回 `reset_reason=cursor_ahead`，用于数据库恢复后
   重建；不把旧游标当作成功。
4. 正常时按 `sequence` 升序读取最多 200 条本人事件。仍有后页时游标停在最后返回事件，否则
   推进到本事务看到的本人最大序号。

读取不返回其他账号的数量、序号范围或时间信息。清理并发通过 `sync_states` 行锁保证读取者要么
看到旧 floor 和完整旧事件，要么看到新 floor 并明确重建，不出现静默缺口。

## 5. 事件保留与清理

`python -m itime.sync.cleanup_worker` 支持常驻和 `--once`。当前工程默认事件保留 30 天，
`ITIME_SYNC_EVENT_RETENTION_DAYS` 可在 7—90 天内调整：

1. 每批选择最多 1000 条到期事件，按账号和序号排序。
2. 对涉及账号的 `sync_states` 行按 UUID 排序加排他锁。
3. 删除事件并把各账号 `discarded_through_sequence` 推进到本批实际删除的最大序号。
4. 同一事务更新清理时间；失败整体回滚，下轮可重试。

事件清理不删除业务对象、操作去重记录或墓碑。账号删除由外键级联清理事件与同步状态。

## 6. API

所有同步路由位于 `/api/v1/sync`，只接受有效本人会话。

| 方法与路由 | 输入与输出 | 主要失败 |
| --- | --- | --- |
| `GET /changes?cursor=&limit=` | 事件、下一游标、是否有后页、是否需重建、服务端时刻 | 游标损坏/跨账号、状态缺失、数据库故障 |
| `GET /status` | 当前账号最新事件时间、保留期和服务端时刻 | 未认证、状态缺失 |
| `PUT /tasks/{task_id}/steps/{step_id}/completion` | 原操作 ID、基础/目标布尔值 → 当前任务与合并结果 | 任务/步骤不存在、归档/回收、重复模板 |
| `PUT /task-occurrences/steps/completion` | 任务、实例 key、步骤、基础/目标布尔值 → 当前实例与合并结果 | 实例无效、已完成/跳过、步骤变化 |

同步拉取是只读操作，不要求 CSRF；两个步骤勾选端点是写操作并要求 CSRF。错误继续使用统一
`code/message/request_id/saved/retryable/details`。

## 7. 安全步骤合并与离线队列

步骤勾选是首版唯一新增的通用离线写类型，因为它是用户已确认的离线范围，且布尔字段能在不
覆盖标题、顺序、日期或任务终态的前提下独立处理。

普通步骤请求固定携带 `operation_id`、`expected_task_version`、`base_completed` 和
`completed`；重复实例另带 `expected_occurrence_version`。服务端锁定用户、任务及目标步骤后：

- 当前值等于目标值：返回 `converged`，不增版。
- 当前值等于基础值且聚合版本未变：只修改完成字段，返回 `applied`。
- 当前值等于基础值但任务标题、说明、标签、日期或其他步骤已改变：仍可使用当前聚合版本合并，
  不覆盖这些字段，返回 `rebased`。
- 目标步骤已删除、任务已归档/回收、普通任务改成重复模板，或重复实例已结束：返回 409，
  不猜测用户意图。

重复实例端点只修改该实例的 `completed_step_ids`，不修改模板步骤和任务完成状态。任务结构及
实例合法性继续复用现有 occurrence 校验。

Web `sync-queue.ts` 使用带版本 schema 的账号级键保存两类步骤操作，单账号最多 100 项、最长
7 天，只保存 UUID、occurrence key、基础/目标布尔值、操作 ID 和时间，不保存任务标题或正文。
网络错误和超时因保存状态未知而保留原操作；服务端幂等结果可安全对账。存储不可用或队列已满
时拒绝离线动作并明确提示联网，不把未持久化操作显示为已排队。

现有专注队列保持原结构和 100 项/7 天边界；同步状态汇总两个队列，但不把专注状态机迁移进
通用解释器。

## 8. Web 同步协调器与缓存

`web/src/lib/sync.ts` 维护单例响应式状态：

- `offline / connecting / synced / pending / conflict / error`。
- 当前账号游标、最后成功拉取时刻、最后事件时刻、待同步数、冲突数和最近请求编号。
- 页面可见时每 2 秒拉取；隐藏时暂停。任意成功业务写入、浏览器 `online/focus` 或其他标签
  广播后立即拉取；失败按 2/4/8/15 秒有界退避。
- 每个标签在 `sessionStorage` 保存自己的账号绑定游标，避免一个标签推进游标导致另一个标签
  漏事件。`BroadcastChannel('itime-sync')` 只加速通知，不替代各标签自己的游标。
- 事件按类型批量派发，不逐事件触发重复请求；页面适配器对 100 毫秒内的同类事件去抖。

`web/src/lib/data-cache.ts` 使用 IndexedDB 保存成功的本人 GET JSON：

- 只有当前内存中已认证账号可读写，键包含账号 ID 和完整请求路径。
- 每次建立已认证 SPA 会话时生成仅保存在内存的 AES-GCM 密钥；IndexedDB 只保存随机 IV 和
  密文。页面刷新后旧密钥不可恢复，在线重新认证时清除不可解密旧缓存并建立新会话缓存。
- 排除 `/auth`、`/admin`、`/sync`、下载正文、SSE 和任何凭据；每账号最多 200 项、最长 7 天。
- 单响应序列化后最多 2 MiB，单账号密文总量最多 20 MiB；超过限制跳过或按最旧访问时间清理，
  不阻断在线响应。
- 仅网络不可达或超时时回退缓存；HTTP 4xx/5xx 不被旧数据掩盖。
- 回退后全局状态显示“离线数据”，页面保留缓存时刻；重新联网后立即读取权威服务端结果。
- 显式退出和账号切换清理旧账号缓存与同步游标；未验证会话时不展示缓存正文。

页面适配器：

| 页面 | 相关事件 | 刷新策略 |
| --- | --- | --- |
| 任务 | project/task/step/label/task_occurrence | 刷新列表和计数；编辑器有草稿时只提示远端变化 |
| 日历 | time_settings/term/calendar_*/task/task_occurrence/plan | 刷新当前范围；打开的编辑对话框不被覆盖 |
| 规划 | task/calendar_*/memory*/plan | 刷新上下文与列表；手工计划草稿保留并标记输入变化 |
| 专注 | focus_session/difficulty/task/step/plan | 先重放本地专注队列，再读取当前状态和历史 |
| AI | conversation/memory* | 刷新会话和当前消息；活动作业仍使用已有 SSE |
| 复盘 | review_*/memory*/task/plan/focus_session/difficulty | 刷新历史与当前只读结果；未提交补充事实保留 |
| 统计 | task/task_occurrence/plan/focus_session | 重新聚合当前可见范围 |
| 设置 | time_settings/privacy_settings/memory_settings | 刷新当前设置；正在编辑的选项不静默覆盖 |

## 9. UI

产品导航末端增加不改变八项主导航结构的同步图标入口：

- 已同步：云勾图标。
- 正在同步或有待传：旋转同步图标和数量。
- 离线：断开图标。
- 冲突/错误：警告图标和可见计数。

图标带可访问名称和 tooltip，固定 44px 命中区，不因文字或数量改变导航尺寸。

`/account/sync` 沿用设置页布局，按顺序显示：

1. 当前状态、最后成功同步和服务器时间。
2. 待同步操作总数，分为任务步骤与专注操作。
3. 冲突列表及“查看对象 / 重试 / 明确丢弃”动作。
4. 游标重建或离线缓存状态；提供刷新，不提供“强制覆盖全部”。

全局离线条说明当前显示最近数据、哪些操作已排队。没有可持久化队列的写入继续显示
`saved=not_saved/unknown` 和联网重试，不冒充已同步。

## 10. 并发、失败与恢复

- 同账号业务写仍沿用用户行首锁和领域对象锁；同步 GET 不锁用户热点行。
- 两设备同时写同一普通聚合继续返回版本冲突；页面保留本地草稿并读取服务器当前版本。
- 两设备操作不同步骤时，专用完成端点分别修改独立布尔值并顺序提交，不覆盖标题、顺序或其他
  步骤。任务整体版本仍递增，后续完整编辑会看到最新版本。
- 服务端已提交但响应丢失时，队列使用原操作 ID；相同请求返回原结果，不重复切换。
- 本地队列损坏时隔离无效项并显示错误，不执行无法验证的对象 ID、动作或时间。
- 增量拉取失败不清除游标、页面数据或待同步项。恢复后从原游标继续。
- 游标重建只使页面重新读取；先保留并展示待同步队列，重放时仍经领域权限和冲突校验。
- 单页收到远端事件时，只有未编辑的区域自动更新；任何草稿、选择或冲突候选都不会因后台刷新
  被静默清空。

## 11. 性能与容量

- 事件页默认 100、最大 200；只覆盖索引 `(owner_id, sequence)`。
- 可见页 2 秒轮询满足本地隔离环境“提交后 5 秒内另一在线端可见”的目标；M8 再记录明确并发
  下的 P50/P95/P99、数据库 QPS 和浏览器耗电后调整。
- 同一标签只允许一个拉取在途；事件多页连续排空，但每轮最多 1000 条后让出事件循环。
- IndexedDB 加密与写入异步且失败不阻断网络响应；单项最多 2 MiB、单账号最多 20 MiB/
  200 个响应、7 天，按最旧访问时间清理。
- 事件清理单批 1000，短事务执行，不与业务正文清理或外部 I/O 共事务。

## 12. 验证与完成标准

服务端使用真实 PostgreSQL/Uvicorn：

- 迁移升级/回退、ORM 约束一致、既有账号回填和新账号同步状态创建。
- 初始、正常、多页、空页、损坏/跨账号/超前/过期游标及两个账号隔离。
- 拉取与清理竞争不丢事件；双清理进程不重复推进或越过未删除事件。
- 任务和日历等现有写入同事务事件回归；会话创建、消息接单、成功、失败、取消产生聚合事件。
- 两设备不同字段/不同步骤、安全收敛、操作重放、响应未知、任务删除/归档和重复实例终态冲突。
- 数据库中断、会话撤销、事件洪峰、最大页和保留期清理。

Web 使用真实生产构建和 Playwright Chromium：

- 两个浏览器上下文登录同一账号，一端创建/修改任务、日历、计划、专注、复盘或记忆，另一端
  在 5 秒内显示更新或明确的远端变化提示。
- 网络离线后当前已加载内容仍可查看；普通步骤和重复实例步骤可连续勾选，待同步数可见；恢复
  网络后按原操作 ID 重放并在服务端核对最终状态。

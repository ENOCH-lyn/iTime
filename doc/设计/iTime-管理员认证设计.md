# iTime 管理员认证设计

更新：2026-10-02。本模块实现超级管理员密码加 TOTP、恢复码和独立管理会话。首个管理员创建、丢失恢复及会话期限尚未得到用户明确答复；当前采用可配置、可撤销的保守工程默认，不能写成产品已确认结论。

## 1. 当前工程默认

| 项目 | 当前行为 | 状态 |
| --- | --- | --- |
| 管理员创建 | 只能在服务器本机运行 CLI 创建；不允许公开注册提交或提升管理员身份 | 工程默认，待确认 |
| TOTP 设置 | CLI 产生 30 分钟一次性 fragment 链接；管理员再次输入密码、扫描身份验证器并提交 6 位验证码 | 工程默认，期限可配置 |
| 丢失恢复 | 首选十个一次性高熵恢复码；全部丢失时，由有服务器权限的运维运行 CLI 重置 TOTP | 工程默认，待确认 |
| 交接 | 先通过 CLI 创建新的独立管理员，完成 TOTP 后再由后续用户管理功能停用旧管理员 | 工程默认，待确认 |
| 管理会话 | 独立 HttpOnly Cookie，固定 8 小时，不与普通用户会话共用 | 工程默认，期限可配置 |
| 时间容差 | 接受当前、前一或后一 30 秒窗口；成功计数器必须严格递增，同一验证码只能成功一次 | 安全实现 |

CLI：

```bash
cd server
uv run python -m itime.admin.cli create --email admin@example.com
uv run python -m itime.admin.cli reset-totp --email admin@example.com
```

创建命令交互读取并确认密码，不把密码放在参数、输出或日志中。`--password-stdin` 只用于受控自动化。命令拒绝覆盖或提升已存在的普通账号。重置会立即撤销该管理员全部普通/管理会话、删除旧 TOTP 与恢复码，并使此前设置链接失效。

## 2. 凭据与会话

- `admin_credentials` 保存 Fernet 加密的 TOTP secret、启用时间和最后成功计数器；数据库不保存明文 secret。
- `admin_recovery_codes` 只保存带服务密钥 HMAC 的摘要。每个显示码有 80 位随机熵，只在创建/轮换成功响应中返回一次；使用时行锁消费。
- `admin_enrollments` 只保存一次性设置令牌 SHA-256 摘要和加密的待确认 secret。确认成功后删除；新 CLI 链接原子替换旧链接。
- `admin_sessions` 与普通 `device_sessions` 分表，Cookie 名、路径、CSRF 派生域和期限独立。服务端逐请求复核管理员状态、TOTP 凭据、认证版本、撤销和到期。
- 管理员密码变化或公开邮箱找回会递增认证版本并撤销全部管理会话。TOTP 重置也撤销全部会话，避免已登录页面绕过重新设置。

TOTP secret、恢复码、密码、设置令牌、会话令牌和 CSRF 不写入访问日志。设置 URI 只在本人持有一次性链接并再次验证密码后返回。管理 Cookie 使用 `HttpOnly`、`SameSite=Strict`、`Path=/api/v1/admin`，HTTPS 环境启用 `Secure`。

## 3. 接口、状态与恢复

前缀 `/api/v1/admin/auth`：

| 方法 | 路径 | 输入与成功状态 | 失败与恢复 |
| --- | --- | --- | --- |
| GET | `/policy` | 管理会话、设置期限和恢复码数量 | 公开配置，无凭据 |
| POST | `/setup` | 一次性令牌、密码 → secret、二维码 URI、到期时间 | 链接无效需 CLI 重置；密码错误不消费链接 |
| POST | `/setup/confirm` | 令牌、密码、TOTP、设备名 → 管理会话及一次性恢复码 | 错误验证码不启用；响应丢失可用 TOTP 登录后轮换恢复码 |
| POST | `/login` | 邮箱、密码、TOTP 或恢复码、设备名 → 管理会话 | 密码前不披露是否管理员；TOTP 重放/恢复码复用拒绝 |
| GET | `/me` | 当前管理身份、认证方式、到期时间、CSRF | 失效、停用、重置或过期统一重新登录 |
| POST | `/logout` | 当前管理会话与 CSRF → 撤销并清 Cookie | 重复退出可恢复 |
| POST | `/recovery-codes` | 管理会话、CSRF、当前 TOTP → 替换全部恢复码 | 旧码在事务提交后全部失效 |
| POST | `/change-password` | 管理会话、CSRF、当前密码、新密码 → 轮换当前会话 | 撤销其他普通/管理会话及旧找回链接 |

错误沿用 `error.code/message/request_id/saved/retryable/details`。设置、确认、登录、恢复码和改密分别使用持久化 IP/账号限流桶；不信任客户端转发头。

## 4. 并发与失败边界

- 密码哈希在数据库事务外执行并受全局有界线程额度约束；事务内重新检查密码哈希，防止并发改密覆盖。
- TOTP 登录和恢复码消费先锁用户，再锁凭据/恢复码；两个并发相同验证码或恢复码最多一个提交成功。
- 管理写操作统一经过 `authorized_admin(request, write=True)`，锁顺序为用户→管理会话。CLI 重置采用同一用户首锁顺序。
- 设置确认在一个事务中启用 TOTP、生成恢复码、删除设置令牌和创建会话；失败时整体回滚。
- 管理密码更新在一个事务中修改哈希、递增认证版本、撤销所有旧会话与找回链接，并创建当前新会话。
- TOTP 依赖服务端 UTC 时钟；部署必须配置可靠时钟同步。客户端设备时钟偏差超出约 30 秒容差时，页面提示校准后重试。

## 5. 实际页面与尚未完成

Vue 页面位于 `web/src/pages/AdminAuthPage.vue`、`AdminPage.vue`，恢复码与改密组件位于 `web/src/components/`。页面提供一次性设置、二维码/手工密钥、TOTP/恢复码登录、恢复码下载与轮换、管理改密、退出、主题和字号；敏感值不写入 Web Storage。动态浏览器证据见[实施与验证](../验收/iTime-Web实施与验证.md)。

正文访问重认证、邀请/用户状态管理、管理员停用与完整交接 UI 尚未实现。恢复码和本机重置的最终运营责任、正式会话时长、是否要求敏感操作再次输入 TOTP 仍需用户确认；后续决定可在不迁移用户正文的情况下调整配置和流程。

# iTime 账号注销设计

版本：0.1；更新：2026-10-04。本文细化 `REQ-DATA-02`、`AUTH-02`、`AI-04`、`PRIV-03`
和 `REL-02`，定义 Web 首版账号注销申请、7 天撤销、在途任务停止、到期清理和恢复边界。
立即锁定范围、临时副本处理、重试策略和界面确认方式是用户授权代理自行决定后的可演进工程
默认，不表述为用户原始决定。

## 1. 范围与方案选择

本阶段交付：

- 已登录普通用户在 `/account/data` 重新验证密码和完整邮箱后申请注销。
- 申请提交后立即停止账号访问、撤销全部会话、阻断新写入，并明确显示 7 天到期时间。
- 7 天内，用户可在登录入口再次验证邮箱和密码，撤销注销并建立一个新会话。
- 申请时终止 AI、导出和订阅刷新等在途工作，结束开放专注，清除临时媒体、导出产物和本地缓存。
- 独立 worker 使用租约领取到期账号，在单个数据库事务中清理个人数据并保留最小删除回执。
- 真实 PostgreSQL、Uvicorn、双 worker、并发写入、晚到结果、浏览器多标签和响应式验证。

本阶段不交付：

- 管理员代替用户申请或撤销注销、绕过 7 天期限恢复账号、合并或迁移账号。
- 物理删除平台全局配置、匿名运行指标，或保留可反查邮箱和正文的“归档账号”。
- 向已经接收请求的外部 AI 供应商撤回网络数据；本地阻断晚到结果，供应商保留能力在上线披露。
- 生产备份销毁、恢复后删除台账重放和法务保留策略；这些随 M8 部署恢复演练完成。

比较三种方案：

1. **独立注销作业 + 冻结账号 + 到期硬删除（采用）**：7 天内完整保留持久业务数据，
   到期后由可重试 worker 物理删除；申请、撤销和清理状态可审计，适配现有 PostgreSQL 作业模式。
2. 只在 `users` 增加 `delete_at`：改动少，但无法独立表达租约、失败恢复、完成回执和多次
   申请/撤销历史，也容易把清理逻辑散落在登录与定时任务中。
3. 申请时立即匿名化，7 天后补删：隐私暴露窗口最短，但无法可靠恢复邮箱、任务正文和外部
   订阅，违反“7 天可撤销”的完整恢复预期。

## 2. 可演进产品默认

1. 7 天从服务端成功提交申请的 UTC 时刻精确计算；客户端时间不参与。`purge_after` 到达后不再
   接受撤销，即使 worker 尚未开始物理删除。
2. 撤销期内账号不能进入任何业务页面，也不能读取、写入、同步或下载导出；登录只有在密码正确
   后才披露注销状态和到期时间。
3. 申请必须重新输入当前密码和完整注册邮箱。管理员账号受保护，不能从普通用户入口注销。
4. 申请后立即清理或终止可安全再生的临时状态：本地缓存/队列、未发送账号邮件、临时原图、
   导出密文、在途 AI/导出/订阅刷新和开放专注。撤销后恢复已保存业务数据，但这些临时工作不会
   自动复活；用户可重新上传、导出或发起 AI 请求。
5. 注销撤销后保留原账号 ID、邮箱、密码摘要、业务数据和 AI 访问状态；只创建一个新的登录
   会话。已取消作业、已结束专注和已清除临时副本不回滚。
6. 到期清理删除邮箱、密码摘要、正文、记忆、索引、样本、会话、额度、媒体、导出及所有本人
   业务行。同邮箱之后可作为全新账号重新注册，不连接旧数据。
7. 完成后仅保留不含邮箱、正文、用户 UUID 明文或业务数量的删除回执：随机作业 ID、
   `HMAC(user_id)`、申请/到期/完成时刻、请求编号和最终状态。其生产保留期限随 M8 备份策略
   冻结；当前不把它用于产品分析或用户画像。

## 3. 数据模型与迁移

迁移 `0029_account_deletions`：

1. 扩展 `users.status` 为 `active / suspended / pending_deletion`。
2. 扩展临时媒体删除原因为 `confirmed / expired / account_deletion`。
3. 新增 `account_deletions`：

| 字段 | 语义 |
| --- | --- |
| `id` | 随机注销作业 ID |
| `user_id` | 撤销期内关联用户；删除用户时 `ON DELETE SET NULL` |
| `subject_digest` | `HMAC("account-deletion:" + user_id)`；完成后用于删除台账核对 |
| `operation_id` | 申请操作号；全局唯一，便于响应未知后识别同一次申请 |
| `status` | `pending / processing / cancelled / completed` |
| `requested_at / purge_after` | 申请时刻和精确 7 天到期时刻 |
| `available_at` | 下一次可领取时间；失败后指数退避，上限 1 小时 |
| `lease_id / lease_until` | worker 排他领取和崩溃恢复 |
| `attempt_count` | 实际清理尝试次数，不因重启归零 |
| `cancelled_at / started_at / completed_at` | 撤销、首次清理和完成时刻 |
| `last_error_code / last_error_message` | 不含正文的稳定运维错误 |
| `request_id` | 首次申请的服务端请求编号 |
| `created_at / updated_at` | 状态审计时刻 |

部分唯一索引保证一个用户最多有一个 `pending` 或 `processing` 注销。状态检查约束保证活动作业
必须有关联用户，`processing` 必须有租约，`cancelled` 必须有撤销时刻，`completed` 必须已经
删除用户并有完成时刻。迁移降级只允许在注销表为空时执行，避免丢失活动作业或完成回执。

`account_deletions` 不级联删除，用于确认清理已经发生。普通注册和管理员创建不预建空注销行。

## 4. 申请注销事务

`POST /api/v1/account-deletion` 输入：

```json
{
  "operation_id": "uuid",
  "email_confirmation": "user@example.com",
  "current_password": "secret"
}
```

处理顺序：

1. 在数据库事务外使用现有 Argon2 有界线程池验证密码快照，避免持锁执行昂贵哈希。
2. 重新进入本人写事务，按既有顺序锁定 `users` 行，确认密码摘要未变化、邮箱完全匹配、
   账号仍为 `active` 且不是管理员。
3. 创建 `pending` 注销作业，`purge_after=requested_at+7 days`；写安全事件。
4. 将用户状态改为 `pending_deletion`，递增 `auth_epoch` 和管理版本，撤销全部设备会话并使
   未使用邮箱令牌失效。
5. 在同一事务终止或失效所有在途本地工作，见第 6 节。任何一步失败则整体回滚，账号继续可用。
6. 提交后删除当前 HttpOnly cookie。响应返回作业 ID、申请/到期时刻和已停止的临时工作摘要，
   `saved=saved`；前端随后清理该账号所有标签页的本地数据。

相同账号的并发业务写和注销申请都先锁用户行：业务写先提交时，其结果属于账号并在到期时删除；
注销先提交时，后续写看到 `pending_deletion` 并拒绝。不会出现申请成功后仍提交新业务数据。

响应丢失时，旧会话已失效。用户再次登录，密码正确后会收到 `account_deletion_pending` 和同一
到期时间，不需要重复创建作业。

## 5. 登录、找回密码与撤销

普通登录保持邮箱和密码错误不可枚举：

- 用户不存在、密码错误或已清理账号统一返回 `invalid_credentials`。
- 密码正确且状态为 `pending_deletion` 时返回 409 `account_deletion_pending`，只包含
  `requested_at`、`purge_after` 和是否仍可撤销；不设置 cookie。
- `suspended` 继续使用现有停用错误，不与用户主动注销混淆。

`POST /api/v1/account-deletion/cancel` 输入邮箱、密码和设备名称。端点使用与登录相同的 IP/邮箱
限流和恒定形状密码校验；锁定用户和当前注销行后：

1. `now < purge_after` 且状态为 `pending` 时，将作业标记 `cancelled`，用户恢复 `active`。
2. 创建一个新的随机设备会话，记录安全事件并返回普通 Session；其他旧会话保持撤销。
3. 已取消的 AI/导出、已清理的临时媒体和已结束的专注不复活；订阅按原业务生命周期重新参与
   后续刷新。

达到到期时刻后返回 410 `account_deletion_expired`，不与 worker 抢救数据。`forgot-password`
可为 `pending_deletion` 账号发送重设链接；重设密码不会自动撤销注销，用户仍需在登录页明确
选择“撤销注销并登录”。这样遗忘密码不会使撤销权失效，也不会因打开邮件链接隐式恢复账号。

## 6. 在途任务与临时副本

申请事务按账号处理：

- **AI 作业**：锁定所有 `queued/running` 作业，复用现有取消逻辑结束 running attempt、
  正文日志和对话投影，释放用户额度预留并清除租约。worker 以作业状态和 lease 再校验，晚到
  供应商结果不能写回复、提案、报告、样本或扣额。
- **数据导出**：`queued/running` 标记失败并清除租约；所有成功导出密文立即清空并转为
  `expired`。晚到 worker 因状态或 lease 不匹配不能重新写入产物。
- **临时媒体**：立即清空加密原图并记录 `account_deletion` 原因；已确认结构化日历仍保留到
  最终清理，撤销后无需恢复原图。
- **日历订阅**：running refresh 标记 `stale`，订阅清除 lease 并回到 `idle`；claim 查询只
  选择 `users.status=active`，因此撤销期不访问外部 URL。旧请求结果因 lease 不匹配无法应用。
- **专注**：进行中或暂停会话在申请时以服务端时刻 `abandon`，保存最终有效时长和不可变事件，
  防止撤销期被计入专注。撤销注销后用户可新建专注。
- **账号邮件**：未使用令牌失效，尚未发送的加密邮件正文清空并结束。已经交给 SMTP 或外部
  供应商的数据无法撤回，正式隐私说明按实际供应商能力披露。

AI、导出和订阅 worker 的 claim 查询均要求用户仍为 `active`。这不仅处理申请事务中的现有
项目，也防止恢复旧队列、租约过期或异常数据在撤销期重新开始外部处理。

## 7. 到期清理与删除覆盖

`python -m itime.account_deletion.worker` 支持常驻和 `--once`：

1. 每轮选择一个 `purge_after <= now` 且可领取的 `pending` 作业，或租约已失效的
   `processing` 作业；使用短租约和 `FOR UPDATE SKIP LOCKED` 支持多 worker。
2. 清理事务统一按 `users → account_deletions` 锁顺序重读状态。用户已撤销、期限未到或 lease
   不匹配时不删除。
3. 删除与该邮箱关联的注册邀请；删除本人安全事件，并清除管理员安全事件中指向该用户的
   `target_id/details`，避免留下可关联标识。
4. 删除 `users` 行。全部本人业务表通过直接或复合外键级联；平台配置中的管理员引用使用
   `SET NULL`。数据库外键保证同一事务要么完整提交，要么完整回滚。
5. 同一事务把注销作业改为 `completed`、`user_id=NULL` 并写完成时刻。事务失败则用户和业务
   数据都不发生部分删除；worker 记录稳定错误并退避重试。

重点覆盖账号、凭据、任务、日历及订阅 URL、对话、AI 作业/尝试/事件/正文日志/质量样本、
提案与计划、专注与困难、复盘与记忆、额度与管理调整、导出密文、同步事件/水位和操作幂等。
供应商全局配置、注册策略和其他用户数据不删除。

完成回执不保存邮箱、原用户 UUID、对象数量或错误原文。M8 恢复演练必须把该删除台账独立于
普通业务备份保留并在恢复开放前重放；在此之前不能宣称生产备份删除闭环已经通过。

## 8. API 与 Web 界面

| 方法与路由 | 输入与输出 | 主要失败 |
| --- | --- | --- |
| `POST /api/v1/account-deletion` | 操作号、当前密码、邮箱确认 → `pending`、申请/清理时刻 | 密码或邮箱错误、管理员保护、已注销、数据库故障 |
| `POST /api/v1/account-deletion/cancel` | 邮箱、密码、设备名称 → 新 Session 和 `cancelled` | 凭据错误、已到期、清理中/已完成、限流 |
| `POST /api/v1/auth/login` | 既有登录输入 | 密码正确但注销中时返回到期信息，不创建会话 |

`/account/data` 在导出区之后增加独立“注销账号”危险区域：

- 明确说明申请后立即退出全部设备、临时工作不会恢复、7 天内可撤销及到期后不可恢复。
- 提供“先生成数据包”入口；存在本地待同步操作时，提交前显示准确数量并要求二次确认。
- 对话框要求输入当前邮箱和密码；提交中禁止关闭或重复点击。
- 成功后清理当前账号 IndexedDB、任务/专注队列、同步游标及所有标签页内存身份，跳转登录页
  显示到期时刻。

登录页收到 `account_deletion_pending` 后，在原表单下显示到期时刻和“撤销注销并登录”按钮。
只有保留在当前页面内存中的正确密码可用于撤销；不把密码、邮箱或注销状态写入 URL、Storage
或日志。取消成功后先显示“账号已恢复”和临时工作不会自动重启，再由用户进入 `/ai`。

后台用户列表增加“注销中”只读状态和筛选；管理员不能用启用/停用按钮替用户撤销，也不能延长
期限。错误界面继续显示原因、保存状态、恢复动作和请求编号。

## 9. 并发、失败与安全

- 申请、撤销和所有本人写入以用户行为首锁；worker 使用同一顺序，避免用户行与作业行死锁。
- 申请与撤销分别只有一个终态获胜。到期边界以服务端 `now` 判断；客户端倒计时只作展示。
- worker 每次只清理一个账号，删除事务受现有 5 秒语句和 2 秒锁等待约束；超时完整回滚，
  指数退避后重试，不把部分级联当作成功。
- 注销密码验证复用 Argon2 并在数据库事务外执行；错误响应不回显邮箱、密码、哈希或账号存在。
- 删除回执 HMAC 使用服务端密钥且不经 API 返回。普通日志只记录作业 ID、阶段、结果和请求号。
- 用户状态变化和会话撤销在同一事务提交；跨标签清理广播不代替服务端权限阻断。
- 恢复后重新注册同邮箱创建全新 UUID，不使用旧注销作业、操作结果、额度或业务数据。

## 10. 验证与完成标准

服务端使用真实 PostgreSQL/Uvicorn：

- 迁移升级/回退、状态/时间/部分唯一约束、ORM 漂移及管理员账号保护。
- 密码/邮箱确认、CSRF、操作响应未知、两个设备、错误密码不泄露注销状态。
- 申请与任务写并发，结果只能是写先完成并随后待清理，或注销先完成且写入被拒绝。
- AI queued/running、attempt、正文日志、额度预留、对话投影和晚到结果；导出与订阅 lease 失效。
- 开放专注结束、未发送邮件和临时媒体清理；撤销后 durable 数据仍在且临时工作不复活。
- 到期前撤销、边界到期拒绝、双 worker、租约恢复、删除事务故障回滚和重试。
- 为每个含 `owner_id` 的当前表及所有直接 `users` 外键核对清理结果；另验证邀请邮箱和安全事件
  标识已清除、其他用户及平台配置不受影响。

Web 使用真实生产构建和 Playwright Chromium：

- 数据页导出入口、注销危险区、密码/邮箱校验、取消对话框和成功后的跨标签本地清理。
- 第二设备立即失效；正确密码登录显示注销到期信息，错误密码不显示；撤销后创建新会话并恢复
  业务数据。
- 受控测试时钟推进到期后运行真实 worker，确认登录失败、账号与正文查询为零、同邮箱可新注册。
- 桌面、手机、平板、320px 最大字号深色、键盘、粗指针、减少动效、axe、控制台、API 500 和
  根级横向溢出。

执行 Ruff、账号注销专项与受影响服务端测试、服务端全量 pytest、迁移检查、清理 worker、
`uv build --no-sources`、前端生产构建、注销专项 Playwright 和全量 Chromium。完成本模块不
代表其他对象单项回收、困难/任务语音、公开链接、其他 AI 提案、Edge/真机、备份恢复、性能基线

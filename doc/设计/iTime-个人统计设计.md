# iTime 个人统计设计

版本：0.1；更新：2026-10-04。本文细化 `REQ-STATS-01`、`REQ-TIME-01` 和 `MET-01/02`，定义 Web 首版个人日/周/月统计的事实口径、活动日聚合、接口与界面。指标分母、跳过/放弃/补记归属和跨日分配是用户授权代理自行决定后的可演进默认，不表述为用户原始决定。

## 1. 范围与方案选择

本阶段交付：

- 独立 `/stats` 页面，按日、自然周和自然月查看本人统计。
- 计划块、任务结果和专注事实三个独立区域及逐活动日趋势，不合成为效率分。
- 当前计划版本去重、任务完成/跳过、专注完成/放弃、人工补记和修订后的有效值。
- 用户当前 IANA 时区下 04:00 活动日，包含 DST 和跨活动日计划块、专注分段。
- 可查看的统计口径、真实空状态、读取失败恢复和请求编号。
- 真实 PostgreSQL、Uvicorn HTTP 与桌面/平板/手机 Chromium 验证。

本阶段不交付：

- 排名、徽章、连续打卡、目标预测、AI 评分或生产力/效率综合分。
- 根据计划时间经过、步骤勾选或专注结束推断任务或计划块已完成。
- 后台留存、活跃、采纳率或用户分群指标。`Q-MET-01` 中的后台聚合尚无已确认用途和分母，不由个人统计模块扩大范围。
- 预计算日报、数据仓库、导出或跨账号比较；导出属于 `REQ-EXPORT-01` 的后续独立模块。

比较过三种实现：

1. **按请求从当前权威事实聚合（采用）**：任务重开、计划换版和专注修订可立即反映；不复制事实，不引入异步汇总漂移。首版单次最多 31 个活动日，符合现有用户规模。
2. 写业务数据时同步维护每日汇总：读取更快，但每个任务、规划、执行和删除事务都要维护派生行，跨日修订容易漏减旧值。
3. 独立统计事件账本：审计能力最强，但会重复现有不可变事件和当前投影，仍需处理更正抵销，首版复杂度超过收益。

## 2. 可演进产品默认

1. 日统计为一个活动日；周统计为锚点所在的周一至周日；月统计为锚点所在自然月。当前周/月只统计到当前活动日，不把未来日期的零值当成结果。
2. 锚点不能晚于服务器判定的当前活动日。设备时间不参与当前日和未来范围判断。
3. 所有时间点按读取时的用户当前 IANA 时区和当地 04:00 边界分组。修改时区不改写原始时间点，只会改变之后读取时的日期展示与分组。
4. 计划只统计每周 `Plan.current_version_id` 指向版本中的块。历史计划版本、待确认/拒绝/过期提案不计入，避免重复生成夸大计划量。
5. 计划展示唯一块数、唯一任务数和区间内计划秒数，不声称计划块已完成。跨 04:00 的块按与各活动日窗口的交集拆分时长。
6. 非重复任务和重复 occurrence 仅在当前状态为 `completed` 时计入，归属实际 `completed_at` 所在活动日；重新打开后立即从完成统计移除。
7. 当前状态为 `skipped` 的重复 occurrence 单独计数，归属最近一次状态写入 `updated_at` 所在活动日；补做 occurrence 作为独立实例，按自身当前结果计数。
8. 任务处于 30 天回收站期间保留其历史结果；彻底清理后相关任务与 occurrence 结果不再出现在统计中。计划和专注使用各自已保存的标题/关联快照，不随任务清理改写。
9. 完成与放弃的专注都是真实时间事实，分别展示数量和时长；放弃不等于完成。人工补记计入专注总量并单独显示，修订后只读取最新 `effective_*` 值。
10. 开放专注按服务器统计时刻计算已保存暂停段和当前运行段，标为进行中；刷新后数值可继续增加。页面不把进行中或放弃专注转换成任务完成。
11. 不提供完成率、采纳率、利用率等百分比。现有数据没有统一且可信的计划块完成分母、无截止任务分母或“应该专注”分母，首版只显示可直接复算的原始计数和时长。
12. 零值表示“此范围没有对应记录”，不表示用户没有行动；补充复盘文字不自动转换为结构化统计。

## 3. 核心不变量

1. 统计是只读派生结果，不创建或修改业务对象，不写统计快照，也不触发 AI、额度或同步事件。
2. 所有查询都从认证会话取得 `owner_id`，每个计划、任务、occurrence、专注和事件条件都包含本人范围。
3. 周一始终为自然周起点；活动日窗口为当地 `[04:00, 次日 04:00)` 转换后的 UTC 半开区间，不能用固定减四小时替代。
4. 响应中的汇总和逐日序列来自同一批已加载事实。汇总中的块数、任务数和会话数按稳定 ID 去重，跨日事实不会在总计中重复计数。
5. 秒数使用整数。每条跨日计划块或专注分配后的逐日秒数之和必须等于该事实落入查询范围的秒数，不因四舍五入增加或减少。
6. 当前计划版本是计划事实唯一来源；旧版本、提案 payload 和复盘快照不能再次计入。
7. 任务完成和跳过按当前投影计算；同一非重复任务或 occurrence 在一个响应中最多贡献一个当前结果。
8. 专注状态和有效时长分别表达。`finished`、`abandoned`、`manual`、`revised` 和 `ongoing` 可交叉，但每条会话只计入一次总会话数。
9. 读取期间发生的并发修改不被统计接口锁住。响应带服务器计算时刻；下一次刷新读取最新已提交事实并收敛，不把一次读请求冒充不可变历史快照。
10. API 单次只接受日、周、月固定范围，最多返回 31 个活动日；不提供任意多年区间，避免无界扫描。

## 4. 时间范围与归属

### 4.1 活动日窗口

服务端先读取 `UserTimeSettings`，再以当前服务器时间计算 `current_activity_date`。对每个待返回日期构造：

```text
start = activity_date 当地 04:00 → UTC
end   = 下一自然日当地 04:00 → UTC
window = [start, end)
```

DST 导致一天不是 24 小时时，仍以两个当地边界的真实 UTC 差值为准。响应返回时区、04:00 边界、自然范围和实际统计截止日，界面不自行猜测服务器活动日。

### 4.2 范围解析

| `scope` | 自然起止 | 当前范围处理 |
| --- | --- | --- |
| `day` | 锚点活动日 | 锚点不晚于当前活动日 |
| `week` | 锚点所在周一至周日 | 当前周的 `data_end_date` 截止当前活动日 |
| `month` | 锚点所在月首日至月末 | 当前月的 `data_end_date` 截止当前活动日 |

历史周/月返回完整自然范围。若锚点晚于当前活动日，返回 `future_statistics_range`；未设置时区返回 `time_settings_required`。Web 可先用浏览器 IANA 时区初始化现有时间设置后重试。

### 4.3 跨界分配

- 计划块按 `[starts_at, ends_at)` 与每个活动日窗口求交集。逐日块数表示当天有正交集的块数；范围汇总块数按块 ID 去重。
- 完成任务按 `completed_at` 所在窗口归属；跳过 occurrence 按当前 `updated_at` 所在窗口归属。
- 专注使用最新有效开始、结束和时长。未修订计时会话从不可变 `start/resume/pause/finish/abandon` 事件恢复真实运行段；开放运行段截止 `calculated_at`。
- 人工补记或已修订会话只有有效区间与总有效秒数，没有每个暂停段。若跨活动日，按有效区间在各窗口的重叠秒数比例分配，并用稳定最大余数法补齐整数秒；响应增加 `proportional_focus_count`，口径中明确这是分配方式。

## 5. 指标合同

### 5.1 计划

| 字段 | 语义 |
| --- | --- |
| `block_count` | 查询范围内与活动日窗口相交的当前版本唯一计划块数 |
| `task_count` | 上述块关联的唯一任务 ID 数 |
| `planned_seconds` | 上述块在查询活动日窗口内的 UTC 交集秒数 |

计划块没有完成状态，因此不返回完成块数或完成率。历史版本仍可在规划页追溯，但不进入当前统计。

### 5.2 任务

| 字段 | 语义 |
| --- | --- |
| `completed_count` | 当前仍为完成的非重复任务和重复 occurrence 数之和 |
| `completed_task_count` | 当前仍为完成的非重复任务数 |
| `completed_occurrence_count` | 当前仍为完成的重复或补做 occurrence 数 |
| `skipped_occurrence_count` | 当前仍为跳过的重复 occurrence 数 |

步骤完成不计作任务完成；计划块结束、专注结束也不计作任务完成。没有统一分母，因此不返回完成率。

### 5.3 专注

| 字段 | 语义 |
| --- | --- |
| `session_count` | 与范围有正有效秒数的唯一专注会话数 |
| `total_seconds` | 完成、放弃及开放会话在范围内的有效秒数 |
| `finished_count / finished_seconds` | `status=finished` 的唯一会话数与有效秒数 |
| `abandoned_count / abandoned_seconds` | `status=abandoned` 的唯一会话数与有效秒数 |
| `manual_count / manual_seconds` | `source=manual` 的唯一会话数与有效秒数 |
| `revised_count` | 有 `ExecutionRevision` 的唯一会话数 |
| `ongoing_count / ongoing_seconds` | 查询时仍为运行或暂停的唯一会话数与当前有效秒数 |
| `proportional_focus_count` | 因人工补记或修订而使用比例跨日分配的唯一会话数 |

`manual`、`revised`、`ongoing` 是来源或状态维度，会与完成/放弃及总量交叉，不应相加得到总会话数。

## 6. 服务端聚合

新增无表、无迁移的 `itime.statistics` 领域模块：

- `time_math.py`：范围解析、活动日窗口和稳定整数分配。
- `schemas.py`：`scope`、响应模型和固定指标结构。
- `service.py`：有界加载当前计划、任务结果、专注与事件并生成逐日/汇总。
- `router.py`：本人统计只读 API。

聚合流程：

1. 读取本人时间设置并解析自然范围、实际截止日和活动日窗口。
2. 一次查询当前计划版本中与总 UTC 窗口相交的计划块，按块 ID 分配到逐日桶。
3. 分别查询当前完成任务、完成 occurrence 和跳过 occurrence，按时间戳定位唯一活动日桶。
4. 查询与范围相交的专注、相关事件及修订 ID 集合；恢复或分配有效秒数。
5. 从逐事实 ID 集合计算去重汇总，从逐日桶生成固定长度序列。
6. 返回 `calculated_at` 和口径版本 `statistics_v1`。不缓存用户正文，不写数据库。

每类查询都有总 UTC 窗口和 `owner_id` 条件。现有当前计划、任务状态、occurrence 日期、专注开始和事件索引足以支持首版规模；在 M8 使用长历史样本测量后再决定是否增加部分索引或预计算，不凭猜测建立汇总基础设施。

## 7. API 合同

所有路由位于 `/api/v1`。

| 方法与路由 | 作用 | 主要失败 |
| --- | --- | --- |
| `GET /statistics?scope=day&anchor_date=YYYY-MM-DD` | 返回本人日统计 | 未来范围、时区未设置 |
| `GET /statistics?scope=week&anchor_date=YYYY-MM-DD` | 返回锚点所在自然周统计 | 未来范围、时区未设置 |
| `GET /statistics?scope=month&anchor_date=YYYY-MM-DD` | 返回锚点所在自然月统计 | 未来范围、时区未设置 |

响应形状：

```json
{
  "scope": "week",
  "anchor_date": "2026-10-04",
  "period_start_date": "2026-09-28",
  "period_end_date": "2026-10-04",
  "data_end_date": "2026-10-04",
  "current_activity_date": "2026-10-04",
  "time_zone": "Asia/Shanghai",
  "activity_day_start_minute": 240,
  "calculated_at": "2026-10-04T08:00:00Z",
  "methodology_version": "statistics_v1",
  "summary": {
    "planning": {},
    "tasks": {},
    "focus": {}
  },
  "days": [
    {
      "activity_date": "2026-09-28",
      "planning": {},
      "tasks": {},
      "focus": {}
    }
  ]
}
```

`days` 只到 `data_end_date`，每一天都存在，即使三组指标均为零。错误继续使用 `{code, message, request_id, saved, retryable, details}`；统计 GET 失败不会改变任何数据。

## 8. Web 界面

产品导航增加“统计”，路径 `/stats`。桌面使用左侧产品导航和范围控制、右侧统计工作区；平板和手机把产品导航与范围控制放到顶部，主体保持单列。

工作区顺序：

1. 标题、当前范围、时区与“当地 04:00 切换”。
2. 日/周/月分段控件，以及上一范围、回到当前、下一范围图标按钮；当前范围不允许前进到未来。
3. 三组独立总览：计划块数/计划时长、任务完成/跳过、专注时长/会话状态。数字和单位固定尺寸，动态值不推动布局。
4. 三条独立逐日趋势，不把不同单位叠成同一轴：计划分钟、完成/跳过任务数、专注分钟。每个数据点同时提供可读数值，不能只靠颜色。
5. “查看统计口径”折叠区，说明活动日、当前计划版本、完成/跳过、放弃、补记、修订和比例跨日分配。
6. 全空范围显示中性空状态，并提供前往任务、规划或专注的现有入口；不展示评价性文案。

加载期间保留稳定占位高度。刷新失败时若已有结果，继续显示上次结果并明确其计算时刻；首次读取失败显示重试、原因和请求编号。页面不增加导出、分享或 AI 建议入口。

## 9. 一致性、性能与安全

- 统计读取不锁业务行，不阻塞任务编辑、规划确认或专注转换。一次响应可能与并发提交交错；`calculated_at` 表示读取时刻，刷新后收敛到最新已提交投影。
- 计划、任务和专注分批查询后只在内存处理最多 31 个日期桶。不得为每个活动日或每条会话发出 N+1 查询。
- 专注事件按本次命中的会话 ID 一次加载；查询未命中会话时不加载事件或修订。
- 开放专注只计算到服务器 `calculated_at`，浏览器刷新只重新 GET，不提交设备时钟。
- 响应不返回任务正文、困难正文、复盘正文或专注事件详情，只返回聚合整数和日期元数据，减少不必要的数据暴露。
- 所有 SQL 条件包含 `owner_id`；两个账号相同日期的计划、任务与专注必须完全隔离。
- 统计页只读，不使用 `operation_id`、CSRF 写令牌或后台权限；账号停用和会话撤销继续由共用认证层拒绝。

## 10. 验证与完成标准

服务端真实 PostgreSQL/Uvicorn 覆盖：

- 上海 03:59/04:00 边界、纽约 DST 周和当前周/月截断。
- 当前计划版本去重、旧版本/提案不计入、跨 04:00 块时长守恒。
- 非重复任务、重复 occurrence、补做、跳过、重新打开及回收/清理后的当前投影。
- 完成、放弃、人工补记、多个暂停段、开放专注、修订和跨活动日秒数守恒。
- 相同任务跨多块、相同会话跨多日的汇总 ID 去重。
- 空范围、未来范围、未设置时区、账号隔离和并发修改后刷新。
- 固定范围上限和查询次数，防止逐日或逐会话 N+1。

Web 生产构建和 Chromium 覆盖：

- 日/周/月切换、前后导航、回到当前、URL 查询恢复和浏览器刷新。
- 三组总览与趋势、零值空状态、补记/放弃/跳过/修订标签和口径折叠区。
- 初次失败重试、保留旧结果的刷新失败、未设置时区自动初始化和登录失效。
- 桌面、平板、手机、320px 最大字号、浅深主题、键盘、粗指针、axe、控制台错误和根级横向溢出。

执行 Ruff、统计专项 pytest、受影响任务/规划/执行/复盘回归、服务端全量 pytest、`uv build --no-sources`、前端生产构建、统计专项 Playwright 和全量 Chromium。完成本模块仍不代表通用同步、导出、注销、Edge/真机、性能或生产部署已完成。

# iTime 全局 AI 对话设计

版本：0.1；更新：2026-10-08。本文记录已实现的普通 AI 对话、多会话、消息持久化、文本生成作业、流式恢复和取消合同。2026-10-08 确认的自动意图、工具循环和通用业务提案由 [AI Agent 对话编排设计](iTime-AI%20Agent对话编排设计.md)扩展；其中“用户手动选择普通回复或规划模式”的旧交互不再是目标状态。

## 1. 范围与方案

本模块交付：

- 多个普通会话，可创建、改名、归档和重新打开。
- 用户消息与 AI 回复持久化，跨页面、跨设备和服务重启后可恢复。
- OpenAI 兼容文本流调用，分段结果先写 PostgreSQL，再通过服务端事件流推送页面。
- 页面离开不取消作业；重新进入从消息快照与事件序号恢复。
- 显式取消、总截止时间、有界重试、双 worker 领取和租约续期。
- 当前会话历史和少量跨会话相关历史的确定性选择，避免把账号全部正文发送给供应商。

本模块不交付：

- 新建、修改或删除任务、日历、计划、记忆等业务提案。
- 日周规划、复盘专用会话、长期记忆和向量检索。
- 每日金额额度、价格、预留、结算、供应商成本和备用服务路由。
- 语音输入和长期附件。

选择“持久化事件日志 + SSE + 最终消息快照”，不直接把供应商连接代理给浏览器。直接代理虽然首字延迟更低，但页面断开后无法可靠恢复，也不能满足后台 worker、单一终态和重试隔离。仅轮询快照实现简单，但会增加可见延迟和无效请求，保留为 SSE 不可用时的恢复路径。

## 2. 数据对象

### 2.1 Conversation

普通会话保存：

- `id`、`owner_id`、`title`、`title_source`。
- `version`、`archived_at`、`created_at`、`updated_at`。
- `title_source` 为 `auto` 或 `user`。空白会话使用“新对话”；第一条用户消息提交时生成最多 48 个字符的本地标题。用户改名后不再自动覆盖。

会话归档只是组织状态，不删除消息，也不改变历史是否可用于相关检索。归档会话不能提交新消息；重新打开后可继续。生成中的会话不能归档，用户须先等待或取消。

### 2.2 ConversationMessage

消息保存：

- 稳定 `id`、`owner_id`、`conversation_id` 和会话内递增 `sequence`。
- `role` 为 `user` 或 `assistant`。
- `status` 为 `complete`、`queued`、`running`、`failed`、`timed_out` 或 `cancelled`。
- `content`、`error_code`、`created_at`、`updated_at`、`completed_at`。

用户消息创建后不可原地修改，状态始终为 `complete`。每次接单在同一事务中写入用户消息、空的 assistant 占位消息、文本作业和初始事件。assistant 正文是长期可见的权威快照；流事件只是可清理的传输事实。

### 2.3 ChatGeneration

文本生成映射单独保存：

- `job_id`、`owner_id`、`conversation_id`。
- `request_message_id`、`response_message_id`。
- `history_through_sequence`、`context_message_ids`。
- `stream_generation`，每次实际供应商尝试开始时递增。

`context_message_ids` 在接单时冻结，worker 不因稍后新增消息而扩大输入。数据库延迟约束触发器保证每个 `conversation` 作业在事务提交时恰有一个有效映射，截图等其他能力不能挂载对话映射；消息身份字段创建后不可变。

### 2.4 AIJobEvent

事件按 `(job_id, sequence)` 唯一：

- `kind` 为 `job_state`、`content_reset` 或 `content_delta`。
- `generation` 标识当前尝试输出代次。
- `payload` 只保存该事件需要的数据。
- `expires_at` 固定为创建后 7 天。

`AIJob.last_event_sequence` 在同一行锁内递增。事件必须先提交，再由 SSE 查询并推送。事件到期后，客户端以消息正文和作业终态恢复，不重新调用模型。

## 3. 通用 AI 作业扩展

配置和作业能力新增 `conversation`。`AIJob` 增加可空的 `conversation_id`，`input_media_id` 改为可空，并增加按能力约束：

- `calendar_screenshot` 必须关联一份临时媒体，且不得关联会话。
- `conversation` 必须关联本人会话、不得关联临时媒体，并且必须存在一条 `ChatGeneration`。

作业继续使用 `queued → running → succeeded | failed | timed_out | cancelled`。文本流中的 `queued/running` 只表示生成状态，不等于业务提案可应用。

账号内最多同时存在 3 个普通对话作业；同一会话最多一个排队或执行中的作业。不同会话可以并行。限制由会话行锁、账号活动作业计数和 `AIJob.conversation_id` 上的数据库部分唯一索引共同保证，不镜像第二份活动状态。

## 4. 接单与上下文

`POST /api/v1/ai/conversations/{conversation_id}/messages` 接收：

- `operation_id`。
- `expected_conversation_version`。
- 1 至 12000 字符的纯文本。

事务顺序：

1. 重新校验账号、设备会话、CSRF 和 AI 访问状态。
2. 锁定会话并检查所有者、归档状态、版本和单会话活动作业。
3. 检查账号活动对话作业上限和已发布 `conversation` 配置。
4. 选择并冻结相关历史消息 ID。
5. 连续分配用户消息与 assistant 占位消息序号。
6. 写入消息、`AIJob`、`ChatGeneration`、初始 `job_state=queued` 事件和操作幂等结果。

相同操作号和相同正文返回原结果；相同操作号承载不同内容返回冲突。响应丢失时客户端使用原操作号重试，或重新读取消息列表；不会重复提问或创建第二个作业。

### 4.1 当前会话历史

选择当前会话中输入消息之前最近 30 条已完成消息，按时间正序发送，总正文最多 48000 字符。必须保留当前用户消息；超过上限时从最旧历史开始移除。

### 4.2 跨会话相关历史

从本人其他普通会话最近 200 条已完成用户消息中做确定性词项和 Unicode 双字重叠评分：

- 查询少于 2 个有效字符时不做跨会话检索。
- 只选择正分最高的 3 条用户消息，并可带上其紧随的已完成 assistant 回复。
- 跨会话正文总计最多 12000 字符。
- 相同分数按消息时间和 ID 稳定排序。

检索只读取本人普通会话消息、本人已确认且有效的长期记忆，不读取复盘短对话、已删除/已暂停记忆或其他账号数据。选中的稳定消息 ID 与记忆 ID/版本写入作业输入摘要，worker 调用前重新校验，便于复现、删除后即时退出检索和后续审计；未确认推断不能替代消息事实或进入长期记忆。

## 5. Provider 与 worker

`conversation` 配置测试使用合成文本，要求上游返回固定可见标记；不发送用户正文。截图配置继续使用合成图片测试。两种能力共用端点网络策略、Key 解密、请求时限和响应体上限。

文本 provider：

- 调用 `/chat/completions`，设置 `stream=true`，只接受文本回复。
- 系统消息明确此阶段只能回复文字，不能声称已经修改 iTime 业务数据。
- 兼容标准 SSE 分帧和一次性 JSON 响应。
- 对 401/403、429、5xx、其他非成功状态、连接失败、超时、无效分帧、空输出和超大输出返回稳定错误分类。
- 不把 Authorization、上游正文或原始异常写入普通日志和客户端错误。

worker 领取任意受支持能力后按 capability 分发。网络调用期间不持有数据库事务。

### 5.1 分段持久化

provider 将小 token 在内存中合并，满足任一条件时提交：

- 距上次提交达到 150 毫秒。
- UTF-8 正文达到 1024 字节。
- 流结束。

每次提交锁定作业，要求状态仍为 `running`、租约 ID 匹配且租约未过期，然后：

1. 追加 assistant 消息正文并更新消息快照。
2. 递增 `last_event_sequence`。
3. 写入 `content_delta` 事件。
4. 将租约延长到 `min(now + lease_seconds, deadline_at)`。

单条 assistant 回复最多 100000 字符，上游原始响应最多 1 MiB。超过限制终止生成并返回稳定错误。

### 5.2 租约续期

worker 在没有新 token 的等待期间也按 `lease_seconds / 3` 心跳续租。续租要求旧租约尚未过期；一旦失败，当前 provider 请求被取消，旧 worker 不得继续写事件、完成消息或结算。

通用完成、失败和截图结果提交同时补充“租约尚未过期”条件，避免合法过期的旧 worker 在尚未被重领时复活租约。

### 5.3 重试与 generation

网络、429 和 5xx 在总截止时间及最大尝试次数内有界重试。新尝试开始时：

- `generation += 1`。
- 清空上一失败尝试的 assistant 部分正文。
- 先写 `content_reset`，再写新 generation 的增量。

客户端只拼接当前 generation。鉴权、端点策略、结构、空输出和大小错误不自动重试。新作业按
`AIJobConfigRoute` 冻结主配置和最多两个备用配置；网络、429、5xx 等可重试失败的下一 generation
使用下一条路由，重试不重置总截止时间。

## 6. 取消、终态与恢复

取消继续使用 `POST /api/v1/ai/jobs/{job_id}/cancel`。取消事务锁定作业后：

- 将作业和运行中 attempt 设为 `cancelled`。
- 保留已可见的部分 assistant 正文，将消息设为 `cancelled`。
- 写终态 `job_state` 事件并清除租约。

供应商连接可能在网络层继续到下一次读写或超时，但旧租约的任何晚到增量、usage 或完成结果都无法提交。失败和超时保留已生成的部分正文，并分别标为 `failed`、`timed_out` 对应的稳定错误；页面明确这些内容不完整。

成功事务原子完成 assistant 消息、attempt、供应商成本、用户额度结算和作业，并写 `succeeded` 事件。质量采样已挂在同一终态事务并重新锁定用户开关；后续业务提案也必须沿用该边界，不能由 SSE 客户端触发。

## 7. API

| 方法与路径 | 输入与输出 | 主要失败 |
| --- | --- | --- |
| `GET /api/v1/ai/conversations` | 活动/归档筛选、稳定游标 → 会话摘要 | 未认证、游标无效 |
| `POST /api/v1/ai/conversations` | 操作号、可选标题 → 空会话 | AI 冻结不阻止创建空会话；操作号冲突 |
| `GET /api/v1/ai/conversations/{id}` | 会话详情与当前活动作业 | 不存在与他人会话统一 404 |
| `PATCH /api/v1/ai/conversations/{id}` | 操作号、预期版本、标题或归档状态 | 版本冲突、生成中不能归档 |
| `GET /api/v1/ai/conversations/{id}/messages` | `before_sequence`、limit → 正序消息页 | 所有者隔离 |
| `POST /api/v1/ai/conversations/{id}/messages` | 操作号、预期版本、正文 → 两条消息和作业 | 冻结、未配置、并发上限、活动作业、版本冲突 |
| `GET /api/v1/ai/jobs/{id}/events` | `after` 或 `Last-Event-ID` → SSE | 所有者隔离、游标无效 |
| `GET /api/v1/ai/jobs/{id}` | 作业快照及最后事件序号 | 所有者隔离 |
| `POST /api/v1/ai/jobs/{id}/cancel` | 操作号 → 终态快照 | 所有者隔离、幂等重放 |

SSE 事件包含 `id`、事件 kind 和 JSON 数据。连接先返回已有事件，活动作业最多等待 15 秒并定期发送注释心跳，然后关闭；浏览器可携带 `Last-Event-ID` 自动重连。响应正文发出后的数据库故障只中断该连接，权威状态仍从普通查询恢复。

## 8. Web 交互

`/ai` 成为登录后的默认产品入口。本模块完成时产品导航为 AI、任务、日历、设置；M5 规划界面接入后当前顺序为 AI、任务、规划、日历、设置。

- 桌面：左侧窄会话栏，右侧无卡片嵌套的消息与输入区域。
- 平板：保留双栏但缩窄会话栏。
- 手机：会话列表与单个会话分屏切换，进入会话后提供明确返回按钮。
- 输入框固定在内容流底部但不遮挡消息；支持多行，`Ctrl/Command + Enter` 提交。
- 生成中显示真实“排队中/生成中/正在重试”状态和取消按钮，不显示虚假百分比。
- 失败显示原因、保存状态、恢复动作和请求编号。部分正文明确标记“不完整”。
- 重新进入先读消息快照，再连接活动作业事件；SSE 错误时回退到有界作业轮询。
- 空会话、无配置、AI 冻结、离线、超时、取消和归档均有独立状态。

页面不把 AI 文本渲染为 HTML，普通回复按纯文本和换行展示，防止脚本和不可信链接注入。业务变更文字只作为普通回复，不显示“已应用”；M5 规划模式通过作业输出关联独立结构化提案，不解析正文。

## 9. 安全、隐私与容量

- 全部会话、消息、生成映射、事件和作业都带所有者约束；他人 ID 统一返回 404。
- 所有写操作经过服务端会话、CSRF、账号状态和操作号幂等检查。
- 普通日志只记录路由模板、状态、时长、作业 ID、能力和错误码，不记录消息正文、Key 或上游响应。
- 对话消息属于用户业务内容，账号存续期间保留；重复正文事件固定 7 天清理。
- AI 冻结只阻止新消息作业，不取消已接单作业，也不影响读取、归档和改名。
- 消息、上下文、输出、账号活动作业和事件提交频率都有明确上限；慢消费者不影响 worker，因为 SSE 只读数据库。

额度模块已接入：接单事务按整条冻结主备路由的最大估算创建一次预留，终态事务按成功 attempt
实际配置成本结算或在失败/取消时释放。失败 attempt 成本归平台，页面不显示虚构余额或“本次
免费”。

- 迁移升级、降级保护和 ORM 漂移。
- 多会话分页、改名/归档、操作重放、版本冲突和双账号隔离。
- 消息、assistant 占位、作业、生成映射和事件的单事务原子性。
- 当前会话裁剪、跨会话相关选择、稳定顺序及不发送无关账号正文。
- SSE 半帧、多 data 帧、JSON 回退、空输出、超大输出、401、429、5xx、超时和断流。
- 双 worker 领取、空闲流续租、租约失效、重试 reset、取消与增量/成功竞态。
- 主服务 429 后备用服务以新 generation 接管、不同模型/Key 与成本归属、401 不切换，以及作业
  总截止时间保持不变。
- 事件 7 天清理后仍可从消息快照恢复。

Web 使用生产构建和真实 Chromium 验证：

- 创建多个会话、切换、改名、归档/恢复和消息持久化。
- 首字/分段显示、离页继续、刷新恢复、SSE 断线续读、轮询回退和显式取消。
- 未发布配置、AI 冻结、并发限制、失败、超时和请求编号。
- 桌面、平板、手机、320px 最大字号、键盘、焦点、减少动效、axe、控制台和横向溢出。

本模块通过本身不代表提案、规划或完整 Web 首版通过；日志/质检、额度和规划提案的后续实现与证据分别见[AI 日志与质检设计](iTime-AI日志与质检设计.md)、[AI 额度与成本账本设计](iTime-AI额度与成本账本设计.md)、[AI 提案与日周规划设计](iTime-AI提案与日周规划设计.md)及[实施与验证](../验收/iTime-Web实施与验证.md)。

## 11. 已实现合同

- `/api/v1/ai/conversations`、消息分页、通用作业查询/取消和 `/api/v1/ai/jobs/{id}/events` 已接入 `/ai`；登录默认进入该页面。
- 管理后台可分别维护截图、转写、对话、规划和复盘五类能力配置版本，使用不含用户正文的合成输入测试，并按能力设置最多两个
  备用服务；路由版本冲突会保留当前草稿供管理员基于最新版重试。

用户开关及管理访问审计均已接入；对应入口不会显示虚构的额度或“已应用”状态。正式第三方模型

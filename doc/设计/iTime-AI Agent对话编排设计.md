# iTime AI Agent 对话编排设计

版本：0.1；更新：2026-10-08。本文替代“用户先选择普通回复或生成计划”的交互，定义以全局会话为主入口的 AI Agent 编排、工具调用、业务提案和确认执行合同。

## 1. 产品目标

用户只需自然描述目标，例如“明天上午学习两小时线性代数”。iTime 自动理解意图、读取本人相关任务与日历、生成计划提案，并在同一会话中等待用户确认或调整。

Agent 首版覆盖当前用户端的主要业务：

- 查询和整理任务，提议新建、修改、排期、完成或归档。
- 查询和调整日历，提议新增、修改、取消或移动安排。
- 生成日计划、周计划并复用现有规划校验和版本能力。
- 发起课表导入，处理图片、公开网页、文件或文字描述。
- 发起或继续单日复盘，生成报告和下一步建议。
- 读取已确认长期记忆，提议新增、修改、暂停、恢复或删除记忆。
- 建议开始专注并带入任务、步骤和计划块。

账号安全、管理员操作、支付、导出、注销和永久清理不开放给 Agent。

## 2. 方案选择

采用“服务端 Agent 编排器 + 类型化工具 + 确认式提案”：

- 会话模型可以选择读取工具和提案工具。
- 读取工具由服务端执行，并把有界结果返回模型继续推理。
- 写入类工具只生成提案，不直接修改业务数据。
- 用户确认时由对应领域服务重新校验所有权、版本、时间和业务约束。

未采用的方案：

1. **浏览器关键词路由**：实现快，但无法可靠理解自然语言、上下文和混合意图。
2. **模型直接调用写接口**：交互快，但无法满足预览确认、并发复核和可审计要求。
3. **为每种意图增加手动模式**：延续当前问题，用户仍需先理解产品结构再选择入口。

## 3. 会话交互

`/ai` 保持登录后的默认页，采用已确认的“对话主画布”：

- 移除“普通回复 / 生成计划”模式切换和默认展开的规划参数。
- 输入框接受自然语言，附件菜单接受图片、文件和网址。
- AI 回复、真实执行状态和业务提案按时间顺序出现在消息流中。
- 提案卡直接提供“确认”“调整”“拒绝”；复杂调整进入对应领域编辑器，返回后仍在原会话显示结果。
- 会话顶部只保留名称和必要命令，不放功能介绍或冗长副标题。
- 桌面显示会话侧栏和主画布；手机在会话列表与单个会话间切换。

自然语言时间先按用户 IANA 时区解释。缺少关键事实时，Agent 每轮只问最少的问题；可采用可靠默认值时直接给出提案，并在提案中标记假设。

## 4. Agent 作业与工具循环

现有 `conversation` 能力升级为 Agent 会话能力，不增加需要用户选择的响应模式。接单事务继续创建用户消息、assistant 占位消息、作业、额度预留和操作去重记录。

worker 的单次作业最多执行四轮工具循环：

1. 载入当前会话、相关历史、已确认记忆和最小账号上下文。
2. 调用已发布会话模型，允许 `tool_choice=auto`。
3. 校验工具名称、参数、所有权范围和调用预算。
4. 只读工具执行后把结构化结果加入同一作业上下文；提案工具创建待确认结果并结束循环。
5. 无工具调用时保存普通文本回复。

总截止时间、主备路由、租约、取消、额度和治理日志沿用现有 AI 作业合同。工具循环不重置截止时间；网络调用期间不持有数据库事务。

## 5. 工具注册表

工具按版本注册，每项明确输入 schema、权限、读取上限、输出 schema 和是否需要确认。

### 5.1 只读工具

- `search_tasks`：按状态、日期和文本检索本人任务。
- `read_calendar`：读取指定日期范围的本人日历投影。
- `read_plan`：读取当前计划、未排项和版本。
- `read_focus`：读取开放专注及近期执行事实。
- `read_review`：读取指定活动日的复盘事实和报告。
- `read_memories`：读取启用且未删除的已确认记忆。

只读工具可以自动执行。每次结果限制数量和正文长度，返回稳定 ID 与版本；不把其他账号数据、管理员数据或密钥暴露给模型。

### 5.2 提案工具

- `propose_task_changes`
- `propose_calendar_changes`
- `propose_plan`
- `propose_focus_start`
- `propose_review_actions`
- `propose_memory_changes`
- `propose_timetable_import`

提案工具只接受服务端公布的字段和枚举。未知工具、多个互斥写工具、越权 ID、超过数量限制或结构错误都会终止本次作业，不生成可确认提案。

## 6. 通用业务提案

现有规划 `Proposal` 扩展为通用 `ActionProposal` 语义，保留稳定 ID、来源作业、会话、状态、版本、过期时间和有序变化列表。

提案种类包括：

- `plan`
- `task`
- `calendar`
- `focus`
- `review`
- `memory`
- `timetable_import`
- `mixed`

每条变化保存动作、实体类型、目标 ID、预期版本、变更前关键值和变更后候选值。涉及多个领域的 `mixed` 提案必须能在一个事务中全部成功或全部失败；不允许部分写入后返回失败。

状态为 `pending | applied | rejected`，页面另计算 `expired | conflicted`。默认七天过期；来源对象变化后提案只可查看和重新生成。

## 7. 确认与执行

用户确认请求包含提案版本和新的 `operation_id`。服务端按固定顺序：

1. 锁定提案和涉及的账号级修订行。
2. 校验所有目标仍属于本人，版本与提案快照一致。
3. 重新执行领域校验，包括日历重叠、任务状态、计划输入修订和记忆来源。
4. 调用现有任务、日历、规划、专注、复盘或记忆服务。
5. 写入同步变更、操作去重和提案终态。

重复确认返回同一结果。确认响应未知时客户端先按原操作号查询或重试。冲突时保留提案与用户调整内容，显示变化对象并提供重新生成或进入领域页处理。

## 8. 输出与消息

assistant 消息包含纯文本正文和可选结构化附件引用：

- `proposal_id`
- `import_batch_id`
- `review_id`
- `navigation_target`

正文不得声称未确认操作已经执行。页面不从模型正文解析 JSON、日期或业务 ID；所有可操作内容都从服务端结构化引用加载。

提案应用后，同一消息卡更新为“已完成”，并列出简短结果。用户拒绝后显示“已拒绝”；过期或冲突显示对应事实和恢复动作。

## 9. 错误、并发与资源

- 同一会话同时只有一个活动 Agent 作业；账号 AI 作业总并发继续受限。
- 工具调用总轮数、每轮数量、上下文字节和输出大小都有硬上限。
- 用户取消后保留已流式显示的文字，但未完成的工具结果不能生成提案。
- 读取失败不返回猜测结果；写提案校验失败不扣用户额度。
- 作业成功且文本或提案已可查看时结算额度；确认执行不重复收取 AI 额度。
- AI 冻结阻止新作业，不影响读取历史提案和已确认数据。
- 技术日志、质量样本和访问审计沿用现有期限与开关。

## 10. 验收

至少覆盖：

- “明天上午学习 X”无需选择模式，自动读取冲突并生成日计划提案。
- 一条消息同时创建任务并安排日历，确认前无业务写入，确认后原子落库。
- 修改任务、移动安排、开始专注、复盘和记忆提案均可从会话完成。
- 模糊输入只追问必要信息；普通问答不误生成提案。
- 工具越权、未知 ID、结构错误、循环超限、取消、超时、主备切换和版本冲突。
- 刷新、离页、跨设备恢复后，消息和提案状态一致。
- DeepSeek 真实端点的普通回复、工具选择、计划、任务、日历、复盘和记忆闭环。
- Chromium 与真实 Edge 的电脑、平板、手机视口、键盘和无障碍验证。

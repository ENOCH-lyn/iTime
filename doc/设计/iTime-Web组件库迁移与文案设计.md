# iTime Web 组件库迁移与文案设计

版本：0.1；更新：2026-10-08。本文定义完整 Web 用户端与管理后台迁移到 Element Plus 的边界，以及全站文案收敛规则。用户已确认“全部 UI 优先使用组件库实现，不重复造轮子”，组件库采用 Element Plus。

## 1. 目标与范围

本次迁移覆盖现有 Vue Web 的公开页、账号流程、用户端、管理后台和所有对话框。目标不是更换视觉品牌，而是统一控件行为、可访问性、响应式状态和交互反馈。

迁移原则：

- 表单、按钮、选择器、日期时间、上传、对话框、抽屉、菜单、分段切换、标签页、表格、分页、提示、确认和加载状态优先使用 Element Plus。
- Lucide Vue 继续作为业务图标来源，不重画已有通用图标。
- 自定义组件只负责业务组合、时间网格、计划时间轴、专注计时器等产品特有界面，不复制组件库已有控件。
- 现有服务端接口、权限、操作幂等、离线队列和业务状态不因迁移改变。
- 每批迁移后立即执行构建和真实浏览器回归，不等待全站替换后再集中排错。

## 2. 技术方案

前端新增 `element-plus`，使用 Vite 按需组件与样式导入。根组件通过 `ElConfigProvider` 统一中文语言、尺寸和层级；主题桥接层把 iTime 的现有颜色、字体、圆角、字号和明暗模式映射为 Element Plus CSS 变量。

保留两类样式：

1. **产品布局样式**：导航、工作区、时间网格、消息流和响应式布局。
2. **组件主题样式**：Element Plus token 覆盖和少量领域组件状态。

删除或停止新增以下自研基础控件样式：`.button`、`.field`、`.segmented-field`、原生 `dialog` 交互、通用输入框/选择框/开关/分页/确认弹窗。迁移期间允许短期兼容，但同一个页面不能长期混用两套同类控件。

## 3. 组件映射

| 现有实现 | 迁移目标 |
| --- | --- |
| 原生按钮及 `.button` | `ElButton` |
| 原生输入框、文本域 | `ElInput`、`ElInputNumber` |
| 原生 `select`、单选分段 | `ElSelect`、`ElSegmented`、`ElRadioGroup` |
| 日期、时间输入 | `ElDatePicker`、`ElTimePicker`、`ElTimeSelect` |
| 原生 `dialog` | `ElDialog`；移动端复杂编辑使用 `ElDrawer` |
| 自研表单错误布局 | `ElForm`、`ElFormItem` |
| 文件选择与拖放 | `ElUpload` |
| 状态文字块 | `ElAlert`、`ElResult`、`ElEmpty`、`ElSkeleton` |
| 确认操作 | `ElPopconfirm` 或 `ElMessageBox` |
| 页面分区切换 | `ElTabs`、`ElSegmented` |
| 管理列表与明细 | `ElTable`、`ElPagination`；窄屏转列表/抽屉 |
| 菜单与次级命令 | `ElDropdown`、`ElMenu` |
| 数量、状态和进度 | `ElBadge`、`ElTag`、`ElProgress` |

不使用组件库强行替代周历网格、计划块布局、会话消息、统计图和专注计时器；这些结构继续由领域组件实现，内部操作控件改用 Element Plus。

## 4. 迁移顺序

迁移按风险和复用度分四批：

1. 根配置、主题 token、通用反馈和认证表单。
2. 管理后台、账号设置及通用对话框。
3. AI、任务、规划、日历、专注、复盘和统计工作区。
4. 公开页面、帮助、协议和遗留样式清理。

每批必须独立提交。迁移页面保留原路由和测试定位语义；确需更改选择器时，同批更新 Playwright 用例。

## 5. 文案规则

界面默认只保留完成任务所需的信息：

- 页面标题直接说明当前位置，不默认添加副标题。
- 输入标签说明字段含义；占位文字只给输入示例，不重复标签。
- 按钮使用明确动词，例如“添加任务”“确认导入”“重新生成”，不使用“好的”“继续操作”等空泛表达。
- 空状态说明当前事实并给一个主要动作，不介绍整套功能。
- 成功提示只说明结果，例如“已添加到日历”。
- AI 提案明确标注“待确认”，不重复解释 AI 能做什么。
- 技术说明、隐私期限和不可逆后果只在相关设置或确认步骤出现。
- 错误必须保留失败原因、数据是否已保存、恢复动作和请求编号；精简文案不能删掉这些信息。

允许保留说明文字的场景仅包括：安全风险、数据生命周期、费用/额度、跨设备冲突、不可逆或状态未知操作。

## 6. 响应式与可访问性

- 桌面保持多栏工作区，平板减少侧栏宽度，手机使用抽屉或页面级切换。
- 触控目标不小于 44px；图标按钮必须有 `aria-label` 和 tooltip。
- 对话框在手机上不得超出可视区域，复杂编辑默认全屏抽屉。
- 字号设置、深色模式、系统主题和减少动效继续生效。
- 不允许水平根溢出、按钮文字截断、标签遮挡输入或弹层失去焦点。
- Element Plus 的默认样式只是基础，仍需验证颜色对比、键盘顺序、焦点返回和读屏名称。

## 7. 状态与失败恢复

组件迁移不得把真实业务状态压缩成单一 loading：

- 提交中禁止重复操作，但允许明确取消的后台 AI 作业继续提供取消入口。
- 响应未知时保留输入和操作号，先重新读取再重试。
- 版本冲突展示服务器最新状态并保留本地草稿。
- 列表刷新失败保留上次成功数据。
- 关闭弹层不自动取消服务端作业，重新打开后恢复状态。

## 8. 验收

每批至少完成：

- `pnpm build`。
- 对应 Playwright 核心流程。
- Chromium 的电脑、平板、手机视口。
- 真实 Edge 的核心页面与对话框。
- 浅色、深色、最大字号、键盘、axe、控制台错误和根级横向溢出检查。

全站迁移完成的判定是：业务页面不再直接实现组件库已有的通用控件，遗留基础样式已删除或仅服务尚未迁移的明确页面，且现有功能和失败恢复没有回归。

# iTime Chat-first 界面重构设计

版本：0.1；更新：2026-10-08。状态：方向已确认，待实现。

本文定义 iTime Web 用户端的新信息架构和 AI 对话主体验。重构不是交付目标；交付目标是消除遮挡、裁切、空标题、层级混乱、重复解释和移动端不可用等问题，让用户无需阅读说明即可完成主要操作。

## 1. 目标与非目标

### 1.1 目标

- AI 对话是登录后的主页面和产品核心，整体体验接近 GPT Web：会话历史清楚、标题可见、消息易读、输入稳定。
- 主导航按用户任务分层，不再把产品模块、会话历史和账号设置混在同一层。
- 通用控件优先使用 Element Plus；业务视图保留必要的领域组件。
- AI 回复支持安全 Markdown，任务、计划和课表等业务结果继续使用结构化卡片。
- 设置合并为一个页面，密码、设备、隐私、额度、同步、数据和外观不再各占一个主导航入口。
- 默认文案只表达当前对象、状态和可执行动作；解释性文字仅保留在安全、费用、隐私、数据生命周期和失败恢复场景。
- 视觉验收必须检查真实截图和元素几何关系，不能用构建、axe、无横向溢出或流程通过代替。

### 1.2 非目标

- 不为了“全部第三方组件”替换日历网格、消息流、提案卡等领域组件。
- 不删除任务、规划、日历、专注、复盘和统计能力。
- 不把 AI 未确认输出直接应用为业务事实。
- 不在本轮改变后端业务语义、权限、同步、额度或数据生命周期。
- 不增加营销装饰、引导页、悬浮助手、业务提醒或通知中心。

## 2. 当前问题

### 2.1 组件使用

当前仅按钮、输入、弹层、上传、分段控件等部分基础控件来自 Element Plus；导航、消息、设置列表和大量表单布局仍是自研。组件库迁移本身不能解决信息架构和视觉层级问题。

后续规则：

- 按钮、输入、表单、选择器、开关、弹层、抽屉、下拉菜单、Tooltip、上传、分页和通用反馈使用 Element Plus。
- 消息流、会话历史、日历、计划时间块、任务详情和业务提案卡是领域组件，可以自研。
- 不再自研已有成熟实现的通用控件，也不强行把领域界面拼成通用卡片。

### 2.2 AI 对话

当前实现存在以下问题：

- 会话列表标题因 DOM 结构与 CSS 选择器不一致而可能只剩图标，用户无法识别会话。
- 会话标题虽然存在于 DOM，但顶部同时显示“AI 对话”等重复标签，真正标题层级不够明确。
- AI 正文使用普通 `<p>` 和 `white-space: pre-wrap`，没有 Markdown 语义。
- 输入区与消息区缺少明确的几何验收合同，长输出、动态卡片、字号变化或手机键盘出现时可能遮挡最后内容。
- 字数统计、作者标签、时间、附件文案和状态同时出现，次要信息噪声过高。
- 当前侧栏同时承担产品导航、会话历史、账号信息和退出操作，层级混乱。

### 2.3 设置

当前 `/account/*` 虽复用一个页面组件，但视觉上仍把“修改密码、登录设备、隐私、额度、同步、数据、外观”作为等权页面和侧栏导航项；概览页又重复展示相同入口和解释，形成双重导航。

## 3. 信息架构

### 3.1 全局应用外壳

桌面使用两级结构：

1. **全局窄栏，64px**
   - iTime 标识。
   - AI。
   - 任务。
   - 日历。
   - 专注。
   - “更多”菜单：规划、复盘、统计。
   - 底部账号头像菜单。

2. **当前功能侧栏**
   - AI 页面显示会话历史。
   - 任务页面显示项目和任务范围。
   - 日历、专注、复盘等页面仅在确有二级导航时显示；没有二级结构时不展示空侧栏。

账号菜单包含：

- 设置。
- 帮助。
- 退出登录。

设置不再出现在全局主导航。同步正常时不展示独立入口；只有待同步、离线或冲突时，才在全局栏或账号区域显示状态。

### 3.2 平板与手机

- 平板保留 56-64px 全局窄栏，会话历史可折叠为抽屉。
- 手机不常驻侧栏。顶部只显示返回、会话标题和更多操作。
- 左上入口打开统一抽屉，先显示新建会话和历史，再显示任务、日历、专注及“更多”。
- 从会话列表进入消息后使用全屏消息视图；返回动作回到原滚动位置。

### 3.3 路由兼容

- `/ai` 继续作为登录后默认入口。
- 新设置主路由为 `/settings`。
- 现有 `/account/password`、`/account/devices` 等地址保留兼容重定向，落到 `/settings` 对应锚点或打开相应抽屉。
- 结构化功能路由继续保留，避免破坏收藏、刷新和跨模块深链接。

## 4. AI 对话主界面

### 4.1 会话历史

会话侧栏顺序：

1. “新建会话”主操作。
2. 搜索会话。
3. 可滚动历史列表。
4. 底部折叠控制。

每行只显示：

- 会话标题，单行截断但保留 Tooltip。
- 最后更新时间。
- 有活动作业时显示一个状态图标。
- 悬停或聚焦时显示更多菜单，包含重命名和归档。

不得出现只有图标没有标题的会话行。自动标题生成后立即更新当前标题；新会话在首条消息前显示“新对话”。

### 4.2 会话顶部

- 高度 56-64px。
- 主标题直接使用会话标题，不显示“AI 对话”副标题。
- 标题可通过菜单重命名。
- 右侧只保留更多操作；生成中时显示停止按钮。
- 重新读取属于错误恢复操作，正常状态不常驻显示。

### 4.3 消息布局

- 正文列最大宽度 760-800px，居中。
- 用户消息右对齐，使用低对比度背景。
- AI 消息不使用整块气泡，保持开放正文布局。
- 不在每条消息重复显示“你 / iTime”；时间默认隐藏，在悬停、聚焦或详情菜单中查看。
- 连续同角色消息合并视觉间距。
- 提案、课表导入、错误恢复等结构化内容位于对应 AI 消息之后，不嵌套进正文气泡。
- 加载状态只显示真实阶段；完成后原位替换，不插入重复状态。

### 4.4 Markdown

仅 AI 正文启用 Markdown；用户输入按纯文本显示。

实现使用成熟解析与清理库：

- `markdown-it` 解析。
- `DOMPurify` 清理输出。
- 禁止原始 HTML。
- 支持段落、二至四级标题、粗体、斜体、列表、引用、链接、表格、行内代码和代码块。
- 外部链接使用 `target="_blank"` 和 `rel="noopener noreferrer"`。
- 代码块提供复制按钮；首版不要求重量级语法高亮。
- 标题字号受消息排版系统约束，不能出现页面级巨型标题。
- 业务动作不从 Markdown 中解析，仍以服务端结构化卡片为准。

### 4.5 输入区

输入区是 `.ai-main` 的独立最后一行，不使用覆盖消息的绝对定位。

- 文本框默认一至两行，最多扩展到八行。
- 附件存在时显示一个紧凑附件行。
- 左侧为附件按钮；右侧为发送或停止按钮。
- 字数低于上限 80% 时不显示计数。
- 不显示“添加课表”等模式性文案，附件按钮使用回形针图标和 Tooltip；Agent 自行判断附件用途。
- 发送快捷键为 Enter；Shift+Enter 换行。需要保留兼容时可在设置中提供快捷键偏好，不在界面常驻解释。
- 中文等输入法处于 composition 状态时，Enter 只确认输入法候选，不触发发送。

消息视口和输入区必须满足：

- 输入区始终占据布局空间。
- 滚动到底部时，最后一条消息底部与输入区顶部至少间隔 16px。
- 输入区高度变化后重新计算可视区域，不覆盖当前消息。
- 用户正在向上阅读时，新内容不强制滚到底部，只显示“回到最新”按钮。
- 用户已接近底部时，新内容保持跟随。
- 手机使用 `100dvh`、`env(safe-area-inset-bottom)` 和 `visualViewport` 处理软键盘。

## 5. 设置页

`/settings` 是单一页面，不使用与主产品相同重量的二级侧栏。

页面按自然顺序排列开放区段，以分隔线而非嵌套卡片分组：

1. **账号与安全**
   - 邮箱和验证状态。
   - 修改密码按钮，打开对话框。
   - 登录设备摘要，打开抽屉查看和退出设备。

2. **偏好**
   - 主题。
   - 字号。
   - 周起始日和时区入口；具体时间设置仍复用现有服务。

3. **AI 与隐私**
   - 当日可用额度使用紧凑进度与金额，不展示完整账本说明。
   - 质量改进开关。
   - 技术正文保留期只在详情中展示。

4. **数据与同步**
   - 同步正常时只显示“已同步”和最后时间。
   - 有冲突或待传时展开恢复操作。
   - 数据导出使用明确命令和作业列表。

5. **账号操作**
   - 帮助。
   - 退出登录。
   - 注销账号位于页面底部危险区。

密码、设备、导出作业和删除确认可使用 Dialog 或 Drawer，但不再要求用户理解多个设置子路由。

## 6. 文案规则

### 6.1 默认删除

- 页面功能副标题。
- 重复说明当前页面能做什么的段落。
- 与按钮同义的小标题。
- “智能、全能、高效”等营销形容词。
- 正常状态下的成功说明和技术实现描述。
- 用户不需要据此做决定的内部状态。

### 6.2 必须保留

- 不可逆或高风险操作的后果。
- 保存是否成功、数据是否已写入、AI 额度是否扣除。
- 隐私用途、保留期限和训练边界。
- 冲突双方差异和恢复操作。
- 网络失败、超时和未知结果的请求编号。
- AI 内容仍待确认的明确状态。

### 6.3 命名

- 页面标题使用对象名或任务名。
- 按钮使用动词，如“保存”“导出”“退出设备”。
- 空状态使用一句结果描述和一个操作。
- 不用副标题解释图标；不熟悉图标使用 Tooltip 和无障碍名称。

## 7. 视觉系统

- 背景使用真实白色和中性浅灰层级，不使用大面积米色、紫色渐变或装饰光斑。
- 品牌绿色只用于选中、主要操作和状态强调，不让整页成为单一绿色调。
- 普通面板圆角不超过 8px；输入主容器可使用 8-12px，但全站保持一致。
- 主正文 15-16px，行高 1.65；导航和元信息 12-14px。
- 消息内标题最多 20px，不与页面标题竞争。
- 阴影仅用于抽屉、浮层和输入聚焦，不用阴影把每个区段变成卡片。
- 动效只用于侧栏开合、消息出现、状态切换和“回到最新”，并支持减少动效。

## 8. 错误与状态

- 页面级错误固定在当前工作区可见位置，不重复出现在侧栏和正文。
- 消息发送未知时保留输入和操作号，提供“检查结果”而不是直接再次创建。
- Markdown 解析失败时回退为纯文本，不影响业务卡片。
- 会话标题加载失败时保留上一标题，不显示空白行。
- 附件上传、Agent 工具、提案确认和课表识别分别显示自身状态，不用一个全局加载遮住整个会话。
- 设置保存失败保留当前选择，并说明服务器实际状态是否已确认。

## 9. 组件边界

新增或重构的主要组件：

- `AppRail`：全局一级导航。
- `AccountMenu`：设置、帮助和退出。
- `ConversationSidebar`：新建、搜索、历史和折叠。
- `ConversationHeader`：标题、停止和菜单。
- `MarkdownMessage`：安全 Markdown。
- `ConversationViewport`：滚动跟随和回到最新。
- `ConversationComposer`：输入、附件和发送。
- `SettingsPage`：统一设置编排。

现有提案卡、课表导入卡和服务 API 保持独立，不塞入 `MarkdownMessage`。

## 10. 响应式合同

| 视口 | 布局 |
| --- | --- |
| 1440×1000 | 全局窄栏 + 会话侧栏 + 消息主区 |
| 1024×768 | 全局窄栏常驻，会话侧栏可折叠 |
| 768×1024 | 全局窄栏常驻，会话历史使用抽屉 |
| 390×844 | 单页会话；历史与应用导航使用抽屉 |
| 320×700 最大字号 | 单页会话；标题、消息、输入和按钮不裁切 |

窗口高度不足时，消息视口缩小，输入区保持可见；不得通过覆盖消息换取输入区可见。

## 11. 视觉验收

### 11.1 必测数据

- 至少 20 条历史会话，包含长标题、中文、英文和无空格长串。
- 至少 30 条消息。
- AI 长回复包含标题、段落、列表、表格、引用、链接、行内代码和代码块。
- 同一会话包含任务提案、规划提案、课表导入卡、附件、失败、取消和生成中状态。
- 设置页包含正常同步、待同步、冲突、额度不足、导出处理中和注销确认。

### 11.2 几何门禁

Playwright 必须直接断言：

- 会话标题文本非空且可见宽度大于 48px。
- 每个可见会话行的标题矩形不为零，不被操作按钮完全覆盖。
- 消息视口与输入区矩形不相交。
- 滚动到底部时，最后消息底部小于等于输入区顶部减 16px。
- 输入扩展到八行、附件出现、错误出现后仍满足不相交。
- 手机模拟视口高度缩小时，聚焦输入后最后消息和发送按钮仍可到达。
- 页面 `scrollWidth <= clientWidth`，且没有文本被 `overflow: hidden` 意外裁掉；仅明确的单行标题允许省略。

### 11.3 人工截图审查

每轮实现必须保存并实际查看以下截图：

- 桌面普通会话。
- 桌面长 Markdown 与代码块。
- 桌面多提案卡。
- 平板会话历史抽屉。
- 手机长回复底部和输入区。
- 320px 最大字号与附件。
- 设置页正常、冲突和危险操作状态。

人工审查逐项记录：标题、消息排版、输入区、滚动、按钮、文字换行、空状态、错误状态和导航层级。只有构建、axe、E2E 或截图文件存在，均不能标记视觉通过。

## 12. 验收标准

- AI 对话是登录后的清晰主体验，首次用户无需理解模式即可开始。
- 会话标题在所有目标视口可见，重命名和归档可到达。
- AI Markdown 安全、可读，业务操作仍由结构化卡片承载。
- 输入区不遮挡任何消息、状态或业务卡片。
- 主导航不再展示设置子项；设置在一个页面完成。
- 默认页面不依赖说明段和重复小标题解释功能。
- Element Plus 覆盖通用控件，不再重复实现通用交互。
- Chromium 与真实 Edge 的目标视口通过功能、几何和截图人工审查。
- 没有可修复的视觉缺陷遗留到验收说明中。

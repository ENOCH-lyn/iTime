# iTime 本人数据导出设计

版本：0.1；更新：2026-10-04。本文细化 `REQ-EXPORT-01`、`AUTH-02` 和
`PRIV-04`，定义 Web 首版本人数据导出的范围、快照、格式、作业、下载、清理和界面合同。
导出产物期限、容量上限、历史保留和格式细节是用户授权代理自行决定后的可演进默认，
不表述为用户原始决定。

## 1. 范围与方案选择

本阶段交付：

- 用户在 `/account/data` 创建完整数据导出，离页后由独立 worker 生成。
- 一个 ZIP 同时包含完整 JSON、分类 CSV、日历 ICS、文本 Markdown 和清单。
- 导出时从 PostgreSQL 读取同一一致性快照，不依赖浏览器已加载的分页数据。
- 产物使用独立密钥加密后短期保存在 PostgreSQL，仅本人认证下载。
- 排队、生成、成功、失败、过期和重新生成均有持久状态、错误原因及请求编号。
- 真实 PostgreSQL、Uvicorn、独立/双 worker、进程重启、下载校验和 Chromium 验证。

本阶段不交付：

- 从导出包恢复账号、跨账号导入、公开分享链接或管理员代用户下载。
- 将密码哈希、会话令牌、邮箱验证令牌、TOTP、恢复码、平台 Key、内部租约或请求摘要写入导出。
- 将管理员配置、供应商成本、内部技术正文日志、质量样本或管理审计混入本人内容导出。
- 导出已按生命周期彻底清除的正文、临时原图或已到期的流式事件。
- 对象存储、超大账号分片下载或法律主体访问请求工作流；这些属于部署和运营阶段。

比较过三种实现：

1. **持久化作业 + PostgreSQL 加密产物（采用）**：与现有作业、租约和单一权威数据库一致，
   可离页恢复、重试和多实例下载；首版文本数据规模适合有限大小的数据库产物。
2. 请求内即时流式生成：无新表，但长账号容易超过普通请求超时，断线后只能重新生成，
   也难以保证多个格式来自同一快照。
3. 持久化作业 + 对象存储：容量和流式下载最佳，但当前没有已部署对象存储、生命周期策略和
   凭据边界，引入它会扩大首版运维面。后续迁移时保持作业与下载 API 不变。

## 2. 可演进产品默认

1. 用户每次创建的是一个“完整数据包”，无需分别选择格式。完整 JSON 是权威无损格式，
   CSV、ICS 和 Markdown 是便携视图，不能反向推定 JSON 缺失。
2. 同一账号最多有一个 `queued` 或 `running` 导出。重复点击返回现有活动作业；
   同一 `operation_id` 和相同请求重试返回第一次结果。
3. 作业成功后可重复下载 24 小时。到期后清除加密产物并标记 `expired`；
   用户可重新生成最新快照。
4. 作业元数据保留 30 天，随后由同一 worker 限批删除。元数据不包含导出正文。
5. 最近 20 个作业可在设置页查看。失败或过期作业的“重新生成”创建新作业，
   不修改旧作业，不把旧快照冒充最新数据。
6. 一次导出解压后正文总量最多 100 MiB，ZIP 明文最多 50 MiB。超过限制时作业失败，
   不保存部分产物；错误说明容量限制和请求编号。限制在 M8 容量测试后可调整。
7. 下载文件名为 `itime-export-YYYYMMDD-HHMMSSZ.zip`，内部路径固定使用 ASCII，
   所有文本为 UTF-8，时间点为带 `Z` 或 UTC 偏移的 ISO 8601，日期保持 `YYYY-MM-DD`。
8. 生成中的并发编辑不会被阻塞。导出使用 PostgreSQL `REPEATABLE READ READ ONLY`
   一致性快照；成功结果记录实际快照时刻，之后提交的修改只进入下一次导出。
9. 导出不扣 AI 额度，不调用供应商，不生成同步变更，也不延长原业务数据生命周期。

## 3. 数据范围

完整 JSON 以用户当前可归属的数据为准，包含活动、归档、30 天回收站和可追溯历史，
但不复活已经彻底清理的正文。

| 分类 | 包含 | 明确排除 |
| --- | --- | --- |
| 账号 | 用户 ID、邮箱、验证时刻、账号/AI 状态、创建时刻；设备名称、创建/最近活动、到期和撤销时刻；本人安全事件 | 密码哈希、会话 token/hash、CSRF、邮箱 token、邮件队列、限流桶 |
| 设置 | 时区与 04:00 活动日、隐私质量开关、长期记忆开关 | 仅浏览器本地保存的主题/字号；平台全局策略 |
| 任务 | 项目/目标、任务、步骤、链接、标签关系、截止与重复规则、实例完成/跳过/调期/补做、归档及回收状态 | `UserOperation` 响应缓存和 `ChangeEvent` 内部同步事件 |
| 日历 | 学期与节次、来源、手工/导入系列、例外、补课、导入批次/候选/身份、订阅设置/事件/本地覆盖/刷新摘要 | 原上传文件、临时截图二进制、订阅 HMAC/密文、worker 租约、HTTP 缓存验证器 |
| AI 对话 | 普通会话、完整消息和用户可见生成状态 | 系统提示词、配置 ID/端点/Key、provider 请求 ID、逐片事件、技术正文日志、质量样本 |
| 规划 | 用户指令和选择范围、提案及差异、计划全部版本、计划块、未排项 | worker 租约、供应商原始响应；与业务结果重复的内部 job output |
| 执行 | 专注会话、不可变事件、修订前后值和困难记录，包含回收状态 | 已彻底清理的困难正文 |
| 复盘与记忆 | 复盘会话、用户补充、问答、报告全部版本、批注、记忆候选、长期记忆及回收状态 | 系统生成提示词和只用于 worker 校验的内部引用 |
| 额度 | 每日额度窗口、本人预留状态和用户账本；管理调整的金额、原因与时刻 | 平台价格策略细节、供应商成本、管理员身份、内部请求 ID |
| 临时媒体 | 文件名、类型、大小、尺寸、创建和清理状态的元数据 | 原图内容；原图仍按确认后或 24 小时规则清理 |

订阅 URL 是用户提交的敏感数据，完整 JSON 中包含原始 URL；它只在 worker 内解密，
不会进入日志、错误、CSV、ICS、Markdown 或作业元数据。无法解密任一订阅 URL 时整个作业失败，
避免生成看似完整但缺少关键数据的包。

## 4. 导出作业与生命周期

新增 `data_export_jobs`：

| 字段 | 语义 |
| --- | --- |
| `id / owner_id` | 稳定作业 ID 与本人归属，使用复合所有者约束 |
| `status` | `queued / running / succeeded / failed / expired` |
| `schema_version` | 当前为 `1`，对应 JSON 和归档合同 |
| `attempt_count / max_attempts` | 最多 3 次；进程崩溃后的租约恢复计入尝试 |
| `available_at / lease_id / lease_until` | 有界领取和双 worker 排他 |
| `snapshot_at` | 成功尝试建立只读一致性快照的服务器时刻 |
| `artifact_ciphertext` | Fernet 加密的 ZIP；只在 `succeeded` 且未过期时存在 |
| `artifact_sha256 / artifact_byte_size` | 明文 ZIP 的完整性摘要和字节数 |
| `filename / expires_at` | 下载文件名及成功后 24 小时到期时刻 |
| `error_code / error_message` | 稳定、可展示的失败原因；不包含正文或原始异常 |
| `created_at / updated_at / finished_at` | 排队、状态变化和终态时刻 |

状态机：

```text
queued → running → succeeded → expired
   ↑        └────→ failed
   └─ stale lease 且未超次数时重新领取
```

- `POST /data-exports` 在用户行锁内检查活动作业，再创建作业和操作重放结果。
- worker 使用 `FOR UPDATE SKIP LOCKED` 领取到期的 `queued` 或租约已失效的 `running` 作业。
- 读取业务数据前续租一次；数据加载完成后关闭只读事务，再在事务外构建 ZIP 和加密。
- 最终写入时同时校验 `id + owner_id + lease_id + running`。晚到 worker 不能覆盖新尝试或终态。
- 可重试异常在剩余尝试内回到 `queued` 并短暂退避；确定性数据/容量/解密错误直接 `failed`。
- 清理以 `FOR UPDATE SKIP LOCKED` 每批最多 100 条清空到期产物；30 天前且无产物的终态元数据
  每批最多 100 条删除。重复执行结果相同。

## 5. 一致性快照

worker 在独立连接中开启 `REPEATABLE READ READ ONLY` 事务，并以事务内第一次查询后的数据库
时间作为 `snapshot_at`。所有分类在同一事务内按稳定主键或业务顺序读取，加载完成后立即提交，
不持有业务行锁。

快照构建遵循：

1. 每条查询都带 `owner_id` 或通过已锁定的本人关联链限制；不接受请求传入 owner。
2. 用户账号行只读取白名单字段。没有 owner 字段的子表必须经拥有者父表连接。
3. JSON 序列化只使用显式字段映射，不对 ORM 对象或数据库表做通用反射导出。
4. 同一分类内按可复现顺序输出；外键 ID 保留，方便用户自行关联。
5. purged 对象仅保留已存在的墓碑字段；空正文仍为空，不从快照、日志或旧操作恢复。
6. 正在运行的 AI、订阅刷新或专注按 `snapshot_at` 的已提交状态导出；晚到结果进入下一次导出。

## 6. 归档与格式合同

ZIP 固定包含：

```text
manifest.json
itime-data.json
csv/projects.csv
csv/tasks.csv
csv/task-steps.csv
csv/task-occurrences.csv
csv/calendar-events.csv
csv/plan-blocks.csv
csv/focus-sessions.csv
csv/difficulties.csv
csv/quota-ledger.csv
calendar/itime.ics
markdown/conversations.md
markdown/reviews.md
markdown/memories.md
README.txt
```

### 6.1 清单与完整 JSON

`manifest.json` 包含 `export_id`、`schema_version`、`snapshot_at`、账号 ID、生成版本、
每个文件的路径、SHA-256、字节数和记录数。`itime-data.json` 顶层按第 3 节分类，
每个数组即使为空也存在。JSON 使用 `ensure_ascii=false`、稳定键排序和两个空格缩进。

ZIP 条目的时间统一为 `snapshot_at`，避免文件系统时间泄露和无意义差异。worker 生成每个条目后
先计算摘要和累计明文字节；任一限制超出时丢弃内存结果并失败，不写半包。

### 6.2 CSV

CSV 使用 UTF-8 BOM、RFC 4180 引号规则和稳定英文列名，避免电子表格误解中文编码。
嵌套值使用 JSON 字符串；以 `= + - @` 开头的文本前加单引号，防止公式注入。
每个文件首行固定表头，即使无记录也存在。CSV 是常用分析视图，不复制全部内部历史表。

### 6.3 ICS

`calendar/itime.ics` 使用 `icalendar` 生成，包含：

- 当前未彻底清理任务的日期/时刻截止与重复规则；
- 手工、文件和截图来源的有效日历系列，并应用取消、移动、覆盖和补课；
- 当前计划版本的计划块；
- 订阅来源保存的 master、detached occurrence、本地覆盖和取消状态。

每个具体事件使用稳定 `UID`、`DTSTAMP=snapshot_at`、原时区或日期值，并通过
`X-ITIME-KIND`、`X-ITIME-SOURCE-ID`、`X-ITIME-ENTITY-ID` 保留来源。被回收、已取消、
历史计划版本、失败候选和未确认提案不进入 ICS。任何源事件无法安全转换时，在
`manifest.json` 写警告和计数，完整原始结构仍保留于 JSON；不能静默把它声称为已导出到 ICS。
标准日/周/月/年重复优先输出 `RRULE/RDATE/EXDATE/RECURRENCE-ID`，课程指定周次输出有限
`RDATE`，避免为长期规则展开无界事件。

### 6.4 Markdown

Markdown 按会话/活动日/记忆分文件，标题文本原样保留并做 Markdown 控制符转义。
消息标注角色、状态和时间；复盘标注报告版本、事实、用户说明、洞察、下一步、信息缺口和批注；
记忆标注类型、来源和回收状态。Markdown 不包含内部提示词、provider 错误体或配额。

## 7. API 合同

所有路由位于 `/api/v1/data-exports`。

| 方法与路由 | 作用 | 主要失败 |
| --- | --- | --- |
| `POST /data-exports` | 创建完整导出或返回当前活动作业 | 未认证、CSRF、操作号冲突 |
| `GET /data-exports?limit=20` | 最近作业及当前真实状态 | 未认证 |
| `GET /data-exports/{id}` | 读取本人单个作业 | 不存在或非本人统一 404 |
| `GET /data-exports/{id}/download` | 解密并下载未过期 ZIP | 未完成、失败、过期、产物不可用 |

创建响应返回 `operation_id`、`reused` 和作业；成功下载返回：

```text
Content-Type: application/zip
Content-Disposition: attachment; filename="itime-export-....zip"
Content-Length: <明文字节>
Digest: sha-256=<base64 digest>
Cache-Control: no-store, private
X-Content-Type-Options: nosniff
```

下载不使用一次性公开 token，不接受 owner ID，不通过 query 参数携带凭据。认证 cookie 已限制
`/api`，普通同源下载由浏览器携带；失效会话必须重新登录。错误继续使用统一
`{code, message, request_id, saved, retryable, details}`，不能返回 ZIP 与 JSON 错误的混合响应。

## 8. Web 界面

账号设置新增“数据管理”，路径 `/account/data`。首版仅显示已实现的导出区域；
注销未实现前不显示无效按钮。

页面结构：

1. 标题和一句说明：完整 JSON 为权威内容，CSV/ICS/Markdown 便于阅读或迁移。
2. “生成完整数据包”按钮。创建后显示真实排队/生成状态，不显示虚假百分比。
3. 活动作业状态包含创建、快照、完成、过期时刻；生成中每 2 秒有界轮询，页面失焦降为 5 秒，
   离页或刷新后从服务端历史恢复。
4. 成功后显示文件大小、到期时间和带下载图标的“下载 ZIP”；下载前再读取一次状态。
5. 失败显示原因、是否保存、请求编号和“重新生成”；过期显示“文件已清理，可重新生成”。
6. 最近历史最多 20 条，桌面为紧凑列表，平板/手机为单列；320px 最大字号下按钮换行但不溢出。
7. 浏览器只持有普通 Blob 下载所需的短时内存，不写 localStorage、IndexedDB 或缓存。

页面关闭不取消导出。账号停用、会话撤销或退出后，轮询与下载按共用认证层失败，不保留旧账号
产物 URL 或自动下载。

## 9. 安全与隐私

- 新增 `ITIME_EXPORT_ENCRYPTION_KEY`。开发和测试可回退基础密钥；生产必须配置与基础、AI、
  日历订阅密钥均不同的 Fernet 密钥。
- 加密密钥、订阅 URL、导出正文、ZIP、SHA 原文、下载响应均不写应用日志。
- API 只返回产物 SHA、大小和状态，不返回密文。下载解密失败统一返回可重试的产物不可用错误。
- 所有跨账号 ID 使用统一 404，测试用户 A 不能列表、查看或下载 B 的作业。
- CSV 防公式注入，ZIP 条目路径固定且无用户输入，Markdown 转义结构字符，ICS 由结构化库生成。
- 导出 worker 不执行包内文本，不访问用户链接或订阅源，不触发 AI，也不解密平台 AI Key。
- HTTP 响应禁止缓存；ZIP 内 `README.txt` 提醒文件可能包含敏感个人信息，应由用户妥善保存。

## 10. 性能、并发与恢复

- 每类数据使用有界批次读取或 SQLAlchemy 流式标量，避免按每个父对象发 N+1 查询。
- worker 同时只处理一个导出；多个进程依靠 `SKIP LOCKED` 分担账号。账号级活动唯一索引防止
  同一账号重复占用内存。
- 快照事务只负责读取并尽快释放连接；压缩、摘要和加密在线程中执行，不阻塞 asyncio 循环。
- 生成期间每 30 秒续租；租约丢失后不提交产物。进程崩溃后下一 worker 重新读取完整快照，
  不复用可能不完整的内存文件。
- API 列表只读元数据，不读取大字段；下载单次读取一个本人密文，解密后立即返回并释放引用。
- 清理失败不影响业务数据，只延迟导出产物删除并记录无正文的错误类型；下轮继续重试。
- M8 使用长历史样本记录快照读取、压缩、加密、下载延迟和峰值内存，再决定对象存储迁移。

## 11. 验证与完成标准

服务端真实 PostgreSQL/Uvicorn/worker 覆盖：

- 迁移升级/回退、状态约束、账号级活动唯一、成功产物与级联删除。
- 同一操作重放、不同内容冲突、重复点击复用活动作业、双 worker 单领取和失效租约恢复。
- `REPEATABLE READ` 快照期间并发写入不混入同一包，下次导出可见。
- 两个账号数据隔离；越权列表/详情/下载统一不可见。
- 每个第 3 节分类至少有一条数据，JSON 记录数与数据库快照一致。
- ZIP 文件清单、逐文件 SHA、UTF-8/BOM、CSV 公式注入、ICS 解析和 Markdown 转义。
- 密码/令牌/密钥/内部日志关键字段不出现在解压后的任何文件。
- 订阅 URL 正确导出但不出现在 API 元数据或日志；错误密文使整个作业失败。
- 容量超限、压缩/加密异常、worker 崩溃、租约丢失、产物过期、并发清理和重复清理。
- 下载头、摘要、文件名、未完成/失败/过期、会话撤销和跨账号行为。

Web 生产构建和 Chromium 覆盖：

- 真实账号创建多类业务数据，页面创建作业，独立 worker 完成后下载 ZIP 并解析核对。
- 刷新/离页恢复、活动作业复用、失败重试、过期重新生成和下载认证失效。

# iTime 日历生命周期设计

更新：2026-10-04。本设计在 `REQ-DATA-01` 的 30 天回收站、`REQ-CAL-01/02/03`
的日历与外部来源规则，以及既有任务、困难和长期记忆生命周期模式之上，冻结日历系列与
ICS 订阅源的删除、恢复和到期清理合同。迁移 `0034_calendar_lifecycle`、服务端领域/API、
独立清理 worker、统一 Web 回收站和真实浏览器测试已于 2026-10-04 完成；本文同时记录实际
边界，不代表学期、项目、AI 会话等其他对象已经开放回收。

本模块采用可演进工程默认：只有用户可独立管理的日历聚合根进入回收站；学期、节次、单次
例外、补课和来源事件仍作为聚合内部数据管理；已经发生的计划、执行和复盘快照不因源对象
删除而改写。AI 技术正文和质量样本继续遵守各自 7 天、30 天期限，不因单项删除扩大即时清理
范围。

## 1. 范围与非目标

### 1.1 本模块覆盖

1. 手工创建、XLSX/ICS 文件导入和截图识别确认产生的 `CalendarSeries`。
2. 用户创建的 ICS 订阅聚合，即 `CalendarSource(kind=ics_subscription)` 及对应
   `CalendarSubscription`。
3. 两类对象的本人删除、30 天回收、恢复、到期脱敏、旧操作阻断、同步失效事件、数据导出和
   Web 可达入口。
4. 删除与订阅刷新租约、规划输入修订、已确认计划来源冲突和账号注销之间的事务边界。

### 1.2 本模块不覆盖

- `AcademicTerm` 和 `TermPeriod` 是课程时间配置，不新增独立删除入口。已有课程引用学期时继续
 允许编辑学期；后续若提供学期归档，应作为独立功能设计。
- 日历单次取消、移动、内容覆盖、补课取消和订阅单次例外继续使用现有可逆操作，不进入独立
 回收站。
- 导入批次、候选、订阅刷新记录属于来源处理历史，不单独展示“删除”；它们随所属系列或
 订阅源到期清理时按本设计脱敏。
- 已确认计划版本、专注事实、复盘报告和统计不是日历对象的级联删除目标。它们继续保留当时
 的不可变快照或按各自现行口径计算。
- 不新增“立即彻底删除”。回收期结束前只能恢复；账号注销仍走独立的 7 天全账号清理流程。
- 不在本模块实现 AI 会话、项目或其他独立内容对象的回收，它们后续分别设计和提交。

## 2. 方案选择

采用聚合根自带生命周期字段和模块专属清理进程：

- `CalendarSeries` 和 `CalendarSource` 分别保存 `deleted_at`、`purge_after`、`purged_at`。
- 正常读取必须显式过滤生命周期；回收站读取只返回未到期且尚未清理的对象。
- 到期清理由 `itime.calendar.cleanup_worker` 有界领取并在事务中脱敏。
- 既有外键和对象 ID 继续作为墓碑，阻止旧客户端、旧导入候选或迟到 worker 复活内容。

未采用以下方案：

1. **通用回收站索引表**：它只能记录“某 ID 已删除”，无法通过数据库约束保证日历展开、
   订阅刷新、规划快照和导入确认都执行同一过滤规则。
2. **直接物理删除并保存审计行**：系列拆分前序、导入身份和计划来源冲突仍引用原对象，直接
   删除会扩大级联范围，也无法可靠拒绝旧操作。
3. **将暂停或单次取消当作删除**：暂停仍需保留并展示现有订阅内容，单次取消只影响一个
   occurrence，均不等同于整个聚合进入回收站。

## 3. 生命周期状态

### 3.1 日历系列

| 状态 | 字段 | 普通日历 | 可执行动作 |
| --- | --- | --- | --- |
| `active` | 三个生命周期字段均为空 | 展开并参与冲突和规划输入 | 查看、编辑、拆分、单次修改、删除 |
| `trashed` | `deleted_at/purge_after` 非空，`purged_at` 为空 | 不展开、不参与冲突和规划输入 | 回收站只读查看、恢复 |
| `purged` | `purged_at` 非空 | 不展开 | 不可恢复，只返回已清理状态 |

删除不改变系列原有 `kind`、来源、重复规则、单次例外或补课，因而 30 天内恢复后可恢复原
行为。恢复不制造新 ID，不重置版本，也不重建已存在的计划或复盘记录。

### 3.2 ICS 订阅源

订阅的 `active/paused` 继续表示网络刷新状态；来源的 `active/trashed/purged` 表示数据生命周期。
两者正交：

- 来源 `active` 且订阅 `active`：按现有周期刷新。
- 来源 `active` 且订阅 `paused`：不刷新，但正常展示已保存来源事件。
- 来源 `trashed`：无论订阅原状态为何，都不刷新、不投影到普通日历，只在回收站显示。
- 来源恢复：保留删除前的订阅 `active/paused`。原为 `active` 时立即排队一次刷新；原为
  `paused` 时仍保持暂停。
- 来源 `purged`：URL、来源正文和事件正文已经清除，不可恢复。

删除和恢复均增加来源版本与订阅状态版本。删除时间固定为服务端 UTC 时刻，
`purge_after = deleted_at + 30 * 24h`，不使用活动日，也不随用户时区变化。

## 4. 数据模型与约束

### 4.1 `calendar_series`

新增：

- `deleted_at timestamptz null`
- `purge_after timestamptz null`
- `purged_at timestamptz null`
- 生命周期一致性检查约束
- `(owner_id, deleted_at, updated_at, id)` 列表索引
- `(purge_after, id) WHERE deleted_at IS NOT NULL AND purged_at IS NULL` 清理索引

`series_result` 新增 `lifecycle`、三个时间字段和 `days_until_purge`。已清理对象只返回稳定 ID、
版本、删除/清理时间和 `lifecycle=purged`，不返回可恢复正文。

### 4.2 `calendar_sources`

新增同样三个生命周期字段、检查约束和索引。首版只有 `kind=ics_subscription` 的来源开放删除
和恢复；文件、截图来源由关联系列的生命周期管理，不能通过通用来源 API 越权删除。

`CalendarSubscription.lifecycle_status` 仍只允许 `active/paused`。删除来源时保留该值，用于恢复
后恢复原刷新意图；worker 必须连接 `CalendarSource` 并要求来源处于 `active` 生命周期。

### 4.3 墓碑和直接明细

系列到期清理后：

- 清除名称、说明、地点、日期、时刻、时区、课程周次、重复参数、学期和来源引用；
- 删除该系列的单次例外与补课；
- 清除指向该系列的导入候选正文及外部 UID，删除可重建的导入身份映射；
- 保留系列 ID、所有者、版本、删除/清理时间和必要的前序标识；
- 采用固定非个人占位值满足非空及重复规则约束。

订阅源到期清理后：

- 清除来源名称、加密 URL、展示 URL/主机、最终 URL、ETag、Last-Modified、错误正文和内容摘要；
- 删除来源事件、字段覆盖、单次例外及刷新明细；
- 将订阅置为不运行的稳定状态并清除租约；
- 已解决的计划来源冲突记录和计划快照可继续保留当时的时间变化及计划块关联；来源名称在
  清理后统一显示非个人占位值；
- 保留来源 ID、所有者、类型、版本、删除/清理时间及不含原 URL 的墓碑。

所有包含对象 ID 的 `UserOperation.response` 在到期清理前清空并记录
`response_purged_at`，避免旧操作重放返回已清理正文。

## 5. API 合同

### 5.1 日历系列

| 接口 | 输入 | 输出与边界 |
| --- | --- | --- |
| `GET /api/v1/calendar/series?lifecycle=active|trashed` | 现有筛选、游标 | 默认仅活动对象；回收站稳定分页 |
| `DELETE /api/v1/calendar/series/{id}` | `operation_id`、`expected_version` | 移入回收站，返回只读对象 |
| `POST /api/v1/calendar/series/{id}/restore` | `operation_id`、`expected_version` | 原 ID 恢复并重新进入日历 |
| `GET /api/v1/calendar/series/{id}` | 对象 ID | 活动或未清理回收对象；已清理返回 410 |

来源为 `subscription` 的 occurrence 不允许经系列接口删除；客户端必须操作订阅源。回收对象的
编辑、拆分、例外、补课和冲突计算返回 409，并给出当前生命周期与版本。

### 5.2 ICS 订阅

| 接口 | 输入 | 输出与边界 |
| --- | --- | --- |
| `GET /api/v1/calendar/subscriptions?lifecycle=active|trashed` | 生命周期 | 默认活动/暂停；回收站返回完整可恢复聚合 |
| `DELETE /api/v1/calendar/subscriptions/{source_id}` | `operation_id`、`expected_version` | 停止在途刷新并移入回收站 |
| `POST /api/v1/calendar/subscriptions/{source_id}/restore` | `operation_id`、`expected_version` | 恢复原刷新意图并按需排队 |
| `GET /api/v1/calendar/subscriptions/{source_id}` | 来源 ID | 活动或未清理回收对象；已清理返回 410 |

回收中的订阅拒绝更新、刷新、暂停/恢复、字段覆盖和单次例外。创建相同 URL 时若存在未清理
回收来源，返回 409 并给出可恢复来源 ID，避免以新聚合绕过回收状态；到期清理后允许用户明确
创建新订阅。

### 5.3 错误与幂等

- 跨账号对象统一返回 404，不暴露存在性。
- 版本不匹配返回 409 和服务端当前版本；客户端保留当前页面状态。
- 已在回收站重复删除使用相同操作 ID 返回原响应；新操作 ID 返回当前状态但不延长 30 天。
- 活动对象重复恢复返回 409；已清理对象删除或恢复返回 410。
- 数据库提交结果未知时返回 `saved=unknown`，客户端使用原 `operation_id` 对账。
- 所有写接口继续要求本人会话、CSRF、账号可写状态和现有输入上限。

## 6. 删除、恢复与并发

### 6.1 删除事务

日历系列删除事务：

1. 读取操作重放记录并锁定本人系列。
2. 校验版本和当前生命周期。
3. 写入删除及到期时间，增加版本。
4. 由既有数据库触发器增加规划输入修订，使旧规划提案无法确认。
5. 写入 `calendar_series/deleted` 同步失效事件和幂等响应。

订阅删除事务：

1. 按来源、订阅、当前刷新记录、开放计划来源冲突的固定顺序加锁。
2. 使运行中的刷新记录转为 `stale`，清空租约并推进 `fetch_revision`，令迟到结果无权提交。
3. 写入来源删除时间和版本；订阅刷新状态转为 `idle`，但保留原 `active/paused` 意图。
4. 将该来源现有开放计划冲突标记为 `resolved/superseded`。
5. 增加规划输入修订并写入 `calendar_source/deleted` 同步事件及幂等响应。

删除后普通日历立即隐藏该对象的全部 occurrence。已经确认的计划、执行和复盘仍显示保存时的
快照，不伪装成这些历史从未发生。

### 6.2 恢复事务

恢复沿用同一锁顺序，要求 `purged_at IS NULL` 且当前时间早于 `purge_after`。恢复清空
`deleted_at/purge_after`、增加版本和规划输入修订，并写入 `restored` 同步事件。

订阅原为活动时，恢复事务将其置为 `queued`、清除旧错误并安排立即刷新。恢复提交前根据已保存
来源事件和当前计划生成来源恢复差异；若新增的固定占用与当前计划块重叠，创建新的开放冲突，
但不改写计划。后台刷新随后产生的新一代差异继续走既有冲突流程。

### 6.3 迟到与旧操作

- 删除前已领取的订阅 worker 必须因来源生命周期、`fetch_revision` 或租约失配而放弃提交。
- 删除前生成但尚未确认的导入候选或规划提案必须因系列生命周期或规划输入修订变化而失败，
 不能创建或引用已删内容。
- 同步客户端收到删除事件后清除普通列表缓存；离线写操作重放时由权威 API 返回生命周期冲突，
不能执行最后写入覆盖。
- 账号注销优先于本模块。注销中账号的清理 worker 不领取对象；账号到期删除仍通过用户根行
级联清理全部日历墓碑。

## 7. 查询、导出与派生数据

- 普通系列列表、日历 occurrence、冲突检查、规划输入、复盘事实和 AI 相关上下文只读取
  `active` 系列及来源。
- 回收站查询不展开全部 recurrence，只返回聚合摘要和删除期限；打开详情时按本人权限读取完整
 仍可恢复内容。
- 完整 JSON 导出包含未清理回收对象及生命周期字段；分类 ICS 只导出活动安排，Markdown/CSV
 对回收对象使用独立“回收站”分类。已清理墓碑不导出正文。
- 删除不修改既有计划版本、规划输入快照、专注记录、复盘报告或计划来源冲突中的不可变快照。
- 统计继续按当前有效任务、计划和专注事实计算；日历回收本身不新增效率或完成指标。
- AI 正文日志和质量样本不建立新的日历对象外键，继续按既有期限清理；账号注销仍立即优先
 清除。

## 8. Web 交互

### 8.1 日历系列

活动日历 occurrence 详情为可编辑系列增加“移到回收站”命令和明确确认。删除成功后关闭详情，
保留当前日期范围并显示“未改写已有计划”的说明。

现有 `CalendarNavigation` 的“日历管理”区新增带 `Trash2` 图标的“日历回收站”按钮，打开独立
`CalendarTrashDialog`；不新增顶层产品导航或路由。对话框按删除时间倒序同时列出：

- 课程或固定安排：名称、原日期范围、重复摘要、来源、清理时间；
- ICS 订阅：名称、脱敏来源主机、原刷新状态、事件数量、清理时间。

回收站详情只读，只提供恢复。不存在“永久删除”按钮。恢复成功后回到普通日历或订阅详情；
发生版本冲突时保留当前详情并允许采用服务器状态后重试。

### 8.2 订阅管理

订阅管理使用“使用中 / 回收站”分段控件。暂停与删除使用不同文字：

- 暂停：停止刷新，现有日历内容继续显示。
- 删除：移入回收站，立即从普通日历隐藏，30 天内可恢复。

删除对话框显示待同步操作数量和在途刷新状态；提交中不能关闭或重复点击。恢复后若触发刷新，
页面显示真实 `queued/running/error` 状态，不显示虚假成功。

### 8.3 响应式与可访问性

沿用现有日历对话框和无嵌套卡片结构。命令使用 Lucide 图标、可访问名称和 tooltip；状态不只
依赖颜色。桌面、平板、手机和 320×700 最大字号下，名称、URL 主机、删除时间、请求编号和操作
按钮必须自然换行且无根级横向滚动。键盘焦点在确认框关闭后回到触发按钮，恢复成功后移到状态
提示。

## 9. 清理进程

`python -m itime.calendar.cleanup_worker` 同时处理到期系列和订阅来源：

1. 每类每批最多 100 条，按 `purge_after, id` 排序并使用 `FOR UPDATE SKIP LOCKED`。
2. 单个聚合在一个数据库事务中清理；任何一步失败整项回滚，其他聚合可在后续批次继续。
3. 先失效操作响应和在途工作，再清理直接明细，最后写墓碑字段和 `purged` 同步事件。
4. 已清理对象重复领取不产生变化；多个 worker 不能重复清理或漏清理。
5. 支持常驻轮询及 `--once`，就绪、关闭信号、数据库超时和错误日志沿用现有清理 worker 模式。
6. 日志只记录对象类型、ID、计数和请求/批次标识，不记录名称、URL、地点或正文。

## 10. 测试与验收

### 10.1 数据库与服务

- 迁移升级、降级保护、生命周期检查约束、部分索引和规划输入触发器。
- 系列及订阅的本人权限、CSRF、版本冲突、操作重放、同操作 ID 异内容、重复删除和恢复边界。
- 活动/回收/已清理列表过滤；普通读取和所有写入口对回收对象的统一阻断。
- 手工、文件导入、截图来源系列；单次、重复、跨日、课程节次、拆分前序、例外和补课。
- 订阅活动/暂停删除、运行租约失效、迟到结果、双 worker、恢复排队、相同 URL 和来源更新竞态。
- 删除和恢复使规划提案过期；订阅恢复后的当前计划重叠只生成冲突，不自动重排。
- occurrence、冲突、规划、复盘和 AI 上下文过滤；不可变计划/复盘快照不被改写。
- 同步删除/恢复/清理事件、旧离线操作阻断、游标过期重建和跨账号隔离。
- 导出中的活动、回收和墓碑分类；订阅 URL 仅在未清理的本人 JSON 中出现。
- 到期清理的正文、URL、导入候选、操作响应和直接明细脱敏；账号注销与本 worker 竞争。
- 两个清理进程并行、事务中途异常完整回滚、再次执行幂等。

### 10.2 浏览器

使用真实 PostgreSQL、API、订阅 worker、受控 ICS 上游和生产构建预览：

1. 创建手工重复安排，删除后从日历消失，在回收站查看并恢复，原单次例外和补课重新出现。

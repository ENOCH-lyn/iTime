# iTime 时间、课表与重复规则设计

版本：0.2；更新：2026-10-02。本文冻结 M3 后续实现所需的时间、课表、固定安排、重复系列和导入语义。用户已明确默认采用用户正在使用的时区，并授权对非安全、费用及不可逆删除类细节采用合理产品默认；以下其余取舍标为“已采纳（工程）”，后续明确需求可通过迁移和版本化接口调整。

## 1. 方案选择

评估过三种重复事件实现：

1. **结构化重复规则，按查询区间展开，单次例外独立保存（采用）**：领域约束清晰，不创建无限未来数据，适合课表周次、单双周和系列修改；查询需要严格限制日期范围。
2. 预生成未来实例：读取简单，但滚动生成、规则修改、时区变化和来源刷新会制造大量修订及清理事务。
3. 只保存 RFC 5545 RRULE 字符串：导入兼容直接，但业务校验、中文编辑器和课程周次语义会依赖不透明字符串。

采用第一种。外部 ICS 的原始规则作为来源快照保留，确认入库时转换成结构化规则；无法无损表达的规则必须保留警告，不静默简化。

## 2. 时间语义

### 2.1 用户时区

- 用户时间设置保存 IANA 时区名，例如 `Asia/Shanghai`，由浏览器 `Intl.DateTimeFormat().resolvedOptions().timeZone` 初始化。
- 新注册请求可携带浏览器时区；历史账号首次进入业务页面时补写。客户端缺失或值无效时暂用 `UTC` 并要求后续设置，不根据 IP 猜测。
- 用户修改时区只改变显示和新建内容的默认时区，不改写已有定时事件代表的 UTC 时间点；事件保留创建时使用的时区。
- 全天事件和日期型截止保存为日历日期，不随显示时区移动到前后一天。日期型截止以该日期次日 `00:00` 的排他边界判断逾期，界面表达为“当天结束前”。
- 每周从周一开始。活动日仍按用户当前时区的 `04:00` 切换；日历事件不因活动日边界改变日期。

### 2.2 本地时间与夏令时

- 非重复定时事件同时保存 UTC 起止时间和创建时区；接口返回两者。
- 重复系列保存本地日期、墙上时刻和 IANA 时区，每次展开时计算 UTC 时间，保证“每周一 09:00”在夏令时变化后仍是当地 09:00。
- 当本地时刻不存在时，该次 occurrence 返回 `invalid_local_time` 警告且不自动平移。
- 当本地时刻重复时，创建或修改请求必须携带明确 UTC offset；缺失时返回可恢复的校验错误及两个候选时间点。
- 时间区间采用半开区间 `[start, end)`；首尾相接不算冲突，结束必须晚于开始。跨午夜通过结束日期偏移表达，不使用负时长。

## 3. 领域模型

### 3.1 用户时间设置

`UserTimeSettings` 与用户一一对应：

- `time_zone`：IANA 时区。
- `week_starts_on=1`：ISO 周一，首版固定但保留字段。
- `activity_day_start_minute=240`：04:00，首版固定。
- `version`、创建/更新时间。

更新使用乐观版本和 `operation_id`。服务端校验时区数据库，不信任设备当前时间。

### 3.2 学期与节次

`AcademicTerm`：

- 名称、开始/结束日期、第一周周一日期、默认时区、版本。
- 日期范围最多 400 天，第一周周一可早于学期开始但最多 6 天。
- 同一账号允许多个学期日期重叠，列表明确显示；不擅自删除历史学期。

`TermPeriod`：

- 隶属学期的节次编号、显示名称、本地开始/结束时间。
- 一个学期最多 30 节；编号和名称在学期内唯一。
- 一次请求提交完整节次表并原子替换；任何非法或重叠节次使整次请求不保存。

### 3.3 固定安排系列

`CalendarSeries`：

- 类型：`course` 或 `fixed`。
- 名称、说明、地点、是否占用时间。
- 所属来源、可选学期、时区、起止本地日期和时刻、跨日偏移。
- 重复规则、版本、创建/更新时间。

课程系列必须关联学期，可使用节次或显式时刻，并保存星期与有效周次。固定安排可以是不重复事件，也可使用通用重复规则。

通用重复规则支持：

- 不重复；
- 每日或每 N 日；
- 工作日；
- 每周或每 N 周的指定星期；
- 每月指定日期；
- 每年指定月日；
- 按结束日期或次数结束。

单个系列最多展开 366 次；日历查询跨度最多 93 天、最多返回 2000 个 occurrence。超过限制要求缩小范围，不截断后伪装成完整结果。

### 3.4 单次例外与补课

`CalendarException` 以系列和原始 occurrence key 唯一定位，动作包括：

- `cancelled`：仅取消本次；
- `moved`：本次移动到新时间；
- `overridden`：本次覆盖名称、说明、地点或占用属性。

编辑入口提供“仅本次 / 本次及以后 / 整个系列”。“本次及以后”通过截断旧系列并新建唯一直接继任系列实现，二者在同一事务提交；已发生的 occurrence 不改写。

`CalendarAddition` 保存关联原 occurrence 的一次性补课，与 `CalendarException` 分离，因此“原课取消”和“另建补课”可以同时存在：

- 一个原 occurrence 最多关联一个补课；需要多段额外安排时创建普通固定安排。
- 补课保存独立本地日期、墙上时刻和 IANA 时区；创建未显式指定时区时采用用户当前设置，后续更新省略时区则保持原值。
- 补课可覆盖名称、说明、地点和占用状态；取消后保留记录及投影但不参与冲突，可再次恢复。
- occurrence 查询、2000 条上限和冲突计算同时覆盖基础实例、例外与补课；同系列补课与原课重叠也明确返回冲突。
- 系列整体修改不得使补课来源孤立；系列拆分按来源日期迁移未来补课，保留补课 ID、来源、时区并递增版本。

## 4. 冲突与状态

- 固定安排允许时间重叠，但写入响应返回冲突对象及相交区间；界面必须明确提示，不能静默丢弃任一事件。
- 课程取消保留 exception 和历史；取消不等于删除系列。
- 当前阶段不提供硬删除。后续删除进入 30 天回收站，并以墓碑阻止旧客户端或导入任务复活。
- 每个系列、学期和时间设置使用版本；所有写请求携带 `operation_id`。同编号同内容返回原结果，同编号不同内容拒绝。
- occurrence 是查询投影，不单独作为权威实体；完成、计划或执行需要引用 `series_id + occurrence_key` 及当时版本。

## 5. 导入与订阅

导入采用“上传/读取 → 候选校对 → 选择确认 → 事务应用”：

- 截图、Excel、ICS 文件和 ICS 订阅共用候选记录格式；原媒体不直接成为日历事件。
- 部分识别成功时展示全部可判断候选，用户可只确认有效行；无效行保留原因。
- 精确重复按账号、来源和外部 UID/recurrence-id 去重；无外部 ID 时使用规范化内容指纹。疑似重复只警告，由用户选择。
- 时间冲突允许确认并保留双方，同时返回冲突；不会因冲突自动覆盖、平移或删除固定安排。
- ICS 文件允许选择部分事件。订阅为只读来源，不写回外部系统。
- 订阅刷新失败保留上次成功数据和时间；来源删除的过去 occurrence 保留，未来 occurrence 标记为来源取消。
- 用户本地例外优先于后续订阅刷新；来源字段变化与本地覆盖同时存在时显示差异，用户可重置为来源值。
- 原图在确认后删除，未确认原图 24 小时清理；结构化候选和已确认事件按各自生命周期保存。

## 6. API 边界

第一批服务按以下边界拆分，避免一个提交同时混入文件解析和外部网络：

1. 时间设置、学期、节次、手工课程/固定安排、例外与 occurrence 查询。
2. Excel 模板、Excel/ICS 文件解析及候选确认。
3. 截图识别作业、原媒体清理。
4. ICS 订阅抓取、刷新、来源差异和计划冲突标记。
5. 任务截止、重复模板、系列修改和拆分参数。

基础路由：

- `GET/PUT /api/v1/time-settings`
- `POST/GET/PUT /api/v1/terms`
- `PUT /api/v1/terms/{id}/periods`
- `POST/GET/PUT /api/v1/calendar/series`
- `POST/PUT /api/v1/calendar/series/{id}/exceptions`
- `GET /api/v1/calendar/occurrences?start=...&end=...`

所有读取按账号隔离。不存在和他人对象统一返回 404；陈旧版本返回当前版本；无效本地时间、范围过大、无效周次和节次重叠分别返回稳定错误码。数据库故障延续 `saved=unknown`，客户端保留同一请求内容和操作编号重试。

## 7. 验证要求

- 单元边界：闰年、月末、跨午夜、周一边界、03:59/04:00、无效 IANA 时区、夏令时缺失/重复时刻。
- 集成：所有权、幂等、版本冲突、学期/节次原子更新、单双周和指定周展开、取消/调课/补课、重叠冲突保留、范围与容量上限。
- 并发：同版本系列编辑只能一个成功；“本次及以后”拆分原子；重复确认不生成重复系列或例外。
- UI：手工建学期和课程、周/月查看、冲突解释、失败恢复、三视口、320px 大字号、键盘、axe、控制台及截图人工检查。
- 导入：真实 XLSX/ICS 文件、错误文件、部分确认、重复导入、订阅更新/取消/超时，以及原媒体清理证据。

## 8. 非本批范围

第一批不调用 OCR 或外部订阅，不实现计划自动重排，也不删除任务或事件。它们分别在后续独立模块中实现，但必须复用本文的时间、来源、版本和 occurrence 标识，不建立第二套冲突语义。

## 9. 已实现基础合同

迁移 `0006_time_terms` 和 `server/src/itime/calendar/` 已实现第一批中的时间设置、学期与节次：

- 注册请求可选传入 `time_zone`；只有新账号创建成功时才保存，经 IANA 数据库校验。未传入的历史或新账号读取时间设置时得到 `initialized=false`、`time_zone=null` 和 `version=0`，不以服务器 UTC 冒充用户设置。
- `PUT /api/v1/time-settings` 以 `expected_version=0` 初始化，后续按当前版本更新；周起点和活动日边界首版固定为周一及 04:00。
- `POST /api/v1/terms` 在未显式给出时区时继承已保存的用户时区；`GET /api/v1/terms` 使用更新时间和 ID 的稳定游标；`GET/PUT /api/v1/terms/{id}` 返回本人学期详情。
- `PUT /api/v1/terms/{id}/periods` 接收完整节次表和学期版本。空列表可清空，最多 30 节；编号、大小写归一后的名称、时段和重叠任一非法时整批不保存；相邻端点允许。
- 时间设置和学期变更写入 `change_events`；所有上述 PUT/POST 写入复用 `user_operations`，同操作号同内容重放原结果，不同内容返回冲突。学期和节次作为同一版本聚合，节次变化递增学期版本。

课程/固定安排与 occurrence 查询的实际合同见下一节；单次例外和系列拆分仍继续按第 3、4、6 节合同推进。

## 10. 已实现系列与 occurrence 合同

迁移 `0007_calendar_series` 和 `server/src/itime/calendar/{recurrence,time_math,series_service}.py` 已实现：

- `POST/GET/PUT /api/v1/calendar/series` 提供手工课程和固定安排系列；课程按学期周一锚点、星期和有效周次生成，使用节次时把当时的连续节次起止时刻保存为系列快照，后续节次表修改不会静默移动既有课程。
- 固定安排支持不重复、每日或每 N 日、工作日、每周或每 N 周指定星期、每月指定日期及每年指定月日。重复系列必须以结束日期或次数结束；无效月末和非闰年 2 月 29 日跳过，不挪到月末。
- 单系列最多 366 次；`GET /api/v1/calendar/occurrences` 使用用户当前时区解释 `[start,end)` 日期范围，跨度最多 93 天、结果最多 2000 条。跨午夜事件只要与范围相交就返回。
- 墙上时间通过本地时间→UTC→本地时间往返校验。非重复事件落在 DST 缺失时刻时拒绝；重复系列保留该次并返回 `invalid_local_time` 警告。重复时刻要求请求提交候选之一的 UTC offset，不默认选择。
- 占用时间的系列允许重叠；创建和编辑响应返回最多 100 项冲突及 `has_more`，日历查询在 occurrence 上双向标出冲突。首尾相接不视为冲突，不占用时间的安排不参与冲突。
- 系列写入使用 `operation_id`、乐观版本和 `change_events`；读取、学期/节次引用及列表筛选均按账号隔离。

迁移回退会同步删除该版本的系列变更事件和幂等结果，避免再次升级后重放已被回退删除的对象。

## 11. 已实现例外与拆分合同

迁移 `0008_calendar_exceptions` 与 `0010_calendar_additions` 已实现取消、调课、内容覆盖和系列拆分：

- 一个系列日期最多有一个例外。例外保存创建时的 `occurrence_key` 和原始日期；整个系列修改显示时刻后仍按原始日期应用，不因 key 文本变化失联。
- 取消保留 occurrence 并标记 `status=cancelled`，不参与占用冲突；调课保留原始标识并替换本地起止时间，且固化调课时区；内容覆盖只改变明确提交的名称、说明、地点或占用属性。
- `GET/POST /api/v1/calendar/series/{id}/exceptions` 和 `PUT /api/v1/calendar/series/{id}/exceptions/{exception_id}` 使用系列聚合版本与例外自身版本。每次实际例外变化同时递增系列版本并写入两类变更事件。
- `POST /api/v1/calendar/series/{id}/split` 实现“本次及以后”：同一事务截断旧系列、建立带 `predecessor_id` 的继任系列，并把分界点及之后仍有效的例外迁移到继任系列。首个实例要求改整个系列；新规则会使未来例外孤立时整笔拒绝。
- 调课后的时段参与冲突检查；从原日期移出的 occurrence 不会继续占用旧时段，移动到查询范围内的历史实例仍能被检索。

当前不提供例外或系列硬删除；后续回收站沿用第 4 节的墓碑和 30 天恢复规则。

## 12. 已实现任务日期与重复合同

迁移 `0009_task_schedules` 以 `TaskSchedule` 保存任务截止、重复、可拆和最小连续块，以稀疏 `TaskOccurrenceState` 保存被操作实例：

- 日期型截止不生成伪 UTC 截止点，逾期边界按任务保存时区的次日当地午夜计算；定时截止保存当地日期/时刻和 UTC 时间点。任务时区在创建后不随用户显示时区变化。
- 未操作的重复实例按规则投影；完成、跳过、调期和补做才创建状态行。重复模板不使用 `Task.status` 表示全部实例完成，旧单项/批量完成入口会拒绝重复模板。
- 状态行保存步骤总数快照和已完成步骤 ID。产生实例状态后禁止增删模板步骤，但仍允许改名、排序；保持完成状态修改步骤进度不会改写首次 `completed_at`。
- `PUT /api/v1/tasks/{id}/schedule` 表示“全部”；`PUT .../occurrences/status` 和 `PUT .../occurrences/schedule` 表示“仅本次”；`POST .../schedule/split` 表示“本次及以后”。补做使用 `POST .../occurrences/makeup`，保留来源 occurrence。
- 拆分复制任务正文、项目、估时、优先级、步骤、链接和标签，迁移未来状态并重映射步骤 ID。已到期实例不可拆分；一个前序任务最多一个直接后继。

日历与任务的 93 天查询均先按持久化起止边界缩小候选，再应用移入范围的例外/调期记录；返回上限仍为 2000，不以截断结果冒充完整结果。

## 13. 已实现补课 occurrence 合同

迁移 `0010_calendar_additions` 和 `addition_service.py` 已实现独立补课：

- `GET/POST /api/v1/calendar/series/{id}/additions` 及 `PUT /api/v1/calendar/series/{id}/additions/{addition_id}` 提供本人列表、创建、取消、恢复、改时段和内容覆盖。
- 创建先验证来源 occurrence 确实属于系列；取消原课不妨碍关联补课创建。每个来源日期最多一个补课，重复创建返回现有补课 ID。
- 补课使用独立 occurrence key、版本和同步事件，实际变化同时递增系列版本；无变化更新不增版。所有写入继续使用 `operation_id` 重放和账号级写锁。
- 查询会补入实际日期落入范围但原系列已远离范围的补课；补课与基础 occurrence、调课及其他系列统一计算冲突，取消或不占用的补课不参与。
- 系列规则缩短会先执行来源孤儿检查；“本次及以后”拆分迁移分界点及之后来源的补课。同一前序系列最多一个直接后继，防止顺序重复拆分形成分叉。
- `0010` 在存在补课数据，或调课时区已不同于系列时区时拒绝降级，避免静默删除或改变时间点；满足无损条件后可回退并重新升级。迁移同时把已有调课记录回填为原系列时区，并补齐重复规则数据库约束。

## 14. 已实现课表与统一日历界面

`web/src/pages/CalendarPage.vue` 及 `web/src/components/Calendar*.vue` 已接入本设计的手工课表和 occurrence 合同：

- `/calendar` 并行查询固定安排和任务 occurrence。用户当前 IANA 时区决定查询日期范围和定时内容的显示日期/时刻，日期型任务保持原业务日期；系列及例外仍保留各自保存时区。
- 桌面显示周/月网格和实例详情栏；840px 以下显示日期议程并把详情切换为单栏，返回后恢复到原事件焦点。
- 学期/节次、课程/固定安排、系列整体、单次例外、关联补课和未来拆分均有可到达表单。DST 缺失时刻保留填写并提示修改，重复时刻展示服务端候选 UTC 偏移供用户明确选择。

## 15. 已实现 Excel 与 ICS 文件导入服务

迁移 `0011_calendar_file_imports` 和 `server/src/itime/calendar/import_*.py` 已实现文件导入的服务端候选流程：

- `GET /api/v1/calendar/imports/template.xlsx` 生成可直接填写的真实 XLSX 模板；`POST /api/v1/calendar/imports/files` 接收原始 `.xlsx` 或 `.ics` 文件正文。原文件仅在请求内存中受限解析，不写数据库或公共目录；XLSX 上限 5 MiB，ICS 上限 2 MiB，单批最多 500 个候选。
- XLSX 只接受标准模板工作表、已知列和最终值，拒绝公式、宏、嵌入对象、外部关系、异常压缩比、超大解压内容及稀疏超范围工作表。课程行可按本人已有学期名称、星期、周次及连续节次校对；固定安排支持现有六类结构化重复。
- ICS 使用 RFC 5545 类型解析，支持 UTC、IANA `TZID`、浮动时间提示、全天单日、`DTEND`/`DURATION` 及可无损映射的 DAILY/WEEKLY/MONTHLY/YEARLY 规则。复杂 `BY*`、EXDATE/RDATE、无限重复、自定义未知时区和 `RECURRENCE-ID` 覆盖保留为无效候选，不静默简化；跨夏令时的 `DURATION` 按真实 UTC 时长计算后再投影为墙上时间。
- `CalendarSource` 保存来源元数据，`CalendarImportBatch` 保存 7 天校对窗口和批次版本，`CalendarImportCandidate` 保存原始行摘要、可编辑标准草稿、错误、警告、外部 UID、指纹和处理状态；不保存原文件正文。
- 候选支持跨页读取和逐项校对。确认请求每次最多 50 项，以批次及候选版本检测并发修改；所选项在同一事务内全部创建或全部回滚，未选项可留待后续，明确跳过后不入库。
- `CalendarImportIdentity` 用来源格式与 UID/RECURRENCE-ID，或无外部 ID 时的规范化内容指纹，阻止重复导入。相同 UID 但内容变化保留警告且不覆盖旧安排；与手工内容相同只提示疑似重复，由用户决定是否保留。
- 确认后的系列标记 `source_type=import` 并关联来源。冲突仍允许双方共存，确认响应返回现有统一冲突结构；系列整体修改和未来拆分保留来源关系。
- 上传、候选修改和确认均使用 `operation_id`；同账号写入沿用用户行锁。跨账号读取、修改和确认统一返回 404；过期批次只能查看，需重新上传后继续。

`web/src/components/CalendarImport*.vue` 已接入模板下载、文件上传、最近批次恢复、候选校对、分批确认/跳过、重复及冲突提示。候选版本冲突保留当前填写并展示服务器最新版；快速切换历史批次只采用最后一次请求结果；终态批次只读。截图识别原媒体与 ICS 订阅刷新不复用文件批次的 7 天候选期限，继续遵守第 5 节各自的媒体和来源生命周期。

## 16. 已实现截图识别服务合同

迁移 `0012_ai_config_versions`—`0014_calendar_screenshot_imports`、`server/src/itime/ai/` 和 `calendar/screenshot_*.py` 已实现截图识别服务：

- 管理员配置须先用合成图片完成真实视觉请求测试再发布；上传绑定当时的不可变配置版本。未发布配置、账号 AI 权限冻结或账号已有 3 个在途截图作业时，上传前返回明确错误且不保存媒体。

- 截图候选保留 30 天。首次确认或跳过候选时在同一事务清空原图密文；确认系列使用 `source_type=screenshot`，继续复用文件导入的重复、冲突和版本合同。

## 17. 已实现 ICS 订阅服务合同

迁移 `0015_calendar_subscriptions`、`calendar/subscription_*.py` 和受限抓取器已实现订阅服务端：

- 订阅 URL 以独立 Fernet 密钥加密，另存 HMAC 用于变更比较；接口、刷新记录和日志只显示主机及省略敏感路径、查询参数后的地址。生产要求 `ITIME_CALENDAR_SUBSCRIPTION_ENCRYPTION_KEY` 与基础及 AI 密钥分离。
- 抓取器逐跳验证 URL 和全部 A/AAAA 地址，拒绝 IP 字面量、私网、回环、链路本地、CGNAT、元数据、保留及混合地址；固定已验证 IP 建连，同时保留原 Host、TLS SNI 和证书校验，并核验实际 peer。测试环境只对全部解析为回环地址的 HTTP 来源放行。
- 最多跟随 3 次手动重定向并拒绝 HTTPS 降级；禁用系统代理、Cookie 和平台凭据。连接、读取空闲和整个 DNS/重定向/下载链路共享 3/5/15 秒限制；压缩体、解压体和压缩比分别限制为 2 MiB、4 MiB 和 20。
- `calendar.subscription_worker` 以 PostgreSQL `SKIP LOCKED` 和随机租约领取来源，网络和解析不占数据库事务。URL 更新、暂停、租约过期或更新的尝试号会让晚到结果失效。
- 订阅事件使用来源内 `UID + RECURRENCE-ID` 身份，不复用文件导入的账号级只新增身份。支持无限 DAILY/WEEKLY/MONTHLY/YEARLY RRULE、RDATE、EXDATE、全天、UTC、IANA 和浮动时间；日历查询仍只展开 93 天且与手工安排共用 2000 条上限和冲突计算。
- 200 响应只有在完整下载、完整日历解析和原子应用后才更新验证器与摘要；304 只在确实向同一最终 URL 发送条件头时接受。DNS、HTTP、容量、类型、压缩和解析失败均保留最近成功数据。
- 已知 UID/RID 的坏项目或冲突重复项保留旧基线并显示项目错误；存在无法识别 UID 的事件时不执行缺失取消。来源主事件缺失/取消保留刷新前历史 occurrence，未来标记 `source_cancelled`；RID 缺失恢复未来主事件投影，RID 移动和取消优先于主事件。
- `POST/GET/PUT /api/v1/calendar/subscriptions`、刷新、暂停、恢复和事件字段覆盖 API 均按账号隔离并使用操作幂等。名称、说明、地点和占用字段可本地覆盖，来源变化显示旧来源值、新来源值和本地值，逐字段重置后恢复来源值。

`CalendarImportDialog.vue` 已增加“订阅 URL”模式，接入来源创建、状态轮询、手动刷新、暂停/恢复、设置修改、失败保旧、刷新记录、来源事件分页、本地字段覆盖及逐字段重置。订阅 occurrence 详情提供返回来源管理的入口并隐藏通用系列写操作。迁移 `0031_plan_source_conflicts`、规划冲突服务及规划/日历页面已实现来源更新后的当前计划复核、真实重叠块提示、明确保留和重新生成入口；刷新不自动改写计划。真实浏览器证据见[Web 实施与验证](../验收/iTime-Web实施与验证.md)。

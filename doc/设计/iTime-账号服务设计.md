# iTime 账号服务设计

更新：2026-10-02。本模块实现邮箱账号、设备会话 API 及相应浏览器页面；邀请制和管理员 TOTP 在后续模块验收。本文件中的工程默认值均可配置，不代表新的用户确认结论。

## 1. 已实现流程与恢复

| 流程 | 输入与成功状态 | 失败及恢复 |
| --- | --- | --- |
| 注册 | 邮箱、12—128 字符密码；创建待验证账号，验证邮件进入持久化队列 | 格式错误不保存；并发同邮箱只创建一个账号；重复注册不改密码、不泄露是否已有账号 |
| 验证 | 邮件链接中的一次性令牌、注册密码；验证完成后登录 | 错密码不消费令牌；过期/已用/被替换提供重发入口；不知道初始密码可通过本人邮箱找回 |
| 重发 | 邮箱；冷却后产生新令牌并替换旧令牌 | 冷却中不重复排队；统一回复，不披露他人账号；邮件延迟可检查垃圾邮件后重试 |
| 登录 | 邮箱、密码、设备名称；返回本人信息与会话 CSRF 令牌，Cookie 存会话凭据 | 只有密码正确后才区分未验证/停用状态；管理员必须转双重验证入口 |
| 找回 | 邮箱申请，邮件令牌与新密码确认；重设成功使所有设备退出 | 不区分邮箱是否存在；一次性消费，两个并发确认仅一个成功；旧链接不能撤销新密码 |
| 改密 | 当前密码、新密码、是否退出其他设备（显式布尔选项） | 当前浏览器始终轮换会话；选择保留时其他正常会话继续有效；既有找回链接全部失效 |
| 设备 | 分页列出本人有效设备；退出指定或当前设备 | 他人设备与不存在设备统一 404；重复退出返回同一结果；撤销成功后旧会话不能继续写入 |
| 退出 | 撤销服务端当前会话并清 Cookie | 网络中断可重试；已退出或过期时再次退出也成功 |

邮件链接使用 URL fragment，API 通过请求正文接收令牌，避免将其写入 URL 查询日志。验证需要注册密码，避免收件人误点他人预注册账号邮件后激活他人已知的密码。本人邮箱仍可通过找回重设密码并完成邮箱验证。

## 2. 工程配置

| 配置/机制 | 当前工程默认与边界 |
| --- | --- |
| 会话 | `ITIME_SESSION_HOURS=720`，固定期限、不自动无限续期；上线前按运营要求调整，策略接口向页面提供实际期限 |
| 邮件 | 验证 30 分钟、找回 15 分钟、重发冷却 60 秒，均为配置；成功入队不承诺已投递 |
| 密码 | Argon2id，64 MiB、3 轮、并行度 1；每服务进程最多两个哈希，排队最多 2 秒；取消请求需等计算完成才释放容量 |
| 限流 | 每类流程每来源 IP 60 次/10 分钟，每邮箱 15 次/10 分钟；数据库原子计数，失败请求不能回滚计数；配置可调 |
| 代理来源 | 默认只认 TCP 对端，不信任客户端 `X-Forwarded-For`；反向代理上线时需明确可信代理与来源传递方案 |
| 邮件执行 | 独立进程，默认 SMTP 总截止 5 秒，单条租约 60 秒，最多 6 次尝试；退避 5/10/20/40/80 秒，令牌到期即停止 |
| 加密 | `ITIME_ENCRYPTION_KEY` 单独保管；待发送 MIME 加密，发送成功/过期/耗尽尝试后清空；短暂错配保留密文供恢复后重试 |
| 临时记录 | 邮件令牌过期 24 小时后及关联空发件记录清理；过期限流桶清理；不据此清理账号、业务正文或审计 |

数据库只保存随机会话及一次性令牌的 SHA-256 摘要；高熵令牌与用户密码采用不同存储机制。CSRF 令牌由服务端 HMAC 派生，仅通过本人会话接口返回。Cookie 设置 HttpOnly、SameSite=Lax、Path=/api；HTTPS 环境启用 Secure。

待配置的外部 SMTP 必须使用 STARTTLS。当前测试只使用本地 Mailpit，不发送外部邮件。生产密钥轮换、正式邮件供应商及用户可感知的期限策略仍需在上线配置中明确。

## 3. 事务、并发与资源

- 注册使用邮箱唯一约束及用户行锁；账号、令牌、发件记录一起提交，不依赖进程内临时任务。
- 用户写入统一通过 `authorized(request, write=True)`，先锁用户，再复核会话是否撤销、过期及认证版本，最后检查 CSRF。后续业务模块必须复用此合同。锁仅跨数据库操作，不跨密码计算、SMTP 或 AI 请求。
- 改密/找回在事务外计算哈希，事务内重新校验原密码版本；密码变化不能被并发旧请求覆盖。找回递增认证版本，失效所有会话；普通改密的其他设备处理由显式选项决定。
- 限流计数独立提交，采用原子 upsert；邮箱/IP 键经过 HMAC，不以明文作为限流存储键。
- 邮件进程通过 `FOR UPDATE SKIP LOCKED` 领取项目，提交租约后释放连接，再进行 SMTP 调用；落库时校验租约 ID。进程退出后另一进程可在租约到期后接手。
- SMTP 不提供跨系统事务：邮件已投递但进程尚未记录成功时崩溃，可能重发同一封邮件。Message-ID 和一次性令牌保持相同，不产生第二份权限，也不宣称邮件恰好投递一次。
- 会话列表按创建时间和 ID 游标分页，每页最多 100 条，无固定设备总数限制。最后活动时间当前记录登录和实际写入，按分钟节流更新。
- 外键和查询路径建索引，限流/发件清理可按到期索引进行；独立安全事件只记录操作、对象和请求号，不复制凭据或正文。

## 4. 实际接口与代码

前缀 `/api/v1/auth`，错误使用共用 `error.code/message/request_id/saved/retryable/details` 合同。涉及账号写入的 API 成功响应均在事务提交之后返回。

| 方法 | 路径 | 权限 |
| --- | --- | --- |
| GET | `/policy` | 公开密码/期限/冷却策略 |
| POST | `/register`、`/resend-verification`、`/verify-email` | 未登录，按流程限流 |
| POST | `/login`、`/forgot-password`、`/reset-password` | 未登录，按流程限流 |
| GET | `/me`、`/sessions` | 本人有效会话 |
| POST | `/logout`、`/change-password` | 本人会话与 CSRF；重复退出可恢复 |
| DELETE | `/sessions/{device_id}` | 本人会话与 CSRF |

实现：`server/src/itime/auth/`；迁移 `0002_accounts`；工作进程 `server/src/itime/mail_worker.py`；服务动态测试 `server/tests/test_auth.py`。Vue 页面位于 `web/src/pages/AuthPage.vue`、`AccountPage.vue`，设备与改密操作位于 `web/src/components/`；浏览器测试位于 `web/e2e/auth.spec.ts`。页面使用同源代理和 HttpOnly Cookie，CSRF 只在内存中保存；邮件令牌从 URL fragment 读取后立即从地址栏移除，不写入 Web Storage。真实执行结果见[实施与验证](../验收/iTime-Web实施与验证.md)。

## 5. 尚未覆盖的范围

Q-AUTH-01 的改邮箱和申诉，Q-AUTH-02 的管理员引导/恢复/交接，Q-AUTH-03 的邀请与账号/AI 限制动作在对应功能模块继续细化。现有 `is_admin` 和 `status` 字段用于权限边界，不能表示后台用户管理或 TOTP 已完成。当前账号页面提供注册、验证、重发、登录、找回/重设、改密、设备管理、主题/字号和错误恢复；邀请制、管理员认证、离线业务队列与完整产品导航尚未完成，因此不将整个 AUTH/ADM 或 Web 产品标为验收通过。

# iTime 文案规范

> 适用范围：登录、注册、账号、课表、任务、AI 预览等所有用户可见文案。

## 1. 基本要求

- **成功就是成功，失败就是失败。** 不写“请求已受理”“如果此邮箱需要处理”这类不确定状态。
- 一句话说清结果和下一步：发生了什么、用户现在该做什么。
- 不把实现细节、安全策略、内部状态写进用户界面。
- 不用“可能需要”“请检查垃圾邮件”作为默认兜底，除非当前流程确实依赖邮件。
- 按钮用动作词：`登录`、`创建账号`、`保存`、`确认调整`；不用“提交处理”。
- 错误文案先说明原因，再给可执行的下一步；不暴露内部异常。

## 2. 登录 / 注册固定文案

| 场景 | 文案 |
| --- | --- |
| 注册成功且已登录 | 直接进入课表，不显示中间页 |
| 邮箱已注册 | `该邮箱已注册` / `请直接登录` |
| 发送验证邮件 | `验证邮件已发送` / `验证邮件已发送至 xxx` |
| 登录失败 | `邮箱或密码不正确` |
| 密码要求 | `至少 8 位。` |
| 没有邮件服务 | 不显示“忘记密码”“重新发送验证邮件” |
| 登录页默认信息 | 不显示会话时长、公共设备提示 |

## 3. 禁止写法

- `如果此邮箱需要处理，我们会发送邮件。请检查收件箱和垃圾邮件。`
- `注册请求已受理`
- `去邮箱看看吧`
- `本次登录最长保留 30 天。公共设备使用后请退出。`
- `请输入 12—128 个字符`
- 在成功页同时显示“成功”和“如果失败/如果未收到”。

## 4. 评审清单

- 用户能否在 2 秒内知道“成功还是失败”？
- 是否明确告诉用户下一步？
- 是否删除了与当前配置无关的邮件/安全说明？
- 是否能把文案缩短一半而不丢信息？

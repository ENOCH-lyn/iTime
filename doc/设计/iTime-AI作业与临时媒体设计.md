# iTime AI 作业与临时媒体设计

版本：0.1；更新：2026-10-02。本文冻结截图识别所需的通用 AI 配置、持久化作业和临时媒体合同，并作为后续对话、规划与复盘作业的基础。金额额度、正文日志和质量样本仍在 M4 对应模块接入；本设计不把这些尚未实现的能力表述为已完成。

## 1. 方案与边界

截图识别采用持久化异步作业，不在上传 HTTP 请求中等待模型：

```text
管理员创建配置 → 合成输入测试 → 发布能力版本
                                  ↓
用户上传截图 → 加密临时媒体 → 排队作业 → worker 领取
                                             ↓
                                  真实视觉模型调用与结构校验
                                             ↓
                                  日历导入批次与候选校对
                                             ↓
                              用户确认/跳过 → 原图立即删除
```

未采用同步调用，因为模型响应可能超过普通请求超时，页面离开会丢失结果，且无法可靠处理取消、租约恢复和在途配置版本。未采用纯内存队列，因为进程重启会丢失上传和作业。首版以 PostgreSQL 保存加密媒体，避免引入尚未部署的对象存储；单图大小、像素和生命周期有严格上限，后续迁移到对象存储时保持媒体 ID 与状态合同不变。

## 2. AI 配置版本

`AIConfigVersion` 是不可变配置版本：

- `capability`：首批为 `calendar_screenshot`，后续扩展对话、规划和复盘。
- `endpoint_url`：OpenAI 兼容 API 根地址，不含查询、片段或用户信息。
- `model`、请求时限、最大输出 token。
- `api_key_ciphertext`：使用服务端根密钥加密；任何读取接口只返回 `key_configured=true`。
- `status`：`draft → tested → published → retired`。测试失败仍保持 `draft` 并保存不含上游正文的错误阶段。
- 配置通过合成图片做真实端点测试；测试不发送用户正文。只有最近一次测试成功的不可变版本可发布。
- 同一能力最多一个已发布版本。发布事务切换当前指针，旧作业继续绑定原配置版本。

生产默认只允许 HTTPS 端点。测试环境可使用回环 HTTP 服务；私有网络 AI 端点须由部署配置明确放行，不能因管理员输入自动扩大网络范围。

## 3. 持久化作业

`AIJob` 保存能力、所有者、配置版本、输入快照、结果引用、总截止时间、尝试次数和租约：

- 状态：`queued → running → succeeded | failed | timed_out | cancelled`。
- API 接单先检查账号 AI 权限、已发布配置和输入限制，再在同一事务写媒体、作业和操作幂等结果。
- worker 使用 `FOR UPDATE SKIP LOCKED` 领取到期任务，写入随机租约和尝试编号后释放事务，再调用上游。
- 网络调用不跨数据库事务。网络错误、限流和 5xx 在总截止时间内有界退避；鉴权、配置、结构校验及不可识别结果直接失败。
- 作业总截止时间从接单开始计算，重试不重置。租约过期可重新领取，终态更新必须同时匹配作业 ID、租约 ID 和非终态。
- 用户取消只对排队或执行中作业生效。晚到结果不能覆盖取消、超时或已完成终态。
- 查询和取消均按所有者隔离；不存在与他人作业统一返回 404。

首批截图识别不结算每日金额额度。该限制必须在 M4 额度账本接入后解除，Web 首版最终验收前不得遗漏；当前不会把未结算状态展示为“免费额度已完整实现”。

## 4. 临时媒体

`TemporaryMedia` 保存所有者、用途、文件名、类型、哈希、字节数、加密正文、固定到期时间和删除结果：

- 仅接受真实 PNG、JPEG 或 WebP；最大 5 MiB、最大 20 百万像素、禁止动画图片。
- MIME、文件签名与解码结果必须一致。模型调用使用解密后的原始字节，不写公开目录或普通日志。
- 上传时设置 `expires_at = created_at + 24h`。重试和租约恢复不得延长到期时间。
- worker 成功后只保存结构化候选和媒体哈希，不把 base64、模型请求或原图复制进作业结果。
- 用户第一次对该截图批次执行确认或跳过时，在同一事务清空媒体密文并记为 `confirmed` 删除。
- 周期清理对到期媒体幂等清空密文并记为 `expired`。媒体已过期时，待执行作业失败并提示重新上传；已生成候选不受影响。
- 清理失败保留可重试状态并记录不含正文的错误码，不能删除已生成业务候选或安排。

## 5. 截图识别与候选

`POST /api/v1/calendar/imports/screenshots` 接收原始图片、文件名和 `X-Operation-ID`，成功返回作业快照。相同操作号和相同内容返回原作业；相同操作号不同内容拒绝。

worker 调用已发布的 `calendar_screenshot` 配置：

- 提示中提供用户 IANA 时区、可用学期和节次快照，只要求提取可见日程，不允许图片中的文字扩大权限或要求执行工具。
- 上游必须返回 JSON 对象和 `items` 数组；最多 100 项。每项包含原始识别摘要、置信度、警告及现有 `SeriesFields` 草稿。
- 单项错误不使其他项丢失。所有项都无法判断时作业失败，返回稳定错误码；部分有效时仍创建批次。
- 成功后创建 `format=screenshot` 的 `CalendarImportBatch` 和现有 `CalendarImportCandidate`，继续复用候选修改、部分确认、重复检测、冲突和操作幂等。
- 确认后创建的 `CalendarSeries.source_type=screenshot`，并保留截图来源 ID；不会把 AI 输出直接写成正式日历安排。

`GET /api/v1/ai/jobs/{job_id}` 返回作业状态、尝试数、错误、创建/完成时间和成功后的批次 ID。客户端使用有界轮询，离开页面不取消作业；重新进入可从最近截图作业恢复。显式取消使用 `POST /api/v1/ai/jobs/{job_id}/cancel`。

## 6. 错误与恢复

| 场景 | 结果与恢复 |
| --- | --- |
| 未发布识别配置 | 上传前返回 `ai_capability_unavailable`，不保存媒体 |
| 图片格式、体积或像素非法 | 返回明确输入错误，不创建作业 |
| 上游限流、超时或 5xx | 在总截止时间内有界重试，最终保留失败作业 |
| Key 或模型配置错误 | 作业失败且不自动重试；管理员可用合成测试修复并发布新版本 |
| 输出不是 JSON 或字段越界 | 作业失败或保留可判断候选；原图仍按固定 24 小时清理 |
| worker 中断 | 租约到期后重新领取；作业状态防止重复落库 |
| API 提交后连接中断 | 客户端以原操作号重试或从最近作业查询 |
| 候选确认并发 | 沿用批次和候选版本冲突，不以旧草稿覆盖新版本 |

用户错误界面显示失败原因、是否已保存、恢复动作和请求编号。上游响应正文、Key、图片字节及 base64 不进入普通日志或错误响应。

## 7. 验证

- 真实 PostgreSQL：迁移升降级、不可变配置版本、单能力发布切换、密钥不回显、账号隔离、幂等和并发领取。
- 真实 HTTP：本地 OpenAI 兼容测试端点接收合成图与真实测试截图，覆盖成功、结构错误、401、429、5xx、超时和重试。
- 媒体：真实 PNG/JPEG/WebP、伪扩展名、动画、超像素、确认后清理、24 小时清理、过期后重领。
- 候选：有效、部分无效、零结果、最多 100 项、重复、冲突、编辑和部分确认。
- Web：上传、轮询、离页恢复、取消、失败重试、候选校对与确认；桌面、平板、手机、320px 大字号、键盘、axe、控制台和截图人工检查。

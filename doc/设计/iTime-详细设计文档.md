# iTime 详细设计文档

版本：0.1；状态：概念设计，供需求讨论；尚未选择技术栈、创建数据库或实现接口。下列建议必须在需求确认后细化，不能作为现有实现说明。

## 1. 系统职责

```text
Web用户端 ─┐
           ├─ 业务服务：身份 / 任务 / 日历 / 计划 / 执行 / 复盘 / 同步
App用户端 ─┘                       │
                                  ├─ 持久化与附件存储
                                  ├─ AI作业与约束校验 → 模型供应商
                                  └─ 提醒与统计
Web管理后台 ─ 管理权限边界 ─ 用户支持 / AI配置 / 用量 / 审计
```

只有用户端、后台、服务端AI和云同步的职责边界已确认。图中具体模块是否独立进程、数据库种类和队列形式均待ADR。

## 2. 概念数据对象

| 对象 | 职责与必要关系 | 未决点 |
| --- | --- | --- |
| User / Identity / Session | 稳定用户ID、登录凭据映射、设备会话 | 登录方式、合并、会话期限 |
| UserPreference | 可编辑偏好、时间习惯与设置 | 与AI记忆的区别和更新授权 |
| CalendarSource / FixedEvent / OccurrenceException | 来源、重复规则、具体日期例外 | 学期、时区、外部同步与取消 |
| Task / TaskStep | 原始事项、目标工作量、依赖与步骤 | 目标层级、重复、归档、步骤复用 |
| Plan / PlanVersion / ScheduledBlock | 某日期或范围的计划、版本和排期实例 | 一个任务多段安排、锁定与恢复 |
| ExecutionSession / ExecutionEvent | 开始/暂停/结束等事实与实际时间 | 并发执行、补记、设备时钟 |
| DifficultyRecord | 关联执行/任务的困难、情绪和想法 | 独立记录、编辑和保留 |
| ReviewSession / ReviewMessage / ReviewReport | 可继续的对话、事实快照与报告版本 | 多次复盘、改报告、流式恢复 |
| Suggestion / PreferenceChange | 建议、接受或拒绝及生效记录 | 自动采纳与可撤销范围 |
| AIJob / UsageRecord | 输入版本、模型执行、取消、结果、消耗 | 扣额规则、重试与预算 |
| AIEndpoint / ModelRoute / ConfigVersion | 供应商地址、模型能力、凭据引用、配置版本 | 协议、轮换、灰度与回滚 |
| SyncOperation / ChangeCursor | 客户端操作去重、增量同步与冲突 | 合并规则、离线删除 |
| Notification / DeliveryAttempt | 通知意图、渠道投递和去重 | 系统限制、隐私显示 |
| AuditEvent | 管理动作及必要追溯元信息 | 正文访问授权、保留期限 |
| Entitlement / Order | 若收费，维护权益与支付结果 | 是否纳入及平台渠道 |

建议所有用户数据具备稳定归属、版本与时间语义。实际字段名、类型、唯一约束、索引和删除策略在需求冻结后定义；不得将上表直接当作已经存在的数据库表。

## 3. 状态与不变量建议

| 领域 | 建议状态 | 必须解决的边界 |
| --- | --- | --- |
| 任务 | 待办、进行中、已完成、已取消、已归档 | 截止已过不自动代表完成；进度来自哪些动作 |
| 计划 | 草稿、已确认、已替代 | 修改是否生成版本；只应用到目标版本 |
| 排期实例 | 待开始、执行中、已完成、已跳过、已取消 | 到点未完成不自动认定实际执行情况 |
| 执行会话 | 进行中、已暂停、已结束、已放弃 | 一致记录有效时长；重连不能重复计时 |
| 复盘 | 进行中、暂停、生成报告中、已完成 | 退出不丢已确认消息；错误可继续 |
| AI作业 | 排队、运行、校验、成功、失败、取消 | 终态单一；取消与成功竞态不重复应用或结算 |
| 建议 | 待决定、已采纳、已拒绝、已撤回 | 建议不是执行事实；是否自动采纳待确认 |
| 同步操作 | 本地待传、发送中、已确认、冲突、失败 | 传输失败不等于业务未执行 |

建议约束：排期不得违反已确认硬约束；已执行事件不能被重新生成静默改写；统计区分缺记录、跳过和实际未完成；跨日事件有明确归属；实体删除后异步任务不能将其重新写回。

## 4. 规划与复盘的AI链路建议

1. 认证并读取当前用户有权访问的数据，生成目标日期和版本快照。
2. 校验输入、预算及重复请求；记录任务身份和所用配置版本。
3. 构造只包含该能力所需的数据；附带模型输出结构要求。
4. 调用模型；记录接单、首字、完整输出、供应商使用量与错误阶段。
5. 验证格式、引用的任务归属、目标时间、冲突和硬约束。事实推测需可辨认。
6. 若输入已变化，进入差异处理或重新生成；不静默覆盖新修改。
7. 根据最终确认规则，提供草稿或应用结果；应用具备幂等与事务边界。
8. 记录成功/失败/取消和费用；是否扣用户额度由商业规则决定。

复盘额外要求：对话消息按稳定编号保存；恢复时不重复用户消息；报告使用可追溯的执行事实；长期记忆变更独立于报告生成；允许用户纠正事实。

## 5. 同步协议需要明确的合同

每类写操作定义身份、实体版本、客户端操作ID、成功响应、冲突响应、重试语义和删除规则。服务端接收成功而客户端断线后，相同操作ID重试应返回同一业务结果。

需要逐项决策：

- 不同字段修改是否自动合并；同字段冲突如何呈现。
- 步骤勾选是否可合并；任务完成与后续新增步骤冲突怎么办。
- 删除与离线编辑相遇时是否可恢复，恢复是否保留原ID。
- 重排期间课表变化如何使草稿失效。
- App后台同步被系统暂停时如何显示待上传，不误称“已同步”。
- 切账号时如何隔离本地数据和同步队列。

## 6. 接口职责与异常合同

具体URL、HTTP方法和schema待技术栈与规则确定；下表是后续OpenAPI/契约的覆盖清单。

| 接口组 | 应覆盖的动作 | 主要错误与恢复 |
| --- | --- | --- |
| 身份与账号 | 注册、验证、登录、刷新、找回、改绑、注销、设备 | 身份验证失败、过期、限流、联系方式不可用 |
| 固定事件 | 上传识别、预览确认、编辑、重复例外、订阅刷新 | 低置信度、重复、部分失败、格式/大小限制 |
| 任务与执行 | 增删改查、步骤、开始/暂停/结束、补记 | 版本冲突、状态不允许、重复操作 |
| 规划 | 提交生成、查询/取消、接受草稿、调整、版本恢复 | 无可行解、输入过期、锁定冲突、AI失败 |
| 复盘 | 创建/恢复、提交消息、报告、建议采纳 | 流中断、重复消息、缺事实、报告版本冲突 |
| 同步与导出 | 增量拉取、操作上传、冲突处理、导出任务 | 游标过期、队列失败、账号切换、下载权限 |
| 管理AI | 端点保存/测试、模型路由、发布、轮换、回滚 | 权限不足、上游认证、连通失败、配置失效 |
| 用量与运营 | 配额查询、聚合指标、审计、支持动作 | 额度不足、重复补额、无权限查看正文 |

错误应区分：输入不合法、无权限、状态/版本冲突、预算不足、上游不可用、超时、取消、无可行规划和未知故障。客户端展示可行动原因、保存状态及请求编号；不能只显示“失败”。

超时分层包括连接、首字、流空闲、单次模型调用、整个作业和队列排队。重试需限定次数和总预算，按错误可重试性处理；客户端断线不能默认启动第二个昂贵请求。具体数值由容量、供应商和体验目标确定。

## 7. 权限、数据及后台边界

普通用户只能操作自身数据；管理员账号不自动获得全部用户内容。后台角色、正文访问和临时支持授权尚待确认。

建议端点配置只返回非秘密元信息与“已设置”状态，凭据写入/轮换与模型测试分开。端点地址是否允许内网由部署需求明确；根据结果设计网络限制，防止配置测试越过允许的网络范围。

注销/删除需覆盖活动数据、附件、索引、AI记忆和在途作业；备份按确认的保留政策过期。导出和分享区分所有者文件下载与公开链接，后者需定义撤回和过期。

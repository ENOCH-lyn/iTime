# iTime 详细设计文档

版本：0.2；更新：2026-10-02。本文是满足[需求规格](../需求/iTime-需求规格说明书.md)的设计方案。**运行基础已实现，业务对象与接口仍按模块推进**，实际状态见[实施与验证](../验收/iTime-Web实施与验证.md)。已确认规则与工程建议以规格、[ADR](../架构/iTime-ADR架构决策文档.md)为依据；涉及待定产品行为处引用问题编号。

## 1. 模块边界

```text
Vue Web 用户端 / Web 后台 / 后续 Android、iOS
                         │
               身份与版本化业务 API
                         │
  任务与课表 ─ 计划提案 ─ 执行与复盘 ─ 同步与数据管理
                         │
      权威数据库：对象、版本、作业、额度、审计、变更
                         │
              持久化作业 → 独立执行进程
                         ├─ AI 供应商（能力路由、备用）
                         ├─ 临时媒体识别与清理
                         └─ 公开网页读取（受限网络）
```

推荐模块化单体，业务事务保留在一个权威数据库。耗时 AI/识别工作独立执行，不长时间占用普通 API 请求或数据库事务。管理 API 对同一数据层实施独立权限检查。公开介绍/演示与真实个人数据入口区分。

## 2. 数据对象与共用契约

| 对象 | 主要语义与关系 |
| --- | --- |
| User / Identity / DeviceSession | 用户归属、邮箱凭据、设备会话、撤销状态；管理员另有 TOTP 与认证状态 |
| Project / Task / TaskStep / TaskRecurrence | 项目或目标、统一任务、顺序步骤、重复模板与单次实例；无任务间依赖 |
| CalendarSource / Term / FixedEvent / OccurrenceException | 导入来源、学期与节次、重复固定安排和指定日期例外 |
| ImportJob / TemporaryMedia | 识别状态、候选结果与原媒体到期时间；校对确认后写业务对象 |
| Plan / PlanVersion / ScheduledBlock | 周任务分配、日计划及版本；一个任务可对应多个时间段 |
| FocusSession / FocusEvent / ExecutionRevision | 专注状态、分段开始/暂停/结束事实、用户补记与修订 |
| DifficultyRecord | 文本、可选分类/情绪与任务/日期关联；关联粒度待 Q-DIFF-01 |
| Conversation / Message | 多个普通会话、消息顺序及生成状态 |
| ReviewSession / ReportVersion / Annotation | 选定单日复盘、事实快照、报告版本及独立批注 |
| Memory / Preference | 确认保存的记忆与偏好、归属、来源和版本 |
| Proposal / ProposalChange | AI 提案的修改对象、前后差异、基础版本及应用状态 |
| AIJob / AIAttempt / AIConfigVersion | 作业及上游尝试、能力、输入快照、截止时间、配置版本 |
| DailyAllowance / Reservation / UsageLedger / ProviderCost | 每日金额额度、预留、用户结算、平台实际/估算成本，分别核算 |
| SyncOperation / ChangeCursor / Conflict / Tombstone | 操作去重、服务端顺序、冲突、删除状态与增量同步 |
| ExportJob / DeletionJob / QualitySample / BodyLog / AuditEvent | 导出、清理、质检样本、正文日志及管理审计，分别定义用途与期限 |

以下字段语义为推荐，不是已创建的表结构：

- 用户对象带稳定 `id`、`owner_id`、服务端 `version`、创建/修改时刻和删除状态。归属由认证上下文决定，不信任请求传入的用户 ID。
- 写操作带 `operation_id`、实体和 `base_version`。同账号同操作 ID 重试返回原结果；相同 ID 携带不同内容拒绝，防止去重误用。
- 时间点存 UTC；事件另存 IANA 时区、原始当地日期/时刻、重复规则。活动日另有业务语义，不能由 UTC 日期直接替代。
- 金额采用定点或整数最小单位，存币种、精度、价格版本、使用量和来源；禁止浮点累积。最终币种与舍入方式待额度设计。
- 约束至少覆盖操作 ID 唯一、重复任务实例唯一、一次提案应用唯一、一次成功结算唯一及同账号单一进行中专注。
- 分页查询按 `owner_id` 与时间/游标建复合索引；报告、对话和事件历史分页加载，不一次读取账号全部正文。

## 3. 身份、权限与后台

邮箱密码注册、验证和找回使用独立的一次性凭据，限制期限及重复使用；密码使用成熟的密码哈希方案。凭据在应用日志之外保管。会话撤销须作用于服务端请求校验，不能只删除客户端入口。

超级管理员必须完成密码与 TOTP；公开注册不能提交管理员身份。普通用户只能访问自己的对象、导出和作业。管理员可直接查看用户正文，同时记录访问者、对象、目的/操作、时间与结果；审计元数据无需重复复制正文。

AI Key 只写不回显。服务端保存加密值和凭据版本，解密根密钥与业务数据库分离。配置测试使用合成输入并显示上游错误阶段，不能默认发送真实用户正文。端点测试的网络范围与费用上限待 Q-ADM-01。

后台模块包括用户/邀请/状态、额度、AI 配置、日志、审计与质检。配置生命周期为草稿 → 测试通过 → 发布 → 被新版本替代，可回滚到先前版本。发布事务切换指针；在途作业保留绑定版本，密钥紧急撤销独立生效。

邮箱账号 API、一次性验证、找回/改密及设备撤销已经实现，实际事务、资源上限和路由见[账号服务设计](iTime-账号服务设计.md)。管理员密码加 TOTP、恢复码、独立会话及本机创建/重置服务见[管理员认证设计](iTime-管理员认证设计.md)。开放/邀请注册、邮箱绑定邀请、账号状态与 AI 访问状态见[注册与用户状态设计](iTime-注册与用户状态设计.md)。会话期限、恢复、邀请运营期限、申诉和 AI 在途作业处理仍是待确认规则，不把当前可调整工程边界标为用户决定。

## 4. 课表、任务与规划输入

课表先按学期/周次/单双周/指定周与节次展开到目标真实日期，再应用单次取消、调课和补课例外。自定义固定不可安排时间同样形成固定区间。采用结构化重复规则按有界查询范围展开，时区和夏令时歧义需显式处理，不静默前移或后移；完整字段与算法见[时间、课表与重复规则设计](iTime-时间课表与重复规则设计.md)。

截图/Excel/ICS 解析返回候选记录、来源、警告和置信信息。确认时校验学期、时间和重复情况，事务写入选择的有效记录并生成同步变更。识别失败保留已得到的候选结果，允许校对；部分有效记录可确认，精确重复幂等合并，疑似重复由用户判断。

订阅只读取公开来源，保留来源事件标识及上次成功版本；刷新失败不清空日程。来源更新影响固定安排后，对相关计划标记冲突，等待用户查看或请求重排，不悄悄改动计划。来源删除保留历史并取消未来 occurrence；本地例外优先，来源变化与本地覆盖并存时展示差异。

任务包含名称、可选截止/耗时/优先级/标签、文本与链接、步骤和拆分设置。重复模板和单次 occurrence 分离，实例完成不能把整个系列标为完成；系列修改区分仅本次、本次及以后和全部。任务实际完成由用户确认，剩余工作量不能从排期时长直接扣除。

任务核心、日期型/定时截止、结构化重复、拆分参数、实例状态、未来系列拆分、手动归档和 30 天任务回收站已经实现；实际表、接口、输入上限、操作幂等、版本、清理墓碑与并发语义见[任务核心服务设计](iTime-任务核心服务设计.md)、[时间课表与重复规则设计](iTime-时间课表与重复规则设计.md)和[任务生命周期设计](iTime-任务生命周期设计.md)。任务实例补做、语音及 AI 校对仍待后续模块。

规划读取目标日期范围的固定区间、任务与步骤、有效偏好、相关执行历史。先计算可用时间，再进行周分配/日细化。用户指定硬约束必须满足；普通估计附标记。推荐以半开区间 `[start, end)` 校验相邻块，避免端点相邻被误报冲突。

## 5. 日期与专注

活动日以用户业务时区的 04:00 为界。例如当地 10 月 3 日 03:30 归属 10 月 2 日活动日，但日历仍显示 10 月 3 日 03:30。不能简单减去固定 UTC 时长处理所有时区；夏令时地区应按当地边界求区间。

专注跨活动日时，建议统计按有效时段与日界线相交分段，保留原始会话和修订。每周从周一开始；用户时区变化不改写既有时间点。具体统计分母和修订归属仍待 Q-MET-01。服务器决定当前额度日，设备时间修改不产生新的额度。

推荐专注状态：未开始 → 进行中 ↔ 暂停 → 已结束/已放弃。开始操作在事务内检查账号现有进行中会话，冲突返回会话状态供用户处理。暂停后是否允许另一会话开始待 Q-EXEC-01。

计时基于已记录时段，前端定时器仅用于展示；刷新或关闭页面不丢失服务端状态。离线只能续已有专注，以操作 ID 保存勾选和计时事件；恢复联网时核对会话版本、服务端结束时间和时钟差，不直接覆盖服务端事实。补记修改保留前值、修改后值、来源及修订时间。

## 6. AI 提案与版本应用

所有 AI 业务改动先构造成提案，包含所有者、输入对象及版本、变更范围、前后差异、估计说明和有效状态。规划、任务拆解、课表修改、记忆及偏好更新使用同一确认机制。

```text
生成中 → 可预览 → 已应用
                  ├─ 已拒绝
                  └─ 已过期/存在冲突 → 修订或重新生成
```

确认事务需要重新鉴权，检查目标未删除、输入版本及硬约束仍有效；对应用记录和变更对象原子提交，发出同步事件。重复确认返回同一应用结果。并发人工编辑造成过期时展示差异，不以旧提案覆盖新版本。

流中的文字不等于可应用结构。提案输出校验失败不创建正式任务或计划。已发生的执行事实独立于计划版本保存，重排不能修改历史执行。局部接受、锁定与历史恢复范围待 Q-PLAN-02，首个实现不能擅自扩大交互能力。

## 7. AI 作业、重试与取消

建议将生成作业状态与提案状态分开：

```text
已接收 → 排队 → 执行 → 校验 → 结果完成
                    ├─ 有界重试/备用服务
                    └─ 失败 / 超时 / 已取消
结果完成 → 聊天回复、识别结果、报告或可预览提案
```

接单先鉴权、验证输入和预算，再事务写作业、预留及待投递记录。执行进程按租约领取，持久化尝试编号、开始时间和截止时间；投递至少一次时仍由作业状态保证只结算、应用一次。

数据库事务不跨越上游网络调用。执行崩溃后能重新领取，但已有尝试可能仍在供应商运行，重复调用成本计入平台；使用供应商幂等能力时须核实协议，不假设所有兼容接口支持。

流式事件携带作业与序号，可按最后序号续读或获取快照；消息稳定编号去重。客户端断线默认继续后台作业；显式取消才改变作业状态。后台运行完成后在重新进入页面时展示，不新增 Web 提醒。

总时长基线约 3 分钟、后台可配置。方案建议以接单至生成终态为总时长，排队、连接、首字、空闲流与单次尝试都有子预算；具体数值待容量测试。失败重试和备用服务切换不能重置总截止时间。

网络超时、限流可按规则退避；鉴权或配置错误通常直接失败；无解不当作网络错误重试。部分流式输出只可作为未完成内容显示，不能直接应用。备用服务须匹配能力并保留实际使用的配置/价格/数据处理位置。

取消、超时、成功采用事务状态比较，只有一个终态获胜。取消完成后晚到输出不可应用或扣用户额度；用户删除对象或注销时，再次校验归属和删除状态，不能使数据复活。

普通多会话、文本作业和流式恢复已按本节实现：`0017_ai_conversations` 保存会话、消息、生成映射和有序事件；worker 以租约心跳执行 OpenAI 兼容文本流，事件先提交后由 SSE 按序号读取，重试使用 generation/reset 隔离旧片段。Web `/ai` 支持离页继续、刷新恢复和显式取消。当前结果只作为持久化文本消息，不创建业务提案；金额额度仍未接入，详见[全局 AI 对话设计](iTime-全局AI对话设计.md)。

## 8. 额度与成本合同

已确认：每日金额额度、04:00 刷新、仅成功扣一次、失败/取消不扣、失败重试成本平台承担、usage 缺失可估算并标注。

账本流程：

1. 校验服务端活动日、额度、账号/平台并发与总成本上限，原子预留请求预算。
2. 每次供应商尝试独立记录实际或估算成本，失败尝试也进入平台成本。
3. 结果校验通过且可供查看时，只引用最终成功 attempt 生成一次用户扣额记录；业务提案后续拒绝或过期不返还，失败/取消释放预留。
4. 重复事件以作业/结算唯一键去重；余额从账本与预留推导，不能由客户端提交。
5. 使用量来源区分供应商上报、平台估算，保存输入/输出量、估算规则版本、价格版本与舍入信息；界面标明估算。

已采用“结果通过校验并可供查看”作为生成成功，提案应用另行记录。跨 04:00 作业归接单时活动日；实际成本超预留和终态后迟到 usage 由平台承担，不追扣用户。AI 冻结只阻止新作业，既有预留继续结算或释放。

免费额度不是现金余额；首版没有充值、支付或会员订单。平台成本超限应停止接收新 AI 请求并说明，不能影响已保存任务的手动查看和编辑。

价格版本、provider usage 和逐尝试平台成本已按[专项设计](iTime-AI额度与成本账本设计.md)实现：迁移 `0019_ai_provider_costs`、`0020_ai_provider_cost_lifecycle` 保存不可变配置价格、请求开始事实和 `AIProviderCost`；对话/截图终态事务记录供应商上报或版本化估算用量，后台 `/admin/costs` 可对账。`DailyAllowance`、预留和用户结算按已确认规则继续实现。

## 9. 公开链接与临时媒体

公开网页抓取只接受约定协议，校验域名解析结果、重定向链与实际连接目的地址，拒绝内网、回环、链路本地及云元数据地址。不能仅检查初始 URL 字符串；应防 DNS 重绑定及连接时地址变化。

限定跳转次数、响应体积、类型、解压体积、总时间和每用户请求量；不携带用户浏览器 Cookie、平台鉴权头或 Key。受登录保护的页面不请求用户凭据。记录来源/取得时间与失败原因，缓存也必须遵循权限和删除策略。

网页文本与用户指令区分，作为不可信资料传入；内容中要求调用工具、读取他人资料或更改计划的文字没有授权效力。模型提出的业务变化继续走提案确认。

原图/录音保存在临时区域，带所有者和到期时间。确认结构化结果后发出幂等删除任务，未完成的原媒体 24 小时清理；不能因失败重试无限续期。超期恢复提示重新上传。文件解析在受限资源下执行，不把宏、脚本或文件内指令当作可执行工作流。

## 10. 同步与冲突恢复

推荐接口合同包括操作 ID、实体 ID、基础版本、变更内容、服务端结果版本和增量游标。服务器接受写入时，业务对象、操作去重记录与同步变更一起提交，避免“业务成功但没有变更事件”。

| 场景 | 处理原则 |
| --- | --- |
| 两端修改不同且语义独立字段 | 基础版本可追溯时安全合并；重新校验业务约束 |
| 同字段、任务完成与步骤结构联动 | 保存冲突及双方候选，让用户选择；不静默丢弃 |
| 服务端提交后客户端超时 | 相同操作 ID 重试返回已提交结果 |
| 删除与离线编辑相遇 | 墓碑阻断普通写回；展示冲突及回收状态，恢复入口按 Q-SYNC-01 定稿 |
| 旧游标过期、大量离线操作 | 保留待传内容，获取一致性快照，再逐项对账；不能清缓存后丢本地修改 |
| 切账号、退出、撤销或注销 | 队列按账号隔离；禁止将旧账号操作传到新账号；撤销会话先重新认证 |
| 网络恢复/失败积压 | 展示待传数、最后同步时间、具体错误和重试；有界退避 |

在线约 5 秒目标适用于正常网络下提交后另一在线端可见，需定义测试条件后测量。推送事件或短轮询是实现选择，不能把后台同步事件做成 Web 业务提醒。

## 11. 复盘、记忆、导出与清理

复盘按选定单日读取计划、实际执行和困难，允许补充事实；没有计划也可开始。报告保存事实快照/来源版本，批注独立保存，重新生成产生新版本，不重写旧报告。普通会话与复盘分别归档。缺记录不能作为失败证据，估计原因不得表述成心理诊断或用户事实。

长期记忆与偏好由用户确认后保存。检索按当前请求、所有者和有效状态选择；删除记忆后使相关缓存/索引失效。报告内建议不自动修改任务、偏好或计划。

| 数据 | 生命周期 | 清理与恢复设计 |
| --- | --- | --- |
| 业务历史 | 账号存续保留 | 用户删除进入 30 天回收站；恢复需校验依赖与冲突 |
| 注销账号 | 7 天可撤销 | 到期清理正文、记忆、索引、样本，停止在途作业；撤销期交互见 Q-DATA-01 |
| AI 请求/响应正文 | 默认 7 天 | 独立存储/权限/到期任务，平台 Key 与鉴权头不入正文日志 |
| 质量样本 | 30 天 | 人工质检/提示词优化/效果评测，不训练；默认参与，关闭停止新采样；采样提交前复核当前开关 |
| 临时原图/录音 | 确认后或未完成满 24 小时 | 删除原件，不删除已确认结构化内容；删除失败可重试并告警 |
| 导出临时文件 | 有限时效，具体期限待配置 | 仅本人鉴权下载，过期重建；JSON 完整导出，CSV/ICS/Markdown 分类导出，不提供整包恢复 |
| 备份与审计元数据 | 周期待配置 | 恢复备份后重放删除台账、清理已到期数据，再开放业务 |

关闭质检仅停止后续采样，既有样本正常到 30 天清理；账号注销清理优先于此规则。单项彻底删除对正文日志/样本的影响待 Q-PRIV-01。清理操作幂等，派生内容与异步任务必须检查删除台账，不能从旧输出重新生成已删数据。

AI 日志与质检现已按[专项设计](iTime-AI日志与质检设计.md)实现：迁移 `0018_ai_governance` 将逐尝试技术正文、成功质量样本、用户隐私设置和管理审计元数据分开保存；终态事务复核用户开关，独立清理进程执行 7/30 天期限，后台正文读取先审计后返回。账号注销及单项彻底删除的跨聚合处理仍随对应数据模块实施。

## 12. API 职责与错误合同

业务 API 采用版本化前缀，以下为接口组设计，业务路由随模块补齐。现有运行接口为 `GET /api/health`、`GET /api/ready`，开发环境提供 `/api/openapi.json` 和 `/api/docs`，生产关闭文档入口。就绪必须同时满足数据库可连接与迁移版本一致。

| 接口组 | 输入/主要动作 → 输出 | 权限及核心失败 |
| --- | --- | --- |
| 账号 | 邮箱验证/登录/找回/会话/注销 → 会话或处理状态 | 访客按流程；个人管理本人；过期、重用、限流、撤销 |
| 任务与日历 | CRUD、系列/单次修改、导入确认/订阅 → 对象和版本 | 所有者；输入错误、重复、来源冲突、识别失败 |
| 对话与规划 | 消息、生成范围、查询/取消、提案确认 → 作业、流、提案或结果 | 所有者；预算不足、输入缺失、过期提案、上游错误 |
| 执行与困难 | 开始/暂停/结束、补记/修订、困难记录 → 事实和版本 | 所有者；账号已有进行中专注、时间/状态冲突 |
| 复盘与记忆 | 会话/报告重生成/批注、确认记忆 → 持久化结果 | 所有者；消息重复、事实版本变化、对象已删 |
| 同步与数据 | 操作上传、游标拉取、冲突解决、导出/回收 → 状态/文件作业 | 所有者；游标过期、依赖缺失、清理中、未认证 |
| 用量 | 日额度和账本分页 → 余额、预留、扣额及估算标记 | 所有者；不允许客户端任意修改余额 |
| 管理 | 用户/额度、配置测试发布回滚、正文/质检查询 → 管理结果和审计 | 超级管理员及 TOTP；无权限、重复调整、无效配置 |

统一错误已在 `server/src/itime/errors.py` 实现，结构为 `error: {code, message, request_id, saved, retryable, details}`；`saved` 分为 `not_saved / saved / unknown`。请求编号由服务端生成并通过 `X-Request-ID` 返回。连接失败或未知系统异常不能承诺事务未提交，因此返回 `unknown`，后续业务模块须支持原操作 ID 对账重试。输入错误只回字段位置与类型，不回显密码或原始正文。区分输入、身份、所有权、状态/版本、额度、上游、超时、取消与系统故障；不能把无法规划全部任务一律报成系统错误。

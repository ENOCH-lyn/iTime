# iTime ICS 订阅设计

版本：0.1；更新：2026-10-02。本文冻结 Web 首版 ICS URL 订阅的网络、来源修订、刷新和本地例外合同。订阅是外部只读来源，不写回外部系统，也不把失败刷新解释为来源删除。

## 1. 方案与对象

订阅采用“受限抓取器 + 持久化刷新作业 + 来源修订投影”：

```text
用户提交 URL → 校验并加密保存 → 排队刷新 → 受限抓取
                                            ↓
                                  完整解析与来源快照比较
                                            ↓
                        原子应用来源修订 → occurrence 投影
                                            ↓
                    来源基线 → 本地字段覆盖 → 用户单次例外
```

不直接复用文件导入的“候选确认后只新增”逻辑。文件是一次性快照，订阅必须识别同一来源事件的更新、取消和缺失；不同订阅中的相同 UID 也不能互相合并。

数据边界：

- `CalendarSource` 保留名称、类型和版本；订阅扩展表保存加密 URL、URL HMAC、脱敏主机、刷新状态、周期、下次刷新时间、租约、连续失败数、最近尝试/成功/变化时间、响应验证器和成功内容摘要。
- `CalendarSubscriptionRefresh` 保存每次刷新状态、尝试编号、HTTP 元数据、错误码、数量和快照摘要，不保存 URL 查询、响应正文或日历正文。
- `CalendarSubscriptionEvent` 以 `source_id + UID + normalized RECURRENCE-ID` 唯一定位，保存当前来源字段、解析状态、首次/末次出现代次和来源取消生效边界。
- `CalendarSubscriptionOverride` 保存用户明确修改的字段及修改时看到的来源值。来源继续更新时保留覆盖，并返回来源旧值、新值和本地值。

来源事件不强制转换为当前有界 `CalendarSeries`。订阅可包含无限 RRULE，查询仍按统一 93 天窗口有界展开；无法安全表达的规则保留上一成功修订和错误，不静默简化。

## 2. 受限外部访问

用户提供的订阅 URL 属于不可信输入。抓取器遵循：

- 生产只接受 HTTPS；测试环境仅为隔离测试允许回环 HTTP。
- 拒绝 URL 用户信息、片段、控制字符、非允许端口和 IP 字面量。保留查询参数，但 URL 加密保存且不进入日志、错误或界面。
- 每一跳重新解析 A 和 AAAA。规范化 IPv4-mapped IPv6，只要结果中存在非公网单播地址就拒绝，包括私网、回环、链路本地、CGNAT、保留、多播、文档网段和云元数据地址。
- 从已验证地址中固定一个 IP 建立连接，同时使用原主机执行 Host 和 TLS SNI/证书校验；连接后核验 socket peer 地址。连接阶段不得再次按原主机自由解析，阻断 DNS rebinding。
- 最多 3 次重定向，每跳完整重验；禁止 HTTPS 降级。请求不读取系统代理，不携带浏览器 Cookie、平台 Authorization、AI Key 或其他用户凭据。
- 连接 3 秒、读取空闲 5 秒、单次总时长 15 秒。自动刷新和手动刷新共享账号及平台并发上限。
- 压缩体最多 2 MiB、解压体最多 4 MiB、压缩比最多 20。流式同时计数，不信任 `Content-Length`；仅接受 identity 或单层 gzip。
- 接受 `text/calendar`、`application/ics`；`text/plain` 仅在严格嗅探到完整 VCALENDAR 时接受。拒绝 HTML 登录页、未知类型和多重编码。

抓取器以可替换的解析器、DNS 解析器和连接器接口实现；单元测试可注入确定性网络结果，生产实现仍必须真实核验连接 peer。

## 3. 刷新状态与租约

创建来源和手动刷新只负责写入 `queued` 状态，由独立 worker 执行：

- worker 使用 `FOR UPDATE SKIP LOCKED` 领取到期来源，设置随机租约和递增尝试号后释放事务。
- 网络请求、解压和解析均在事务外进行；应用快照时重新锁定来源，并核对租约 ID、来源版本和尝试号。陈旧结果直接丢弃。
- 同一来源只有一个在途刷新。重复手动刷新返回现有作业状态，不并发抓取。
- 自动刷新使用可配置周期与抖动；失败采用有界退避，不能无限快速重试。
- `304 Not Modified` 是成功检查，只更新检查及成功时间。响应验证器只发送给产生它们的同一最终 URL，重定向到其他目标时不泄露。
- `200 OK` 只有在下载、解压、完整解析和事务应用均成功后才更新 ETag、Last-Modified、最终 URL 和内容摘要。
- 404、429、5xx、DNS、TLS、超时、类型、容量和解析错误均保留上次成功数据。界面显示最近成功时间、最近失败原因和可重试状态。

## 4. 来源修订与取消

完整成功快照按来源内身份键比较：

- 主事件以 UID 标识；单次覆盖和取消以 `UID + RECURRENCE-ID` 标识。规范化时保留时区和真实时间点语义。
- 同一快照出现相同身份键但内容不同，拒绝该身份键并保留旧版本；不能依赖 VEVENT 顺序选择一个。
- 可识别 UID 但字段或规则暂不支持时，记录项目错误并保留该 UID 的旧成功修订；不能把“本次未解析”当作删除。
- 主事件 `STATUS:CANCELLED` 或在完整成功快照中缺失表示来源删除。刷新生效时刻以前已经发生的 occurrence 保留，未来 occurrence 投影为 `source_cancelled`，不再占用时间。
- 单次 `STATUS:CANCELLED` 只取消对应 RECURRENCE-ID；来源单次移动或覆盖先于本地覆盖投影。
- UID 改变按旧事件来源取消、新事件创建处理。来源字段变化递增来源和事件版本，并发读取获得一致代次。

投影优先级固定为：

1. 来源主事件；
2. 来源 RECURRENCE-ID 覆盖或取消；
3. 用户字段级本地覆盖；
4. 用户 `CalendarException` 单次取消、移动或内容覆盖。

本地层最终优先。用户可逐字段“重置为来源”；重置只删除对应覆盖，不回写外部。

## 5. API 与界面

- `POST /api/v1/calendar/subscriptions`：名称、URL、刷新周期、操作 ID → 来源和首次刷新状态。
- `GET /api/v1/calendar/subscriptions`、`GET /{id}`：本人来源、状态、最近成功/失败和字段差异；只返回主机及省略路径和查询参数后的展示地址。
- `POST /{id}/refresh`：幂等排队或返回当前在途刷新。
- `PUT /{id}`：修改名称、URL 或周期；修改 URL 清除旧验证器并排队全量刷新。
- `PUT /{id}/events/{event_id}/overrides`：字段级本地覆盖或重置。
- `POST /{id}/pause`、`POST /{id}/resume`：暂停不删除现有历史；恢复后排队刷新。

订阅来源事件不允许经通用系列接口直接改写基线。来源停用或删除仍遵守业务对象 30 天回收站设计，不能以硬删除绕过历史与旧客户端防复活。

刷新引起未来固定时间变化后发出受影响 UTC 区间的同步变更。规划模块落地前仅返回日历冲突；计划模块完成后创建“待复核”冲突标记，不自动重排已经确认的计划。

## 6. 验证

- 网络：A/AAAA 混合、IPv4-mapped IPv6、解析后变私网、peer 不匹配、逐跳重定向、HTTPS 降级、代理环境变量、云元数据地址。
- 响应：chunked、伪造长度、gzip bomb、慢首包、慢流、错误 MIME、HTML、损坏和超限日历。
- 来源：200/304、ETag 隔离、UID/RID 更新与取消、缺失删除、过去保留、未来取消、无限 RRULE、有错误项目时保留旧值。
- 并发：双 worker、租约过期、进程中断、陈旧结果、重复手动刷新、URL 更新与旧刷新竞争。
- 本地变更：字段覆盖优先、来源差异展示、重置来源、单次例外优先、冲突保留。
- Web：创建、刷新、暂停、失败保留、差异处理和三视口真实浏览器流程。

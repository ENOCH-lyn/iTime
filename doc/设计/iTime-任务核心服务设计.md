# iTime 任务核心服务设计

版本：0.2；更新：2026-10-03。本文记录已实现的目标、项目、任务、步骤、截止时间、重复实例、拆分及任务生命周期服务。时间与重复细则见[时间、课表与重复规则设计](iTime-时间课表与重复规则设计.md)，归档、任务删除和回收站见[任务生命周期设计](iTime-任务生命周期设计.md)。

## 1. 已实现范围

### 项目与目标

`Project` 用 `kind=project|goal` 区分项目和目标，包含名称、说明、所有者、版本及创建/更新时间。它是任务的可选上级；没有上级的任务属于收集箱。当前支持创建、详情、搜索/分页列表和完整编辑，尚不提供删除或归档。

### 任务及资料

`Task` 包含名称、正文、可选项目、预计分钟数、优先级、完成状态、版本及时间。优先级当前 API 表示为 `0=未设置、1=低、2=中、3=高`；它是可调整的界面/存储合同，不推导截止或规划顺序。

任务资料仅包括正文和 HTTP(S) 链接；链接标题可选，单任务最多 20 条。公开网页读取和安全摘要属于 M4，不在保存链接时发起外部请求。用户填写的耗时标记为 `estimate_source=user`，后续 AI 建议必须标为 `ai`，两者不能混淆。

标签按账号隔离，以压缩连续空白并转小写后的名称去重；保留首次显示名称。单任务最多 10 个标签。步骤按连续位置排序，单任务最多 100 个；勾选步骤只更新步骤事实和任务版本，不自动完成任务。

任务完成通过独立接口由用户明确提交。归档与完成正交；删除进入 30 天回收站，期间完整保留并只读，到期清理正文和直接关联明细后保留最小墓碑。

### 截止、拆分与重复实例

`TaskSchedule` 与任务一一对应，区分无截止、日期型截止和定时截止。日期型截止保存日历日期及任务时区，以当地次日 `00:00` 的最早有效瞬间作为逾期边界；定时截止同时保存当地日期/时刻、IANA 时区和首个 UTC 时间点。用户修改时区不改写既有任务时间。

任务默认可拆，最小连续块为 15 分钟；也可标记不可拆或调整最小块。重复规则与日历系列使用同一套结构化算法和 366 次上限。`TaskOccurrenceState` 只在某次被完成、跳过、调期或作为补做创建时持久化；未操作实例按模板投影。状态保存步骤总数快照和完成步骤 ID，任务模板一旦存在实例状态便不再允许增删步骤，避免历史进度分母变化。

重复任务的模板 `Task.status` 保持未完成，普通单项/批量完成接口拒绝重复模板；每个 occurrence 必须由用户明确完成、重新打开或跳过。补做创建额外一次实例并保留来源 occurrence，不自动移动或完成原实例。

## 2. API

所有写接口要求有效用户 Cookie、CSRF、客户端生成的 UUID `operation_id`；更新还要求当前版本。输入使用禁止额外字段的结构化校验。

| 方法与路径 | 输入/输出 | 主要失败与恢复 |
| --- | --- | --- |
| `POST /api/v1/projects` | 类型、名称、说明 → 项目/目标 | 同操作可安全重试；复用编号提交不同内容返回 409 |
| `GET /api/v1/projects` | 搜索、类型、游标 → 含任务计数的列表 | 游标不完整或无时区返回明确错误 |
| `GET/PUT /api/v1/projects/{id}` | 本人详情/带版本完整编辑 | 他人或不存在统一 404；陈旧版本 409 |
| `POST /api/v1/tasks` | 基础字段、标签、链接、初始步骤 → 完整任务 | 上级必须属于本人；整次事务成功或回滚 |
| `GET /api/v1/tasks` | 生命周期、正文搜索、状态、项目/收集箱、优先级、标签、游标 → 摘要列表 | 默认只含活动任务；可切换已归档或回收站，稳定按更新时间和 ID 倒序分页 |
| `GET/PUT /api/v1/tasks/{id}` | 完整详情/带版本编辑 | 冲突返回当前版本；输入保留在客户端重试 |
| `PUT /api/v1/tasks/{id}/archive` | 归档或取消归档 → 完整任务 | 与完成状态独立；回收站任务须先恢复 |
| `DELETE /api/v1/tasks/{id}` | 带版本删除 → 30 天回收站任务 | 保留原归档状态与完整聚合，普通写入被阻断 |
| `POST /api/v1/tasks/{id}/restore` | 带版本恢复 → 删除前活动/归档范围 | 已过恢复期返回 410，不创建新任务替代墓碑 |
| `PUT /api/v1/tasks/{id}/completion` | 完成或重新打开 → 完整任务 | 只有此动作改变任务完成状态 |
| `POST/PUT/DELETE .../steps` | 新增、编辑/勾选、排序、移除步骤 | 均检查任务版本；排序必须提交当前完整步骤集合 |
| `POST /api/v1/tasks/actions/bulk` | 最多 100 个任务及各自版本 → 原子批量结果 | 完成/重开、优先级、项目、增删标签；任一冲突则全部不保存 |
| `GET /api/v1/labels` | 搜索 → 标签及任务计数 | 仅返回本人标签 |
| `GET/PUT /api/v1/tasks/{id}/schedule` | 截止类型、时区、重复、可拆及最小块 → 任务详情 | 写入使用任务版本和操作幂等；无日期默认值不制造空记录 |
| `GET /api/v1/task-occurrences` | 最多 93 天日期范围 → 有界实例列表 | 日期型不随显示时区漂移；定时型按 UTC 落入用户查看范围 |
| `PUT .../occurrences/status` | 实例版本、完成/打开/跳过及步骤进度 → 实例 | 不自动改变重复任务模板完成状态 |
| `PUT .../occurrences/schedule` | 单次调期日期/时刻 → 状态记录 | 保留原 occurrence key；DST 歧义需选 offset |
| `POST .../occurrences/makeup` | 来源 occurrence 和新日期/时刻 → 关联补做 | 原实例不自动改变；单模板最多 366 个补做 |
| `POST /api/v1/tasks/{id}/schedule/split` | 分界 occurrence、完整后继规则 → 前序与后继任务 | 原子克隆模板资料并迁移未来状态；一个前序最多一个直接后继 |

列表只返回步骤进度和链接数量，详情才返回完整步骤与链接，防止常规列表随正文规模膨胀。名称、正文、标签、链接和批量数量均有明确上限；普通 API 不执行外部网络或长事务。

## 3. 一致性、并发与恢复

- 每个本人写事务先锁定用户行，因此同账号多设备写入有确定顺序；批量任务再按 UUID 排序锁定，避免未来锁顺序变化引入死锁。
- 项目、任务和标签使用复合所有权外键。数据库拒绝把其他账号的项目、任务、步骤、链接或标签关联进当前账号。
- 任务所有字段、链接集合、标签集合和步骤状态共用任务 `version`。同版本只有一个并发写入成功，失败方取得 `current_version` 后刷新比较。
- `user_operations` 以 `(owner_id, operation_id)` 唯一保存请求摘要和原响应。同编号同内容在提交后丢失响应时返回原结果；同编号不同内容拒绝，避免误去重。
- 业务对象、操作记录和 `change_events` 在同一事务提交。变更事件是后续增量同步基础，本批不宣称完整离线冲突协议已实现。
- 数据库异常沿用统一 `saved=unknown` 合同；客户端应保留原 `operation_id` 重试同一请求，不能改编号后盲目重复创建。
- “本次及以后”拆分复制任务字段、步骤、链接和标签；未来 occurrence 状态迁移到后继任务，已完成步骤 ID 按模板步骤位置映射。旧任务规则只保留分界点之前的实例。
- 已到期的实例不能作为拆分点；同一前序任务不能顺序或并发产生多个直接后继。若数据库中已有拆分后继，`0009` 降级会明确拒绝，避免把后继静默暴露成普通任务。
- 生命周期变更会清空该任务此前幂等操作的缓存正文，但保留操作号、范围和请求哈希。同内容旧重试返回结果已过期且不会重新执行，不同内容仍拒绝复用编号。
- 任务清理进程按到期时间有界领取并使用 `FOR UPDATE SKIP LOCKED`。归档/回收站任务不进入项目和标签计数或日历 occurrence；到期清理保留任务 ID、所有者、版本和删除时间墓碑，重复任务后继外键保持有效。

## 4. 数据边界

任务名称最多 200 字符、正文最多 20,000 字符、步骤名称最多 300 字符、预计耗时 1—525,600 分钟。分页每次最多 100 条，批量操作最多 100 项。这些是防止单请求无界占用的工程限制，不代表产品对长期任务时长的解释。

搜索当前在账号范围内匹配任务名称和正文，并可叠加状态、项目、优先级和单标签过滤。初期规模目标下先采用数据库过滤；M8 使用真实历史量测量 P50/P95/P99 后再决定全文索引，不把尚未执行的性能结果写为已达标。

## 5. 已验证与待续

真实 HTTP/PostgreSQL 测试覆盖账号隔离、跨账号项目拒绝、项目/任务幂等重放、操作编号误用、标签去重、正文搜索、稳定分页、步骤增改排序删除、步骤完成不完成任务、用户明确完成、批量全成全败、同版本双设备竞争和同操作双设备并发创建。时间扩展另覆盖日期型日末、UTC 固化、用户改时区、DST 缺失/重复时刻、重复实例独立状态、步骤快照、跳过/补做、单次调期、孤儿保护及系列拆分。

生命周期专项另覆盖归档与完成正交、列表/计数过滤、回收站恢复原范围、跨账号与版本冲突、全部普通写入阻断、旧操作响应墓碑、日历隐藏、到期脱敏、重复任务前序外键、批量上限、双 worker 和独立进程。对应 Web 界面仍待下一批实现；关联计划、报告、困难、AI 日志和质检样本接入后还需扩展跨聚合清理，不因本批测试视为完整数据治理已经交付。

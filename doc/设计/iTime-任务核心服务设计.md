# iTime 任务核心服务设计

版本：0.1；更新：2026-10-02。本文记录 M3 第一批已实现的目标、项目、任务与步骤服务。重复、截止时间、拆分参数、归档、任务删除与回收站仍受 Q-TASK-01/Q-DATA-01 约束，不在本批实现中预设语义。

## 1. 已实现范围

### 项目与目标

`Project` 用 `kind=project|goal` 区分项目和目标，包含名称、说明、所有者、版本及创建/更新时间。它是任务的可选上级；没有上级的任务属于收集箱。当前支持创建、详情、搜索/分页列表和完整编辑，尚不提供删除或归档。

### 任务及资料

`Task` 包含名称、正文、可选项目、预计分钟数、优先级、完成状态、版本及时间。优先级当前 API 表示为 `0=未设置、1=低、2=中、3=高`；它是可调整的界面/存储合同，不推导截止或规划顺序。

任务资料仅包括正文和 HTTP(S) 链接；链接标题可选，单任务最多 20 条。公开网页读取和安全摘要属于 M4，不在保存链接时发起外部请求。用户填写的耗时标记为 `estimate_source=user`，后续 AI 建议必须标为 `ai`，两者不能混淆。

标签按账号隔离，以压缩连续空白并转小写后的名称去重；保留首次显示名称。单任务最多 10 个标签。步骤按连续位置排序，单任务最多 100 个；勾选步骤只更新步骤事实和任务版本，不自动完成任务。

任务完成通过独立接口由用户明确提交。任务尚无硬删除入口，避免绕过已确认的 30 天回收站规则。

## 2. API

所有写接口要求有效用户 Cookie、CSRF、客户端生成的 UUID `operation_id`；更新还要求当前版本。输入使用禁止额外字段的结构化校验。

| 方法与路径 | 输入/输出 | 主要失败与恢复 |
| --- | --- | --- |
| `POST /api/v1/projects` | 类型、名称、说明 → 项目/目标 | 同操作可安全重试；复用编号提交不同内容返回 409 |
| `GET /api/v1/projects` | 搜索、类型、游标 → 含任务计数的列表 | 游标不完整或无时区返回明确错误 |
| `GET/PUT /api/v1/projects/{id}` | 本人详情/带版本完整编辑 | 他人或不存在统一 404；陈旧版本 409 |
| `POST /api/v1/tasks` | 基础字段、标签、链接、初始步骤 → 完整任务 | 上级必须属于本人；整次事务成功或回滚 |
| `GET /api/v1/tasks` | 正文搜索、状态、项目/收集箱、优先级、标签、游标 → 摘要列表 | 稳定按更新时间和 ID 倒序分页 |
| `GET/PUT /api/v1/tasks/{id}` | 完整详情/带版本编辑 | 冲突返回当前版本；输入保留在客户端重试 |
| `PUT /api/v1/tasks/{id}/completion` | 完成或重新打开 → 完整任务 | 只有此动作改变任务完成状态 |
| `POST/PUT/DELETE .../steps` | 新增、编辑/勾选、排序、移除步骤 | 均检查任务版本；排序必须提交当前完整步骤集合 |
| `POST /api/v1/tasks/actions/bulk` | 最多 100 个任务及各自版本 → 原子批量结果 | 完成/重开、优先级、项目、增删标签；任一冲突则全部不保存 |
| `GET /api/v1/labels` | 搜索 → 标签及任务计数 | 仅返回本人标签 |

列表只返回步骤进度和链接数量，详情才返回完整步骤与链接，防止常规列表随正文规模膨胀。名称、正文、标签、链接和批量数量均有明确上限；普通 API 不执行外部网络或长事务。

## 3. 一致性、并发与恢复

- 每个本人写事务先锁定用户行，因此同账号多设备写入有确定顺序；批量任务再按 UUID 排序锁定，避免未来锁顺序变化引入死锁。
- 项目、任务和标签使用复合所有权外键。数据库拒绝把其他账号的项目、任务、步骤、链接或标签关联进当前账号。
- 任务所有字段、链接集合、标签集合和步骤状态共用任务 `version`。同版本只有一个并发写入成功，失败方取得 `current_version` 后刷新比较。
- `user_operations` 以 `(owner_id, operation_id)` 唯一保存请求摘要和原响应。同编号同内容在提交后丢失响应时返回原结果；同编号不同内容拒绝，避免误去重。
- 业务对象、操作记录和 `change_events` 在同一事务提交。变更事件是后续增量同步基础，本批不宣称完整离线冲突协议已实现。
- 数据库异常沿用统一 `saved=unknown` 合同；客户端应保留原 `operation_id` 重试同一请求，不能改编号后盲目重复创建。

## 4. 数据边界

任务名称最多 200 字符、正文最多 20,000 字符、步骤名称最多 300 字符、预计耗时 1—525,600 分钟。分页每次最多 100 条，批量操作最多 100 项。这些是防止单请求无界占用的工程限制，不代表产品对长期任务时长的解释。

搜索当前在账号范围内匹配任务名称和正文，并可叠加状态、项目、优先级和单标签过滤。初期规模目标下先采用数据库过滤；M8 使用真实历史量测量 P50/P95/P99 后再决定全文索引，不把尚未执行的性能结果写为已达标。

## 5. 已验证与待续

真实 HTTP/PostgreSQL 测试覆盖账号隔离、跨账号项目拒绝、项目/任务幂等重放、操作编号误用、标签去重、正文搜索、稳定分页、步骤增改排序删除、步骤完成不完成任务、用户明确完成、批量全成全败、同版本双设备竞争和同操作双设备并发创建。

后续在 M3 继续：Q-TASK-01 定稿后的截止/重复/拆分/归档，30 天回收站，语音转写与 AI 预览确认，以及课表、例外、Excel/ICS/截图导入和日历 UI。当前测试通过不表示这些范围已经实现。

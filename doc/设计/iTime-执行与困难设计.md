# iTime 执行与困难设计

版本：0.1；更新：2026-10-03。本文细化 `REQ-EXEC-01`、`REQ-DIFF-01` 及执行范围内的 `REQ-SYNC-01`、`REQ-TIME-01`，定义 Web 首版专注计时、任务步骤、补记修订、困难记录和离线恢复合同。本文中的开放会话范围、倒计时归零、陈旧会话提示和关联粒度是用户授权代理自行决定后的可演进工程默认，不表述为用户原始决定。

## 1. 范围与方案选择

本阶段交付：

- 独立 `/focus` 页面和六项产品导航，可从任务、当前计划块或自由标题开始专注。
- 正计时、倒计时、暂停、恢复、结束和放弃；刷新、关闭页面和换设备后从服务端恢复。
- 一个账号最多一个开放专注。`running` 和 `paused` 都视为开放，用户须结束或放弃后才能开始另一项。
- 关联任务步骤可在专注中勾选，但步骤完成与任务完成保持独立；结束专注后由用户明确选择是否完成任务或任务实例。
- 已结束专注的补记和修订；原始状态事件不可改写，修订保存前后值和原因。
- 已加载专注在离线时可继续显示计时，并排队暂停、恢复、结束、放弃和步骤操作；恢复联网后按原操作号顺序对账。
- 一句话困难，可选分类、情绪、一个任务和一次专注关联；支持编辑、删除、恢复和 30 天到期清理。
- “带到 AI 对话”只打开带困难上下文的对话草稿，用户再次提交才产生 AI 作业和额度消耗。

本阶段不交付：

- 自动根据倒计时或步骤状态完成任务。
- 多个暂停会话、多人共享计时、番茄组循环、环境音、排行榜或激励系统。
- 语音转写、后台提醒、Web Push 或浏览器关闭后的本地闹钟。
- 基于困难自动调用 AI、自动修改计划或自动生成心理/情绪判断。
- 通用跨业务同步协议；本阶段只实现执行页所需的有界离线操作队列。

比较过三种实现：

1. **当前状态投影 + 不可变事件 + 修订快照（采用）**：列表和当前计时读取简单，同时能还原暂停、恢复、离线重放及人工修订，符合现有版本和操作幂等模式。
2. 只保存一行可变开始/结束时间：表少，但并发、暂停区间、未知保存状态和修订历史无法可靠审计。
3. 完全事件溯源：事实最完整，但每次列表和状态读取都需重放，首版复杂度和迁移成本超过收益。

## 2. 核心不变量

1. 同一账号至多一个 `running` 或 `paused` 专注。暂停不会释放开始另一项的资格，避免遗留多份可恢复会话。
2. 状态只允许 `running → paused → running`，并由 `running|paused → finished|abandoned` 进入终态。终态不可恢复为开放状态。
3. 开始、暂停、恢复、结束和放弃都写不可变事件；`FocusSession` 当前字段是同一事务内更新的查询投影。
4. 正计时和倒计时只改变展示及目标值。倒计时到零后继续显示超时，不自动结束专注，也不自动完成任务。
5. 服务端时间是在线操作的权威时间。离线事件可携带客户端记录时间，但必须晚于前一事件、不晚于服务端当前时间 5 分钟以上，且按会话版本和操作号有序应用。
6. 页面定时器只根据服务端快照、`server_now` 和当前开放区间计算，不逐秒写数据库。
7. 计划块、任务步骤、任务完成和专注事实相互独立。计划变化不改写已开始的专注；步骤全完成和专注结束都不隐式完成任务。
8. 已结束或放弃的专注才允许人工修订。原始事件和原始时长保留，当前有效起止和有效时长由最新修订覆盖。
9. 困难内容只保存用户输入。分类和情绪均可空，不从正文推断；一个记录最多关联一个任务和一次专注，也可完全独立。
10. 所有者从认证会话取得。跨账号任务、计划块、专注或困难 ID 统一返回不存在，不泄露对象状态。
11. 所有写操作使用全账号 `operation_id`。相同操作重放返回原结果，相同 ID 携带不同内容拒绝。
12. 困难删除后 30 天内只读且可恢复；到期清空正文、分类、情绪和关联快照，保留最小墓碑阻止旧操作复活。

## 3. 数据模型

### 3.1 FocusSession

`focus_sessions` 保存当前状态和历史展示快照：

- `id`、`owner_id`
- `source=timer|manual`
- 可选 `task_id`、`occurrence_key`、`scheduled_block_id`
- `title_snapshot`、`task_title_snapshot`、`step_snapshots`
- `mode=stopwatch|countdown`
- 倒计时 `target_seconds`；正计时必须为空
- `status=running|paused|finished|abandoned`
- 原始 `started_at`、可选 `ended_at`
- 当前运行段 `active_started_at`；暂停和终态为空
- 已关闭运行段累计 `accumulated_seconds`
- 当前有效 `effective_started_at`、`effective_ended_at`、`effective_duration_seconds`
- 冻结的 IANA `time_zone`
- `version`、`created_at`、`updated_at`

数据库检查约束保证模式/目标、状态/时间和非负时长一致。`owner_id` 与关联任务、计划块使用复合外键；标题与步骤快照使后续任务改名、步骤删除或计划换版不改写执行历史。部分唯一索引在 `status IN ('running', 'paused')` 时按 `owner_id` 唯一，应用同时锁定用户行，避免并发开始竞态。

`effective_*` 在正常结束时由原始事件计算；人工补记直接创建终态会话并填入有效值；修订只更新有效值，不覆盖原始事件。实时会话不自动截断；超过 12 小时返回 `attention_required=true`。手工补记和修订的单次有效时长限制为 24 小时，异常长的实时会话结束后可由用户据实修订。

### 3.2 FocusEvent

`focus_events` 是不可变状态事实：

- `id`、`owner_id`、`focus_session_id`
- 单调 `sequence`
- `kind=start|pause|resume|finish|abandon|progress|task_completed`
- 权威 `occurred_at`
- 可选 `client_recorded_at` 与 `source=online|offline`
- 有界 `details` JSON，仅保存步骤 ID、任务/实例版本等结构化元数据
- `created_at`

`(focus_session_id, sequence)` 唯一。状态事件与会话版本在同一事务提交；离线重放仍使用原 `operation_id`，因此响应丢失不会重复累计时长。事件不保存困难正文或任意客户端键值。

### 3.3 ExecutionRevision

`execution_revisions` 保存人工修订：

- `id`、`owner_id`、`focus_session_id`
- `session_version`
- `before_data`、`after_data`
- 必填 `reason`，1—500 字
- `created_at`

允许修改终态会话的标题、任务/实例关联、有效开始、有效结束和有效时长。开始/结束必须是带时区时间点，结束不晚于服务端当前时间 5 分钟以上，有效时长为 0—24 小时。服务端检查同一用户其他专注的有效区间；存在重叠时拒绝并返回冲突会话 ID，不静默制造双重专注统计。

### 3.4 DifficultyRecord

`difficulty_records` 保存：

- `id`、`owner_id`
- 可选 `task_id`、`focus_session_id`
- 可选 `occurrence_key`
- `content`，1—2000 字
- 可选 `category`、`emotion`，各 40 字；界面给出常用建议但允许用户自填
- `occurred_at`、冻结 `time_zone`
- `deleted_at`、`purge_after`、`purged_at`
- `version`、`created_at`、`updated_at`

关联专注时，任务与实例必须和该专注一致；关联任务但不关联专注时，任务必须属于本人且未清理。删除固定在服务端时间后 30×24 小时到期；删除、恢复和到期清理都产生变化事件。到期后普通读取返回 `410 difficulty_purged`。

`ChangeEvent.entity_type` 扩展 `focus_session|difficulty`，动作扩展 `started|paused|resumed|finished|abandoned|revised`。步骤和任务完成仍沿用原任务变化事件。

## 4. 状态与计时算法

### 4.1 开始

开始请求可包含任务、任务实例或当前计划块：

1. 锁定用户行，查询现有开放专注。
2. 如已存在，返回 `409 focus_session_active` 和本人当前会话摘要。
3. 校验任务处于活动且未完成状态；实例必须为开放状态；计划块必须属于本人当前计划版本。
4. 冻结任务标题、关联步骤和时区，写 `FocusSession(status=running)` 与 `start` 事件。
5. 保存操作结果和 `focus_session` 变化事件后提交。

不关联任务时必须提供 1—200 字标题。开始请求不接受过去时间；历史记录使用补记入口。

### 4.2 暂停、恢复和终止

每次状态转换锁定会话并检查 `expected_version`：

- 暂停：`accumulated_seconds += occurred_at - active_started_at`，清空 `active_started_at`。
- 恢复：保持累计时长，设置新的 `active_started_at`。
- 结束/放弃：如当前运行先累计最后区间，写终态和 `ended_at`，再生成有效起止与时长。

秒数按实际 UTC 时间差计算，避免 DST 当地时刻造成重复或缺失。相同操作号重放不再次累计。版本冲突返回当前会话、最后事件和请求编号。

倒计时剩余：

```text
elapsed = accumulated_seconds + max(0, server_now - active_started_at)
remaining = target_seconds - elapsed
```

`remaining > 0` 显示剩余时间；`remaining <= 0` 显示超时 `abs(remaining)`。跨过零点只改变展示，不产生隐式服务端事件。

### 4.3 步骤与任务完成

`PUT /focus-sessions/{id}/progress` 接受步骤 ID 集合和任务/实例预期版本：

- 非重复任务更新 `TaskStep.completed`，并递增任务版本。
- 重复任务更新对应 `TaskOccurrenceState.completed_step_ids`，不改模板步骤。
- 会话记录 `progress` 事件并递增版本，但不改变计时状态。
- 已归档、回收站、已清理、已完成或已跳过任务拒绝更新。

终态会话提供独立“完成任务”动作。非重复任务复用任务完成合同，重复任务复用实例状态合同；动作成功后写 `task_completed` 事件，但不改变已记录的专注时长。用户可结束专注而不完成任务。

### 4.4 补记和修订

补记创建 `status=finished`、`source=manual` 的会话，写 `start` 和 `finish` 两个事件；不占用开放会话名额。服务端按用户时区解析本地时间，DST 重复时刻要求 UTC 偏移，缺失时刻拒绝，不静默平移。

修订创建 `ExecutionRevision` 并更新 `effective_*`。列表同时返回“原始记录 / 已修订”标记和最近修订摘要。任何计划版本变化都不影响执行事实；后续复盘和统计默认读取有效值，并可追溯原始事件和修订。

## 5. 离线与并发恢复

Web 不缓存新专注请求。只有已从服务端加载且属于当前账号的开放会话可进入离线模式。

客户端按用户和会话隔离保存有界队列：

```text
itime-focus-queue:{user_id}:{focus_session_id}
```

每项包含操作号、动作、客户端记录时间、预期会话版本，以及进度动作所需的任务/实例版本。正文、Cookie、CSRF 和困难内容不写入该队列。最多保留 100 项和 7 天；超过限制停止新增并要求联网。

离线时：

- 计时根据最近服务端锚点继续显示。
- 暂停、恢复、结束、放弃和步骤勾选立即更新本地投影并入队。
- 新专注、补记、修订、困难写入和任务完成不可离线发起。
- 页面明确显示待同步数量和最后服务端时间，不把本地状态声称为已保存。

联网、页面重新获得焦点或重新进入时，客户端按顺序用原操作号重放。成功后删除对应项；响应未知时先重放同一项；版本冲突时停止后续项并保留整个剩余队列。用户可：

- 采用服务端状态并明确丢弃本地待同步操作；
- 在当前服务端状态仍允许时，以新预期版本重新应用下一项；
- 服务端已进入终态时，将本地时间作为修订草稿检查后保存。

切换账号、会话撤销或账号停用时不向新账号重放旧队列；旧队列保留到原账号重新认证或 7 天到期。

## 6. 困难记录与 AI 帮助

困难可在专注中或独立创建。创建和编辑校验正文长度、可选标签、发生时间、任务/专注关系及版本。列表按发生时间和 ID 稳定分页，可按活动/回收站、任务、分类和日期范围过滤；查询范围最多 93 天。

删除后默认列表隐藏，回收站可恢复。恢复重新校验关联对象；关联任务已清理时保留无关联记录和原任务标题快照，避免恢复失败或暴露旧正文。清理 worker 使用 `FOR UPDATE SKIP LOCKED` 每批 100 条处理，支持多进程和幂等重试。

“带到 AI 对话”流程：

1. 用户在困难记录上明确点击。
2. 浏览器只把困难 ID 放入 `/ai?difficulty=<id>`，不把正文写入 URL。
3. AI 页面鉴权读取本人记录，将正文、用户填写的分类/情绪和关联任务标题放入输入草稿。
4. 用户可修改或取消；只有再次点击发送才创建普通 `conversation` 作业并预留额度。

服务端不从困难内容推断情绪、诊断或自动触发 AI。首版不建立 AI 对困难记录的写回关系。

## 7. API

| 方法与路由 | 作用 |
| --- | --- |
| `GET /api/v1/focus-sessions/current` | 当前开放专注、服务端时间、任务步骤和待关注状态 |
| `GET /api/v1/focus-sessions` | 按状态、日期和稳定游标读取本人历史 |
| `POST /api/v1/focus-sessions` | 在线开始正计时或倒计时 |
| `POST /api/v1/focus-sessions/manual` | 补记一条已结束专注 |
| `GET /api/v1/focus-sessions/{id}` | 读取会话、事件、修订和任务上下文 |
| `POST /api/v1/focus-sessions/{id}/transitions` | 暂停、恢复、结束或放弃，支持离线时间重放 |
| `PUT /api/v1/focus-sessions/{id}/progress` | 原子更新关联任务步骤并记录执行事件 |
| `POST /api/v1/focus-sessions/{id}/complete-task` | 用户明确完成关联任务或实例 |
| `PUT /api/v1/focus-sessions/{id}` | 修订终态专注的有效事实 |
| `GET /api/v1/difficulties` | 分页筛选本人困难和回收站 |
| `POST /api/v1/difficulties` | 创建困难 |
| `GET /api/v1/difficulties/{id}` | 读取本人困难 |
| `PUT /api/v1/difficulties/{id}` | 版本化编辑 |
| `DELETE /api/v1/difficulties/{id}` | 移入 30 天回收站 |
| `POST /api/v1/difficulties/{id}/restore` | 从回收站恢复 |

成功响应包含 `operation_id`、对象当前版本和 `server_now`。错误继续使用统一 `{code, message, request_id, saved, retryable, details}`；版本冲突 details 返回本人当前对象，不返回其他用户或已清理正文。

## 8. Web 交互

`/focus` 采用工作台而非营销页：

- 桌面左侧为当前专注与启动条件，中间为稳定尺寸的大计时器和状态动作，右侧在“步骤 / 困难”间切换。
- 平板将当前专注置顶，步骤和困难并排；手机使用单列，计时器、主动作、步骤、困难、历史依次出现。
- 无开放会话时可从近期任务、当天计划块或自由标题开始；模式使用分段控件，倒计时分钟使用数字输入与步进按钮。
- 状态动作使用熟悉的播放、暂停、停止图标并提供 tooltip；结束和放弃是不同命令，放弃需确认。
- 倒计时归零后使用中性“已超出目标”状态，继续显示正向超时时长。
- 页面显示“已保存 / 待同步 / 冲突”真实状态。未知保存使用原操作号对账，离线队列冲突不自动丢弃。
- 结束摘要分别显示专注时长、步骤状态和任务状态；完成任务是独立按钮。
- 历史列表按真实日期展示，修订项标记“已修订”；详情可查看暂停段和修订原因。
- 困难输入以一句话为主，分类和情绪为可选字段；删除和恢复使用明确确认。

任务详情和日历计划块详情增加“开始专注”入口，只传对象 ID 到 `/focus`。六项产品导航为 AI、任务、规划、日历、专注、设置；窄屏隐藏文字但保留至少 44px 命中区和可访问名称。

## 9. 安全、容量与恢复

- 列表范围最多 93 天、每页最多 100 条；事件和修订仅在单会话详情加载。
- 单会话最多 10,000 个事件，达到上限后必须结束或修订，防止异常客户端无限写入。
- 转换事务不执行网络调用；用户行、会话、任务的锁顺序固定为用户 → 会话 → 任务 → 实例，避免跨端死锁。
- 当前会话查询不依赖浏览器时间。陈旧提示仅提醒用户核对，不自动改变事实。
- 离线时间只影响个人执行记录，不参与额度、安全令牌或服务端活动日判定；服务器保留接收时间和客户端时间。
- 困难正文不进入普通日志。AI 带入发生在用户可见草稿，发送后按普通对话 7 天技术正文、30 天可选质检规则处理。
- 账号删除时执行、困难、事件和修订级联删除；任务进入回收站时现有执行与困难保留标题快照，但不允许再通过其修改任务。

## 10. 测试与完成标准

服务端使用真实 PostgreSQL 和 Uvicorn 覆盖：

- 迁移往返、状态/时间检查、复合所有权、单开放会话唯一和用户级联删除。
- 双连接同时开始、暂停/结束竞态、操作重放、同 ID 异内容、版本冲突和事务回滚。
- 正计时、倒计时归零后超时、多个暂停段、放弃、12 小时陈旧提示和 24 小时修订上限。

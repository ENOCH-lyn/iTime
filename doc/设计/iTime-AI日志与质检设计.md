# iTime AI 日志与质检设计

版本：0.1；更新：2026-10-03。本文在现行需求 `REQ-PRIV-01`、`REQ-PRIV-02` 和 `REQ-ADMIN-01` 之上，冻结 Web 首版 AI 技术正文日志、质量样本、用户退出开关、管理员正文访问审计及到期清理合同。每日金额额度的成功结算时点仍未定案，本模块不得创建扣额记录或把质量采样等同于计费成功。

## 1. 范围与方案

本模块交付：

- 每次真实供应商尝试一条独立技术正文日志，默认保存 7 天。
- 每个最终成功 AI 作业至多一份独立质量样本，默认保存 30 天。
- 用户默认参与质量改进，可关闭或重新开启；关闭只阻止随后提交的新样本。
- 超级管理员可分页查看日志和样本元数据，显式选择用途后读取正文。
- 每次正文披露和质检结论都写管理审计；审计失败时不返回正文。
- 两类正文独立、幂等、限批清理，支持多个清理进程并发和 `--once` 运维执行。

比较过三种存储方案：

1. **独立日志、样本和偏好表，按尝试记录日志（采用）**：能保留失败重试的独立证据，7 天日志删除不影响 30 天样本，访问权限和清理边界明确。
2. 在 `AIJobAttempt` 上直接增加正文字段：表较少，但尝试元数据需要长期保留时无法独立清理正文，普通作业查询也更容易误取敏感字段。
3. 每个作业只保存一份最终快照：实现最简单，但重试会覆盖前次部分输出，不能支持实际故障定位。

质量样本首版对所有符合条件的成功作业采样，不引入未确认的随机比例。后续若增加采样率，只能减少已同意用户的新样本，不能绕过终态时的开关复核。

## 2. 数据对象

### 2.1 UserPrivacySetting

每个账号一行：

- `owner_id`：主键并外键到用户，账号清理时级联删除。
- `quality_improvement_enabled`：默认 `true`。
- `version`：从 1 开始，保护多端并发修改。
- `created_at`、`updated_at`。

迁移为现有账号回填默认行；注册和本机管理员创建事务同步创建。读取或采样发现缺失行时按数据异常处理：用户设置接口可补建默认行，采样侧停止采样并记录不含正文的普通错误日志，不因缺失记录重新推定同意。

### 2.2 AIBodyLog

每次 `AIJobAttempt` 对应至多一条日志：

- `id`、`job_id`、`owner_id`、`attempt_number`、`capability`。
- `request_body`：清理过的 JSON 对象；不含 Authorization、Cookie、平台 Key、原始异常或截图 base64。
- `response_body`：已持久化的模型文本；流式对话按分段追加。
- `status`：与尝试状态一致，包括 `running`、`succeeded`、`retryable_failed`、`failed`、`timed_out`、`cancelled`、`abandoned`。
- `error_code`、`error_stage`、`provider_request_id`、`http_status`。
- `started_at`、`request_prepared_at`、`finished_at`、`expires_at`。

`(job_id, attempt_number)` 唯一并关联尝试，`(job_id, owner_id)` 关联作业。领取真实尝试时先创建不含正文的占位日志；输入组装完成后再填充请求快照。日志到期以尝试开始时间加配置保留天数计算，默认 7 天。

对话请求保存实际发送的系统消息、冻结历史、模型和受限参数。截图请求只保存系统提示、文字提示、识别上下文、媒体类型和“原图已省略”标记；不得复制图片字节、data URL 或 base64。响应只保存可作为模型正文识别的内容，不保存未知上游错误页。

### 2.3 AIQualitySample

每个最终成功作业至多一条样本：

- `id`、`source_job_id`、`source_body_log_id`、`owner_id`、`capability`。
- 独立复制的 `request_body` 和 `response_body`，不依赖 7 天日志继续存在。
- `status` 为 `pending` 或 `reviewed`。
- `outcome` 为 `acceptable` 或 `needs_improvement`，未评审时为空。
- `review_notes`、`reviewed_by_user_id`、`reviewed_at`、`version`。
- `sampled_at`、`expires_at`，默认 30 天。

`source_job_id` 唯一，防止租约恢复或重复终态提交产生双份样本。样本只用于人工质检、提示词优化和效果评测，不进入训练数据导出或训练任务。

### 2.4 SecurityEvent 扩展

现有 `security_events` 增加 JSON 对象 `details`，保存审计元数据，不复制正文。管理员正文访问至少记录：

- 管理员账号和管理会话 ID。
- 资源类型、资源 ID、目标用户 ID。
- 用途和结果。
- 请求编号、访问时间。

成功披露使用 `ai_body_log_accessed` 或 `ai_quality_sample_accessed`；不存在的目标使用对应 `*_access_denied`。质检结论使用 `ai_quality_sample_reviewed`。管理员账号删除后现有外键可能把操作者 ID 置空，首版审计列表仍保留动作、目标、请求编号和详情；审计元数据长期保留期继续按 `Q-ADM-01` 待运营配置，不在本模块擅自删除。

## 3. 用户设置 API

| 方法与路径 | 输入与输出 | 主要失败 |
| --- | --- | --- |
| `GET /api/v1/privacy-settings` | 当前本人完整设置 | 未认证、设置暂不可用 |
| `PUT /api/v1/privacy-settings` | `operation_id`、`expected_version`、质量改进开关 → 新快照 | CSRF、版本冲突、操作号复用 |

写入复用 `UserOperation`。相同操作号和相同内容返回原结果；相同操作号用于不同内容返回冲突。值未变化不增加版本，但仍保存幂等响应。实际变化写 `ChangeEvent(entity_type=privacy_settings, action=updated)`，供后续统一同步读取。

关闭不删除业务消息、7 天技术日志或已有质量样本；重新开启只影响开启事务之后提交的新成功作业。UI 只有收到服务端确认后才显示“已生效”；网络未知状态先重新读取，不乐观覆盖。

## 4. 作业与采样事务

### 4.1 尝试开始和流式正文

领取作业的事务按 `AIJob → AIJobAttempt → AIBodyLog` 创建尝试及日志占位。租约过期重领时，前一个尝试和日志先标为 `abandoned`，新尝试创建新日志。

worker 组装真实供应商请求后，在仍持有有效租约的短事务中写入清理后的 `request_body`。网络调用期间不持有数据库事务。对话每次持久化 `content_delta` 时，在同一事务把相同增量追加到当前日志；旧租约或旧 generation 不能更新日志。

### 4.2 成功、失败、超时和取消

所有尝试终态同时更新对应日志的状态、错误阶段、上游请求编号和 HTTP 状态：

- 成功：以校验后的最终模型正文覆盖日志响应，完成业务结果后再判断质量采样。
- 最终失败或超时：保留数据库已持久化的部分响应；不保存原始异常消息。
- 可重试失败：完成当前日志，后续尝试使用新日志。
- 取消：保留取消事务前已提交的部分响应，晚到输出因租约不匹配不能写入。
- 租约过期：旧尝试和日志标记 `abandoned`，旧 worker 不能完成或采样。

领取阶段不得直接把对话作业写成终态。已过总截止时间或已耗尽尝试的作业由 worker 取得短终结租约后进入能力对应的统一失败流程，保证 assistant 消息、事件、日志和作业终态一致。

### 4.3 质量采样

质量样本仅在作业最终成功事务中创建。锁顺序固定为：

```text
AIJob → 能力投影对象 → AIBodyLog → UserPrivacySetting
```

采样前以 `FOR UPDATE` 重新读取偏好：

- 开关为 `true`：复制最终尝试日志的请求和响应，依靠 `source_job_id` 唯一约束保证一次。
- 开关为 `false` 或偏好行缺失：不创建样本。
- 失败、超时、取消、可重试失败和废弃尝试：不创建样本。

偏好更新和采样竞争时，以偏好行锁的提交顺序为边界：样本先提交属于关闭前已有样本；关闭先提交则该作业不得新增样本。

## 5. 管理 API 与访问审计

| 方法与路径 | 行为 |
| --- | --- |
| `GET /api/v1/admin/ai-body-logs` | 按能力、状态、用户和稳定游标列出元数据，不返回正文 |
| `POST /api/v1/admin/ai-body-logs/{id}/access` | 用途固定为技术排障，校验管理 CSRF，记录审计后返回正文 |
| `GET /api/v1/admin/ai-quality-samples` | 按能力、评审状态、结果和稳定游标列出元数据 |
| `POST /api/v1/admin/ai-quality-samples/{id}/access` | 选择人工质检、提示词优化或效果评测，审计后返回正文 |
| `PUT /api/v1/admin/ai-quality-samples/{id}/review` | 预期版本、结论和可选备注 → 新评审快照 |
| `GET /api/v1/admin/audit-events` | 按动作、操作者和稳定游标读取审计元数据 |

正文访问采用 POST，禁止浏览器预取和缓存。每次实际披露都记录一条事件，不按请求去重。访问事务先完成管理员认证和 CSRF，再查询资源并写审计；审计提交成功后才返回正文。若目标不存在，事务先提交 `access_denied`，离开事务后再返回 404，避免异常回滚审计。

列表不返回请求或响应摘要，避免“元数据页面”成为隐式正文披露。普通用户 API 不暴露日志、样本或审计对象；管理员 API 只接受独立管理会话。

## 6. 到期清理与容量

独立 `python -m itime.ai.retention_worker` 支持常驻和 `--once`：

- 每类最多锁定 500 条到期记录，按 `(expires_at, id)` 排序并使用 `FOR UPDATE SKIP LOCKED`。
- 日志和样本分别删除；删除 7 天日志不级联删除 30 天样本。
- 崩溃使当前事务整批回滚，下次安全重试；多个 worker 可并行而不重复计数。
- 有积压时继续下一批，空批次休眠 60 秒。
- 只记录删除数量和错误类型，不记录正文、用户邮箱或原始异常。

账号注销模块接入时必须优先按 `owner_id` 删除日志、样本和偏好。当前尚无单条会话永久删除入口，未来实现时须依据 `Q-PRIV-01` 决定是否立即清除关联日志和样本；本模块不提前改变已确认的 7/30 天默认期限。

请求 JSON 与响应文本分别限制为 1 MiB；超过上限的作业按稳定校验错误终止，不以截断正文冒充完整日志。列表每页最多 100 条，正文详情单条读取。

## 7. Web 交互

用户设置新增“隐私与质量”页面：

- 使用复选开关显示当前服务器状态。
- 明确说明用途为人工质检、提示词优化和效果评测，不用于训练。
- 明确说明关闭只影响后续样本，已有样本最长 30 天；7 天技术正文日志不受影响。
- 保存中禁用重复提交；版本冲突、网络未知状态和请求编号使用统一错误组件展示。

后台新增“AI 日志”“质检”“审计”三个入口：

- 日志和质检列表只显示状态、能力、时间、到期时间、目标账号及技术标识。
- 点击查看正文后先选择或确认用途；正文置于明确的敏感内容区域，关闭或切换条目时从页面状态清空。
- 质检可提交“可接受/需改进”和可选备注，版本冲突后刷新，不覆盖另一管理员结论。
- 审计页只显示元数据，不展示正文。

桌面、平板和手机均使用现有设置页的全宽内容区，不在卡片中再嵌套卡片。长请求、响应、邮箱、UUID 和请求编号可换行，320px 大字号不得产生横向溢出。

## 8. 验证

服务端使用真实 PostgreSQL、真实 Uvicorn 和本地 OpenAI 兼容 HTTP 服务验证：

- 迁移升级、模型漂移、带正文数据的降级拒绝。
- 默认参与、关闭、重新开启、操作重放、版本冲突和双账号隔离。
- 对话与截图的成功、失败、超时、取消、重试、租约失效和领取阶段终结。
- 日志每次尝试独立，旧 worker 不能追加；每个成功作业最多一份样本。
- 关闭与成功提交并发时，以偏好锁顺序决定是否有样本。
- 正文中不存在 Key、Authorization、Cookie 或截图 base64。
- 管理员元数据列表不泄露正文；每次成功/失败访问和质检结论均可从审计查询。
- 日志 7 天、样本 30 天边界，双清理 worker 分批并发，以及独立进程 `--once`。

Web 使用生产构建和真实 Chromium 验证：

- 用户查看默认状态、关闭、重开、跨标签版本冲突、网络失败恢复。
- 管理员分页筛选、显式正文访问、用途审计、质检提交和审计回查。
- 正文不预取、切换后清空、管理会话失效、请求编号和保存状态。
- 桌面、平板、手机、320px 大字号、键盘、焦点、减少动效、axe、控制台和横向溢出。

本模块通过不代表每日额度、AI 业务提案、注销清理或完整 Web 首版通过。

## 9. 已实现合同

迁移 `0018_ai_governance`、`server/src/itime/ai/governance_*.py`、AI worker 终态接入、`retention_worker.py`、用户隐私设置页及后台日志/质检/审计页面已实现本文范围：

- 每次真实供应商尝试分别保存已清理请求和已提交响应；重试、失败、取消、租约失效及排队超时不会绕过对应终态投影。
- 对话与截图成功事务重新锁定用户隐私设置，默认创建一份 30 天样本；关闭先提交时不创建新样本。
- 截图日志只保存媒体类型、大小、摘要和省略标记，不复制 base64 原图；Key、Authorization 和 Cookie 不进入正文表。
- 超级管理员以独立会话和 CSRF 显式读取正文，读取成功及目标不存在均先提交审计；元数据列表不返回正文或自由文本评审备注。
- 独立清理进程按 7 天日志和 30 天样本分别使用 `FOR UPDATE SKIP LOCKED` 限批删除，样本不依赖技术日志继续存在。

服务端全量 195 项及 Chromium 全量 126 项回归已通过；专项证据、命令和截图路径见[Web 实施与验证](../验收/iTime-Web实施与验证.md)。

# iTime PRD 分析与缺口

更新：2026-10-02。本文比较[原始 PRD](原始PRD-V1.0.md)与[现行需求规格](iTime-需求规格说明书.md)，用于解释产品规则的变化。原文保持不变，开发以现行规格为准。

## 1. 原文各模块的处理结论

| 原文位置 | 原有问题 | 当前处理及设计影响 |
| --- | --- | --- |
| 版本/产品形态 | 暂定品牌，仅写手机 App | 统一 iTime；完整 Web 用户端和后台先发，再 Android、iOS |
| 用户与场景 | 强依赖高校课表 | 学生优先兼容通用个人使用；无课表可直接整理任务和规划 |
| 信息架构 | 今日为主页，缺账号和全局助手 | 全局 AI 对话为主入口，保留独立任务、课表、日历、执行、复盘和设置页面 |
| 原优先级 | 同步、周月统计后置 | 首版 Web 提供完整范围；研发按模块分阶段，正式版不以演示替代 |
| 导入 | 四种入口无识别纠错与来源语义 | 保留截图、Excel、手工、ICS/订阅；预览校对，来源只读，失败保留上次成功数据 |
| 课表 | 每周重复不足以表达学期 | 支持学期、节次、单双周、指定周和例外，固定区间参与约束校验 |
| 任务分类 | 强制想做/要做 | 统一任务；项目或目标 → 任务 → 步骤，无任务间依赖 |
| 任务属性 | 跨日、重复与完成规则不足 | 重复任务参与规划，可跨天拆分或不可拆；完成由用户主动确认 |
| 快速输入 | 语音和输入位置缺恢复语义 | 保留语音转写和快速输入，允许校对；AI 解析成业务数据须预览确认 |
| 规划范围 | 仅明日，“后一天”含糊 | 用户指定单日或整周，周任务先分到天再细化；界面显示具体日期 |
| 步骤与缓冲 | 一律 3—5 步、固定规则 | 步数按复杂度，简单任务可一步；缓冲默认 15 分钟可调；默认均衡密度 |
| 信息不足/过载 | 缺关键输入及无解行为 | 关键缺失追问、普通估计标注；输出可行部分和未排原因，不侵占硬约束 |
| 结果应用 | 手动调整、自动重排边界不清 | 生成、重排及其他 AI 业务改动均先预览确认；并发修改需要版本校验 |
| 执行 | 时间到点和完成混用 | 正计时/倒计时；账号最多一个进行中专注；补记修改留修订，不自动认定完成 |
| 困难 | 多个字段增加记录负担 | 一句话为主，分类和情绪可选；主动求助，不自动发起额外 AI 调用 |
| 复盘前提 | 必须有已结束计划 | 单日复盘可补做，无计划可补事实；约 3—5 分钟，可跳过 |
| 报告 | 缺版本及事实更正 | 批注和重新生成保留版本，区分事实、补充和推测 |
| 偏好沉淀 | “自动沉淀”与最终决策权冲突 | 记忆/偏好经确认保存，可管理删除；对话按请求检索相关历史 |
| 分享 | 保存与公开传播混在一起 | 首版不分享；仅本人数据导出 JSON/CSV/ICS/Markdown，不做整包恢复 |
| 提醒 | 手机推送沿用到所有终端 | Web 不需要业务提醒，App 后续可加；账号验证邮件独立 |
| 同步/离线 | 缺冲突、删除和时钟语义 | 在线约 5 秒目标；安全合并，实质冲突人工选择；离线查看、勾选和已有专注续计时 |
| 隐私 | “仅本人、不外发”与服务端 AI 冲突 | 如实说明服务端、供应商、超级管理员正文访问、日志与质检用途 |
| 保留 | “至少一年”未覆盖用户删除 | 账号存续保留；回收站 30 天、注销 7 天撤销；原媒体确认后/24 小时清理 |
| 埋点与统计 | 完成、用时、采纳定义混杂 | 计划块、任务、专注分开，不合成效率分；活动日 04:00，指标分母仍需细化 |
| 性能和兼容 | AI 5 秒、固定旧系统下限无场景 | AI 约 3 分钟可配，流式和后台恢复；Web 先验收 Chrome/Edge，App 矩阵后定 |
| 时间表 | 原 14 周未包含新增范围 | 无硬截止，按阶段质量验收；当前仅文档，开发另行开始 |

## 2. 新增的关键产品合同

| 合同 | 当前要求 | 主要风险及落点 |
| --- | --- | --- |
| 账号与管理 | 邮箱密码、验证找回、设备管理；开放注册可切邀请；超级管理员 TOTP | 服务端所有权、失效会话、恢复流程；详细设计 §3 |
| AI 作业 | 分能力配置、备用服务、后台执行、流式恢复、约 3 分钟超时 | 队列重复、取消竞态、版本过期；详细设计 §7 |
| AI 提案 | 助手所有业务写入均预览确认 | 陈旧提案覆盖人工修改、重复确认；详细设计 §6 |
| 金额额度 | 每日 04:00 刷新，成功扣一次，失败取消不扣；缺 usage 估算标注 | 并发透支、失败重试转嫁成本、跨日结算；详细设计 §8 |
| 公开网页 | 自动读取任务中的公开链接 | 重定向至非公开地址、网页指令扩大权限；详细设计 §9 |
| 日志与质检 | 正文日志 7 天；默认参与质检可关闭，既有样本到 30 天清理；不训练 | 用途混淆、无限保留、注销后复活；详细设计 §11 |
| 配置运维 | 草稿、测试、发布、回滚；自有/租用服务器，小规模预算 | 错误配置影响全部用户、成本失控、恢复失败；ADR、cloud |

## 3. 剩余缺口

未明确项不再散落在历史问题和测试的字母索引中，集中在[访谈问题清单](iTime-需求访谈问题清单.md)。优先处理时间/时区、任务与重复实例、预览确认、AI 成功结算边界、离线冲突及删除关联规则，再实现对应模块。

技术推荐、部署配置和产品规则分开记录：Python/Vue、Web 优先等已有结论不重复询问；模型价格、域名等待配置；有权益或语义影响的方案在实现前明确。

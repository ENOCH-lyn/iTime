# iTime PRD 分析与缺口

版本：0.1；日期：2026-10-02；状态：访谈输入，以下建议不等于已批准需求。

## 1. 分析依据

原始 PRD 的核心是“固定课表 → 任务 → 规划 → 执行 → 复盘”。用户补充把产品扩大为具备商业产品体验的完整 Web/App、账号、云同步、服务端 AI 和 Web 管理后台。

这会改变优先级、数据模型、隐私描述、性能指标和上线计划，不能仅在原文末尾加几个页面。

| 5.2.1 任务分类 | 想做/要做二分法不能完整表达重要性、紧急性和目标层级 | 确认保留二分类、四象限、项目目标或组合方式 | E |
| 5.2.2 属性 | 缺重复、拆分、依赖、剩余时长、附件、归档和删除语义 | 定义可排任务输入与生命周期；明确哪些由用户或 AI 决定 | E |

| 5.3.3 规则 | 固定15分钟缓冲及最多两项同类任务可能浪费时间 | 将参数可配置化，处理冲突优先级与不可满足方案 | F |

| 5.3.4 日期 | “后一天”可能为明天或后天；次日早晨未定义时区 | 全部使用明确日期与用户本地时区，定义凌晨归属和旅行行为 | F、J |

| 5.4.1 AI判断状态 | 未说明状态如何采集；不能推断用户正在做什么 | 首先确认显式输入或设备集成来源；不承诺被动识别能力 | G |
| 5.4.2 困难 | 情绪等敏感内容缺修改删除、访问范围、上传与模型发送边界 | 明确可选字段、关联对象、存储和第三方 AI 使用说明 | G、H、M |

| 5.5.2 复盘分析 | AI可能把没打卡推断成失败，把相关性推断成原因 | 区分已记录事实、用户解释和推测；数据不足应明确说明 | H |
| 5.5.2 报告分享 | “默认仅自己可见”与分享需授权流程衔接 | 确认导出格式、公开链接、过期/撤回和敏感内容选择 | H、M |
| 5.5.3 断点续聊 | “自动继续”缺持久化、流式中断、消息重复与多端并发语义 | 分离消息接收、模型执行和报告提交，定义恢复点 | H、I、K |
| 6 规划条件 | 要规划明天却要求“当天课表”；无课程用户被挡住 | 改为“目标日约束已明确”，允许空课表的范围待确认 | D、F |
| 6 隐私 | “不外发”与服务端调用第三方 AI 不能同时笼统成立 | 明确服务端同步、模型供应商处理、分析与公开分享不同路径 | K、M |
| 6 保留一年 | “至少一年”无上限，与账号注销、主动删除冲突 | 分类定义在线、备份、日志、账单和导出保留期限 | I、M、O |
| 7 埋点 | 实际用时/完成/采纳语义不明；可能过度采集情绪文本 | 指标和事件版本化、去重及最小字段；不默认上传私密正文用于运营 | N、M |
| 7 后台 | 有分析诉求但没有管理员产品要求 | 补账号、权限、AI配置、任务故障、用量、成本、通知和审计边界 | L |
| 8 性能 | AI<5秒未区分接单、首字、完整结果；无数据量/网络/设备条件 | 采用有场景的延迟分位数、容量及超时；通过原型实测后承诺 | K、O |
| 8 兼容 | iOS14/Android8与2026年的工具链和系统能力需重新评估 | 确认目标机型、系统下限、浏览器及支持年限 | B |
| 8 离线 | 仅查看/勾选，无离线新建、冲突、退出账号或缓存清除规则 | 明确本地队列、版本冲突、删除与重新联网的行为 | I |
| 8 安全 | “加密存储”缺对象、密钥保管与管理员权限边界 | 明确传输/静态加密、密码、平台Key、附件、备份和内容访问规则 | C、K、L、M |
| 8 合规 | 法律名称不能替代目标市场、运营主体、年龄与供应商决定 | 先确认市场和业务形态，形成可执行的数据与发布清单 | A、M、O |

| 10 风险 | 缺供应商限流、预算、同步冲突、通知可靠性、付费履约 | 纳入可重试、可回滚、可观察的失败路径和成本模型 | I—O |
| 附录闭环 | 优化建议“自动沉淀”与“只建议、用户最终决定”矛盾 | 区分会话建议、长期记忆、偏好变更；是否自动采纳需确认 | H、K |

## 3. 需要新增的完整章节

| 新章节 | 必须回答的内容 | 不明确会造成的问题 |
| --- | --- | --- |
| 双端及发布范围 | iOS/Android、Web响应式、平板、桌面端、上架方式 | 无法选栈、估工或验收“完整” |
| 账号与身份 | 登录方式、验证、找回、改绑、注销、设备会话 | 数据归属和同步无法闭环 |
| 同步与离线 | 服务端权威版本、冲突、删除、时区、后台计时 | 丢失修改、任务复活、重复统计 |
| AI平台 | 协议、供应商、模型路由、异步作业、预算、错误恢复 | Key泄露、重复计费、生成结果覆盖人工修改 |
| 管理后台 | 角色、内容可见范围、配置发布、审计与运营 | 所有管理员都能看到私密情绪或修改全站模型 |
| 商业与权益 | 免费/付费/配额、支付、续费/退款、跨端权益 | 收费范围不清、额度不同步、失败扣费争议 |
| 用户生命周期 | 新手引导、无任务、空闲周、停用、导出迁移 | 只实现主流程，真实用户无法完成首次使用 |
| 运维和支持 | 环境隔离、备份恢复、告警、工单、版本兼容 | 服务有故障但无法定位、恢复或通知 |

## 4. 优先确认顺序

先确认产品定位、首发平台、商业和部署边界；再确认账号、云端数据、AI和管理权限；随后逐项细化排期、执行和复盘规则；最后确认视觉、指标、容量、发布和验收。

全量问题见 [需求访谈问题清单](iTime-需求访谈问题清单.md)。允许回答“暂缓”“按你的建议，但先给我方案”“首发不做”；没有答复的选项保持待确认。

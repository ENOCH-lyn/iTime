# iTime 需求规格说明书

版本：0.1；日期：2026-10-02；状态：需求澄清草案，尚未冻结。

## 1. 范围与状态

目标是在固定安排、任务和个人偏好的基础上，帮助用户规划时间、执行任务、记录困难并复盘。正式交付包括完整 Web 用户端、App 用户端、Web 管理后台和服务端能力。

状态定义：

- **已确认**：本次用户明确提出的要求，可作为约束。
- **原PRD候选**：上传文档已有描述，需协调矛盾并确认细则及版本。
- **建议**：分析提出的方案，不构成已授权产品范围。
- **待确认**：缺少定义，不能作为开发验收标准。

## 2. 已确认需求

| 编号 | 需求 | 可核验边界 |
| --- | --- | --- |
| REQ-BASE-01 | Git仓库名 iTime | 本地仓库；远端所有者与可见性另行确定 |
| REQ-BASE-02 | Git配置与GitHub凭据只保存在当前项目 | 不修改全局配置或钥匙串；凭据不进入提交 |
| REQ-DOC-01 | 建立类似Topilot的完整文档与AI协作规范 | 需求、ADR、设计、计划、测试、验收及入口齐全 |
| REQ-WEB-01 | Web具备完整用户功能及UI | 用户功能清单确定后逐项验收 |
| REQ-APP-01 | App具备完整用户功能及UI | iOS/Android与系统下限待确认；不得默认为仅网页包装 |
| REQ-ADMIN-01 | Web额外提供管理员后台 | 后台范围与角色矩阵待确认 |
| REQ-AUTH-01 | 注册与登录 | 登录方式、会话、找回、注销细则待确认 |
| REQ-SYNC-01 | 用户内容同步服务器 | 数据类别、时效、离线和冲突策略待确认 |
| REQ-AI-01 | AI规划通过服务器执行 | 客户端通过业务服务请求规划 |
| REQ-AI-02 | 管理后台配置AI端点及Key | 平台凭据由服务端使用，不分发到普通客户端 |
| REQ-DISC-01 | 通过详细问题完善PRD | 未答复的问题不自动定案 |

## 3. 用户与角色

原PRD用户以高校学生为主，是否扩展到职场等群体待确认。暂识别未登录访客、已登录个人用户、管理员三类概念角色；免费/付费、客服/运营/财务、组织成员等均待访谈确定，不能预设其权限。

## 4. 功能模块规格草案

| 编号 | 模块与目标 | 输入/输出 | 待定义的规则 |
| --- | --- | --- | --- |
| REQ-CAL-01 | 课表/固定事件管理 | 手工或导入资料 → 可校对的重复事件与例外 | 学期、节次、时区、重复、取消与冲突 |
| REQ-TASK-01 | 任务箱 | 用户事项 → 可编辑、可检索任务 | 层级、优先级、依赖、重复、耗时、完成定义 |
| REQ-PLAN-01 | 规划生成 | 目标日期、任务、约束、偏好 → 时间段及操作步骤 | 生成跨度、预算、无解、确认生效与版本 |
| REQ-PLAN-02 | 手工调整/重排 | 已有计划及变更 → 更新计划 | 锁定、撤销、已执行保护、多端并发 |
| REQ-EXEC-01 | 执行与计时 | 用户开始/暂停/完成等动作 → 实际执行记录 | 后台恢复、补记、跨端排他或并行 |
| REQ-DIFF-01 | 困难记录 | 文本/语音/标签 → 关联记录 | 可选字段、可见性、编辑删除和AI使用 |
| REQ-REVIEW-01 | 对话式复盘 | 执行事实、困难、用户答复 → 对话与报告 | 无数据、断点恢复、报告版本及事实更正 |
| REQ-MEM-01 | 建议与偏好 | 复盘建议 → 可管理的偏好/行动 | 自动或确认采纳、撤销、记忆清除 |
| REQ-STATS-01 | 个人统计与分析 | 经定义的事件 → 趋势及解释 | 分母、日期、缺失值、采纳标准 |
| REQ-NOTIFY-01 | 提醒 | 用户规则和事件 → 可管理的通知 | 渠道、时区、静默、去重及不可送达提示 |
| REQ-EXPORT-01 | 数据导出/报告分享 | 用户选定数据 → 文件或链接 | 格式、权限、撤销、附件和敏感内容选择 |
| REQ-BILL-01 | 商业权益（待确认） | 套餐/订单/用量 → 权益 | 是否收费、渠道、失败扣费、退款和跨端权益 |

以上除已确认范围外，均为原PRD候选或待确认模块。不存在“默认已实现”功能。

## 5. 横向规则建议

这些建议需要在对应问题回答后固化：服务端统一鉴权和数据归属校验；相同动作具备幂等语义；AI结果经业务约束校验；同步冲突可恢复；用户能区分草稿、生效、未同步、失败、已取消；错误说明保留操作结果和恢复方式。

AI可辅助拆解和提出方案，但不得把估计的任务时长、未经确认的情绪原因或推断的完成情况写成用户事实。

## 6. 非功能需求待定项

| 编号 | 维度 | 必须确定的验收参数 |
| --- | --- | --- |
| NFR-PERF-01 | 性能 | 设备/网络、数据量、P95首页/同步/AI首字与完成时间 |
| NFR-CAP-01 | 容量与成本 | DAU、晚间高峰并发、队列上限、单用户/全站预算 |
| NFR-REL-01 | 可靠性 | 超时、取消、重试、崩溃恢复、备份RPO/RTO |
| NFR-SEC-01 | 安全与隐私 | 数据权限、凭据保管、日志、保留、注销与AI处理 |
| NFR-COMP-01 | 兼容性 | App系统/机型、Web浏览器、旧版本API兼容期限 |
| NFR-UX-01 | 可用性 | 空/加载/错误/离线状态、无障碍、深色模式与双端验收 |

原文首页3秒、AI5秒、14周排期与留存目标暂作为讨论输入，未作为性能承诺或交付承诺。

## 7. 需求冻结条件

首发清单、双端矩阵、业务状态与冲突规则、账号和管理员权限、AI配置/费用/失败语义、市场与部署约束已明确；各需求具备测试口径，未决项有明确负责人和处理时点。用户逐项回答可分模块冻结，不要求一次决定所有后续版本。

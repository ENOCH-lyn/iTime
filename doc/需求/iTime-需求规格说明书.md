版本：0.4；更新：2026-11-12。产品方向及下列基线已确认；细化方案和待定项分别标注。Web 首版功能闭环已完成 M1—M8-A，原生 Android 客户端完成首轮（v0.1，模拟器主流程验收）。2026-11-12 主人确认收敛范围：iOS 客户端、业务提醒、M8-B 备份恢复、M8-C 生产发布、正式模型质量评测与实体设备验收不再作为本项目要求。具体实现及执行证据见[实施与验证](../验收/iTime-Web实施与验证.md)与 Android 客户端验收记录。

## 1. 产品定位与交付边界

iTime 帮助个人整理任务和固定日程，通过 AI 规划、执行记录与复盘形成持续改进的闭环。学生优先，兼容没有课表的通用个人场景；主要面向大学及以上成年人，首发市场为中国大陆，语言为简体中文。

用户已明确：“全量功能，不过首版先做web端的全量，后面加APP”。交付顺序为完整 Web 用户端与管理后台 → Android。Android 首轮已于 2026-11-12 交付：Kotlin + Jetpack Compose（Material 3）原生客户端，离线优先（Room + outbox），与服务端共用同一套权限、同步与 AI 语义；iOS 不再纳入本项目范围。

| 范围 | 当前有效要求 |
| --- | --- |
| Web 首版 | 全局 AI 对话、账号、任务/目标/步骤、课表及全部导入方式、日周规划、手动调整、执行、困难、复盘、记忆、统计、同步、数据管理及管理后台 |
| 公共页面 | 产品介绍、演示、帮助、用户协议和隐私说明；演示可未登录访问，个人真实内容登录后保存 |
| 商业方式 | 先免费运营，实行每日 AI 金额额度；预留后续收费能力 |
| 首版不包含 | 分享、多人协作、第三方登录、用户自带模型 Key、独立习惯系统、任务间依赖、通用附件库、真实支付及会员购买 |
| Android（首轮已交付） | 原生 Compose M3；离线可查看、新建与编辑任务/项目、勾选完成、按次完成重复任务；联网自动同步；复杂冲突由用户选择保留本地或云端；AI 对话与审批在线调用；手机/平板自适应（NavigationRail、宽屏双栏） |
| 已移出范围 | 2026-11-12 主人确认：iOS 客户端、业务提醒、M8-B 备份恢复、M8-C 生产发布、正式模型质量评测与实体设备验收不再作为本项目要求；验证/找回密码邮件仍属账号流程 |

本规格承接[原始 PRD](原始PRD-V1.0.md)的产品功能，并以本轮明确答复修正冲突。原文中的二分类、分享、强制步数、性能数字及固定工期不自动成为当前要求。未定细节见[访谈问题清单](iTime-需求访谈问题清单.md)。

## 2. 角色与共用交互合同

| 角色 | 访问范围 |
| --- | --- |
| 访客 | 公开介绍、演示、帮助与账号入口；不能保存真实个人数据 |
| 个人用户 | 自己的任务、日历、计划、执行、困难、对话、报告、记忆、额度和数据管理 |
| 超级管理员 | 首版唯一管理角色；密码加 TOTP；可管理用户、邀请/状态、额度、AI 配置、日志、审计、质检，并直接查看授权范围内的用户正文 |

管理员查看正文须可审计；普通用户不能访问他人内容或管理接口。平台 Key 由服务端保管，不作为客户端可读取数据。

所有用户写操作都需要明确保存状态；本地待同步不表示已保存到服务器。失败页面说明原因、是否已保存、可恢复操作及请求编号。重试不能重复创建记录、应用变更或扣额。以下功能的用户权限均限本人；后台访问走独立管理权限。

AI 生成的业务变更全部先预览、后确认；正常保存聊天消息、作业状态和审计记录不额外请求“数据库写入确认”。AI 估计与用户事实分开展示，未记录不等于未完成。

| REQ-APP-03 | Android AI 入口 → 服务端 Agent 结果 | 对话与提案审批全部线上执行；离线时显示「AI 需要联网」，不排队离线 AI 请求 | 发送失败可一键重试；提案应用需服务端版本校验；AI 额度与日志沿用 REQ-AI-01 / REQ-QUOTA-01 |

会话有效期、改邮箱与账号申诉流程仍需在账号模块细化；不得擅自扩展成第三方账号合并功能。

## 4. 任务与固定安排

| 编号 | 输入与输出 | 已确认规则 | 边界与恢复 |
| --- | --- | --- | --- |
| REQ-TASK-01 | 一句话/语音转文字、属性、文本与链接 → 可编辑任务 | 统一任务，不强制“想做/要做”；目标或项目 → 任务 → 操作步骤；保留截止、耗时、标签、优先级、搜索、批量操作 | 名称是基础输入；不确定耗时可由 AI 建议并标注；识别可校对，失败可改手工输入 |
| REQ-TASK-02 | 重复规则、步骤、拆分设置 → 任务实例与进度 | 重复任务统一参与规划；只有步骤顺序，不做任务间依赖；允许跨天分段，也可标记不可拆 | 单次与系列修改需区分；勾完步骤或倒计时结束不自动把任务标为完成 |
| REQ-CAL-01 | 学期、起始周、周次、节次、具体日期例外 → 固定事件 | 完整支持学期、单双周、指定周、临时调课/取消/补课；可自定义固定不可安排时间 | 真实日期和时区保留；已有固定事件冲突必须展示，AI 不能通过移走固定事件解决 |
| REQ-CAL-02 | 图片、Excel、ICS、公开网页、文字描述或手工输入 → 可校对的日程 | AI 会话与日历提供等价导入入口并复用统一候选；提供 Excel 模板；外部日历只读，不写回外部账户 | 识别错误可校对；重复/部分识别和来源失败须保留可判断的结果，未确认内容不自动导入 |
| REQ-CAL-03 | 订阅来源更新 → 更新来源日程并指出计划冲突 | 保留来源关系，不静默重排已确认计划 | 拉取失败保留上次成功数据和更新时间；允许重试，具体自动刷新周期待配置 |

任务资料限文本和链接；截图、录音用于识别，不扩展成长期附件库。语音输入承接原 PRD，转写后由用户校对；多任务解析等 AI 业务改动仍需预览确认。

采用可演进默认：日期型截止按任务时区当天结束判断；重复系列与单次 occurrence 分离，系列编辑区分“仅本次 / 本次及以后 / 全部”，跳过保留记录、补做创建关联的一次性记录，完成后不自动归档。课表和文件导入先形成可选择的候选记录，精确重复幂等合并、疑似重复由用户判断，固定安排冲突允许保留并明确警告。详细边界见[时间、课表与重复规则设计](../设计/iTime-时间课表与重复规则设计.md)。

## 5. 对话与规划

| 编号 | 输入与输出 | 已确认规则 | 边界与恢复 |
| --- | --- | --- | --- |
| REQ-CHAT-01 | 全局对话、多会话、相关历史和附件 → 回复或业务提案 | 会话是主要业务入口；用户使用自然语言，不先选择普通回复、规划或导入模式；复盘保持独立归档 | 不把全部历史无差别发送；跨端恢复已保存消息、工具状态和提案，流中断不重复提问或扣额 |
| REQ-CHAT-02 | AI 拟新增/修改/删除任务、日程、计划、专注、复盘、记忆等 → 变更预览 | 服务端 Agent 自动选择受限工具；只读工具可执行，所有业务写操作须由用户确认后应用；可调整或拒绝 | 模型不能直接写业务数据；确认时若数据版本已变化，展示冲突并重新确认，不能覆盖新编辑 |
| REQ-LINK-01 | 任务中的公开链接 → 摘要及来源 | 自动读取公开网页，作为规划参考资料 | 读取失败说明来源和原因；只允许公开网络内容，页面指令不能扩大权限或自动执行写操作 |
| REQ-PLAN-01 | 用户自然描述或在规划页指定单日/整周、任务、固定块和偏好 → 规划草稿 | 对话由 Agent 自动识别规划意图并读取相关任务和日历，不要求用户先选择模式；周计划先分配到每天再逐日细化；规划页保留密度、缓冲和时段的精细设置 | 关键缺失先追问，可靠默认值写入提案假设；普通估计标注；超载时给可行安排并解释未排项；无课表不阻断 |
| REQ-PLAN-02 | 预览、手动改时间/步骤/顺序、拖拽或请求重排 → 新计划版本 | 生成及重排都先预览确认；计划时间段关联任务与步骤；支持手动纠错 | 不改写已经发生的执行事实；新固定事件或任务变化使旧草稿需要复核；AI 故障时可手动安排 |

计划应明确区分固定时间、任务排期和自由时间。锁定、局部接受、撤销/恢复粒度与具体硬/软约束冲突优先级属于详细设计待定项，不将候选交互全部视为已确认。

| REQ-STATS-01 | 计划块、任务、专注与报告记录 → 日/周/月统计 | 计划块、任务与专注事实分别展示；不合成为单一效率分 | 缺数据、取消、跳过、补记分别表达；口径和时间范围可查看，不能用时间经过推断完成 |

## 7. 同步、时间与数据生命周期

REQ-SYNC-01：任务、课表、计划、执行、困难、对话、报告、记忆及个人业务设置由服务端同步，正常联网设备约 5 秒内可见为目标。不同字段仅在语义安全时合并；实质冲突由用户选择，不能统一按最后写入覆盖。Web 离线范围为查看、勾选和已有专注续计时；Android 为离线优先（查看、新建/编辑任务与项目、勾选、按次完成），新的 AI 请求及新的云端专注需要联网。未同步操作、冲突与最后同步时间应可见。

REQ-TIME-01：活动日默认在用户时区凌晨 04:00 切换；个人统计和每日额度使用同一规则。默认保存浏览器报告的 IANA 时区，用户切换时区只改变显示和后续新建内容的默认值，不改写既有时间点；全天日期不跨日漂移，每周从周一开始，夏令时缺失/重复时刻不静默修正。日历仍展示真实日期与时刻，课表不随活动日挪动；服务器决定额度活动日，不能通过修改设备时间反复刷新额度。

| 编号 | 数据/动作 | 已确认生命周期及恢复 |
| --- | --- | --- |
| REQ-DATA-01 | 独立内容对象、单项删除与事实历史 | 开放删除的独立内容对象进入 30 天回收站，期间可恢复，不能因旧设备或在途任务重放而复活；首版已确认的独立删除范围包括任务、困难、长期记忆、日历系列和 ICS 订阅源。步骤、批注、单次例外等子项随父聚合或版本历史管理；已确认计划、专注、复盘等事实记录不因源对象删除而改写。学期、项目、AI 会话等其他独立对象是否开放删除随对应模块继续确认 |
| REQ-DATA-02 | 账号注销 | 7 天可撤销期，之后清理个人数据；清理覆盖正文、记忆、索引、样本和在途任务，如有备份则按运维策略处理，不作为本项目功能要求 |
| REQ-EXPORT-01 | 用户导出自己的内容 | 完整 JSON，以及 CSV/ICS/Markdown 的适用分类导出；提供本人可下载结果和失败重试；不做整包恢复或公开分享链接 |
| REQ-MEDIA-01 | 识别原图/录音 | 用户确认识别结果后删除原媒体；未完成处理的媒体 24 小时清理，超期需重新上传 |
| REQ-PRIV-01 | AI 技术排障日志 | 默认保存请求/响应正文 7 天；管理员可审计查看；鉴权头与平台 Key 不进入正文日志 |
| REQ-PRIV-02 | 质量改进样本 | 用于人工质检、提示词优化和效果评测，不做训练/微调；默认参与，可关闭；关闭仅停止后续采样，已有样本保留至 30 天清理；账号注销清理优先 |

云同步、AI 供应商处理、技术日志、质检用途及管理员正文访问必须在隐私说明中如实表达。退出质检不等于关闭必要业务存储或技术日志。部署和 AI 地区无指定地域要求，实际上线使用的地区及供应商仍需明确说明。

## 8. AI 平台、金额额度与后台

| 编号 | 输入与输出 | 已确认规则 | 失败与恢复 |
| --- | --- | --- | --- |
| REQ-AI-01 | 客户端业务请求 → 服务端 AI 作业与结果 | OpenAI 兼容优先；按对话、规划、复盘、识别等能力独立配置，也可复用；模型由平台选择；后台执行并尽可能流式 | 约 3 分钟总等待基线可配置；重试及备用切换有界；离开页面不丢作业，重新进入可查状态 |
| REQ-AI-02 | 后台端点/Key/模型参数 → 配置版本 | 草稿 → 测试 → 发布，可回滚；可配置备用服务 | 测试失败不替换线上配置；客户端不接收平台 Key；旧作业使用明确的配置版本 |
| REQ-QUOTA-01 | 每日免费金额额度、成功用量、配置价格 → 预留、扣额与余额 | 接单时按用户时区 04:00 活动日冻结并预留；结果校验通过且可查看时按最终成功尝试和配置价格仅结算一次；业务提案后续拒绝或过期仍计费；缺失 usage 时估算并标注 | 失败、取消及失败重试成本由平台承担并释放预留；实际成功成本超预留及迟到 usage 不追扣用户；并发必须防止超用，金额额度不是现金钱包 |
| REQ-ADMIN-01 | 管理登录及用户/额度/AI/日志/审计/质检操作 → 可追溯管理结果 | 只有超级管理员，密码加 TOTP；支持邀请制开关、用户状态和额度管理；可直接查看正文 | 服务端逐请求授权，敏感动作审计；故障可定位到请求及配置版本；Key 替换不回显明文 |

额度成功边界已采用“结果校验通过且可查看”：普通回复、识别结果、报告和可预览业务提案均在该时点结算，提案应用是后续独立业务事实。跨 04:00 作业归接单时冻结的活动日；超预留和迟到 usage 由平台承担。每日额度数值和币种由后台策略版本配置，不写死为产品常量。

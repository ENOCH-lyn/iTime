# iTime 范围与 AI 融合重构 v2

版本：0.1；更新：2026-10-10。本文承接 2026-10-10 用户关于「单栏导航、AI 为核心、日历课表化、专注删除、规划页只读、复盘以 AI 驱动、统计并入个人中心、AI 必须使用 function tools 和长期记忆」的变更要求，是对现行[需求规格](iTime-需求规格说明书.md)的增量修订。原规格中与本文冲突的条目以本文为准；未在此修订的条款继续有效。

## 1. 用户确认的方向（硬约束）

1. **导航降为单栏**：参照 ChatGPT 单栏信息架构，顶部放功能入口，下方放 AI 会话历史；取消现在的 64px 窄栏 + 260px 次级侧栏的双列结构。
2. **AI 和日历是双主角**：其余功能次要或并入 AI 对话。
3. **任务保留但不主要**：必须与 AI 和日历融合，而不是独立闭环。
4. **专注删除**：Web 不再提供独立的专注计时页，相关路由、菜单项、组件和用户入口全部移除；底层执行事实（时间段打卡）如仍需保留以供复盘，走任务/日历时间块的"实际用时"字段，不单独建页。
5. **规划页改为只读展示**：保留查看、修改、删除已有规划的接口和界面；**不再**在规划页内直接触发"生成计划"，所有生成/重排的交互转移到 AI 对话。
6. **日历支持执行记录**：日历事件卡片内可直接标记完成、备注卡点、记录实际用时，供 AI 复盘引用。
7. **日历布局接近课表、Y 轴按真实时间精确映射**：参考 Google Calendar / Fantastical / Notion Calendar 的分钟精度绝对定位，不用等高格，但要有最小高度避免挤压。
8. **统计并入个人中心**：新建 `/me` 作为个人中心（账号、安全、隐私、同步、数据、AI 额度、注销、**统计**），统计不再是独立主导航项。
9. **复盘以 AI 多轮问答为主**：`/reviews` 退化为**结果展示页**；复盘的发起入口只有一个"去 AI 说复盘今天"；AI 的提问**不要求固定模板**，由模型自行组织合理的追问序列。
10. **AI 架构升级为 function tools + 长期记忆**：废弃现在"把上下文塞进 prompt"的做法，改为给 AI 一组足够完整的只读/写工具，让 AI 能查询任意日期的任务/日历/规划/复盘，并支持长期记忆的写入、召回、删除。

## 2. 范围调整（对需求规格的直接修订）

| 原规格条目 | v2 修订 |
| --- | --- |
| REQ-WEB-01 主入口 | 单栏导航：顶部【新对话、日历、任务、规划、个人中心】；下方滚动区是 AI 会话历史；默认落地页为 `/ai` |
| REQ-EXEC-01 专注 | **删除独立页面**：无 `/focus` 路由、无菜单项、无专注计时组件；用户想记录"实际用时"在任务或日历事件卡片内直接输入；全账号最多一个进行中会话的约束不再适用（无会话） |
| REQ-PLAN-01 规划 | 规划页改为**只读列表 + 展示**：可查看所有规划、点击进入详情、修改元信息或删除；"生成/重排计划"的入口全部指向 AI（按钮文案："去 AI 对话里说：帮我生成本学期规划"，点击带 prompt 预填跳到 `/ai`） |
| REQ-PLAN-02 预览应用 | 生成/重排仍走"AI 预览 → 用户确认"流程，但发起入口只有 AI 对话；规划页**不再**自带生成按钮 |
| REQ-CAL-01/02/03 日历 | 新增**事件执行状态**字段：`待开始 / 进行中 / 已完成 / 已跳过 / 卡住`；新增"卡点备注"文本字段；新增"实际用时"分钟数字段。日历主视图改为**分钟精度绝对定位**（Y 轴每小时固定像素高度，可缩放 32–64px/h），事件按 `(start_minute / 60) * HOUR_PX` 定位，重叠事件按分列算法等分宽度；短事件最小高度保证标题可见，溢出用 tooltip |
| REQ-REVIEW-01 复盘 | 复盘**不再有独立表单页**；`/reviews` 作为**结果展示页**显示历史复盘摘要（AI 生成 + 用户补充）；复盘发起只在 AI 对话里，由 AI 用 function tools 读取当日的执行事实、规划、任务、困难等上下文，用自然对话组织合理追问（**不是固定问题序列**），用户回答后 AI 调工具 `write_review` 落库 |
| REQ-STATS-01 统计 | 统计并入 `/me` 个人中心；不再是独立主导航项；展示口径不变（计划块、任务、专注事实分别展示；不合成单一效率分） |
| REQ-CHAT-01/02 对话 | 对话仍是主要业务入口；AI 的工作方式从"注入上下文"升级为"调用 function tools + 读写长期记忆"；写操作保留"预览-确认"硬约束（AGENTS.md 第 4.4 条） |

## 3. AI 必须具备的工具与能力（function tools + 长期记忆）

详细 schema、权限矩阵、幂等 key、速率、审计见 [ADR-014](../架构/iTime-ADR架构决策文档.md#adr-014ai-function-tools-与长期记忆)。本节只定稿需求侧。

**只读工具**（AI 可直接执行）：
- 日历：`get_calendar_events(date_from, date_to)`、`get_event(event_id)`
- 任务：`list_tasks(filter)`、`get_task(task_id)`、`search_tasks(query)`
- 规划：`list_plans(filter)`、`get_plan(plan_id)`
- 复盘：`list_reviews(date_from, date_to)`、`get_review(review_id)`
- 困难：`list_difficulties(date_from, date_to)`
- 长期记忆：`search_memory(query, limit)`、`list_memories(filter)`
- 时间：`get_time_settings()`、`get_today()`（避免模型用自己的时间）

**写工具**（必须走预览-确认）：
- 日历：`create_event`、`update_event`、`delete_event`、`update_event_status(event_id, status, note, actual_minutes)`
- 任务：`create_task`、`update_task`、`delete_task`、`split_task_steps`
- 规划：`create_plan`、`update_plan`、`delete_plan`、`regenerate_plan`
- 复盘：`write_review(date, summary, highlights, blockers, next_focus)`
- 困难：`create_difficulty`
- 长期记忆：`save_memory(content, tags)`、`update_memory`、`delete_memory`

**长期记忆硬约束**：
- 用户**可见、可增删改、可导出**；
- 存入独立 `ai_memory` 表（不混入对话正文日志的 7 天期限）；
- 默认保留直至用户主动删除；删除进入 30 天回收站，与 REQ-MEM-01 对齐；
- 不参与质检训练；
- 账号注销时按 REQ-DATA-02 清理；
- 超级管理员可审计查看，和既有正文访问审计规则一致；
- 每次新对话开启时，服务端自动调 `search_memory` 拉取与当前首条用户消息最相关的 N 条记忆，拼入 system prompt（**这是服务端编排，不是模型任意拉取**）。

## 4. 删除的范围

**UI 层**：
- 删除 `/focus` 路由和 `FocusPage.vue`、`FocusSecondaryNav.vue`、`AppRail` 中的专注入口；
- 删除规划页内的"生成/重排"按钮和相关对话组件（如果有）；
- 删除独立的复盘发起表单组件；
- 删除 `/stats` 作为主导航项（迁入 `/me/stats` 或 `/me` 的默认 tab）。

**服务端层**：
- 专注会话（如 `focus_sessions` 表）：**先保留表结构和数据**，关闭 API 和前端入口；二期再评估是否迁移字段到任务/日历并下线。
- 规划生成的 AI 作业入口迁移到对话工具，页面侧的 `POST /api/v1/plans:generate` 保留但从 UI 调用改为可由 AI function tool 调用；
- 复盘的独立 `POST /api/v1/reviews:start` 作业链路迁移到 `write_review` 工具，表结构不变。

**不删除**：
- 后端数据模型、迁移、历史数据（避免破坏既有用户数据和审计链条）；
- 规划、复盘、任务、日历的 CRUD API（AI function tool 要用）。

## 5. 分阶段落地计划

| 阶段 | 范围 | 验收 |
| --- | --- | --- |
| **S1 导航与范围收敛** | 单栏导航、删除专注入口、规划页改只读、统计迁 `/me`、复盘页改展示态；AI 对话保留现状 | Playwright 三视口回归通过；UX-07 升级为"单栏 AppShell"用例；后端只做入口关闭，不动数据模型 |
| **S2 AI function tools + 长期记忆** | 新增 `ai_memory` 表和迁移；实现 ADR-014 工具链；对话编排从"注入上下文"切为"工具调用"；只读工具先全量上线，写工具走预览-确认 | 后端 pytest 覆盖每个工具（成功/失败/权限/幂等）；e2e 覆盖"AI 查询任意日期任务/日历"、"AI 保存/召回长期记忆"、"AI 预览-确认写工具"闭环 |
| **S3 日历课表精度 + 事件执行状态 + 复盘工作流** | 日历改分钟精度绝对定位 + 重叠分列；事件卡片新增状态/卡点/实际用时字段和迁移；AI 复盘工具链上线 | 后端迁移和字段测试；e2e 覆盖"日历标记完成、备注卡点、记实际用时"、"AI 读取当日事实复盘并写入 review" |

每阶段单独 PR 和 commit，每阶段真实服务测试 + Playwright UI 测试，中文沟通和文档。

## 6. 未在本次定稿的事项（挂起）

- 任务和日历融合的具体 UI：任务是否以时间块出现在日历？无时间任务挂在哪里？拖拽交互如何？—— S3 前再定稿。
- 日历每小时像素默认值和缩放范围（32/48/64px/h 哪个为默认）—— S3 实现时真机校验后定。
- AI 调用频率上限和并发：function tool 单次对话最多调用多少次、最大 token 预算 —— S2 实现 ADR-014 前定。
- 长期记忆的"自动归纳"是否存在：对话结束时是否由 AI 自动总结沉淀？本次定稿为**仅手动显式 `save_memory`**，自动归纳不在首版范围。

# iTime 需求访谈问题清单

更新：2026-10-03。已确认结论已并入[需求规格](iTime-需求规格说明书.md)，本文件仅保留影响后续实现的未定细节，避免重复询问。候选方案不等于用户决定；按模块开发顺序细化，不要求一次回答全部。用户已授权 goal 模式下由代理自行决定并持续实现，不再因产品细节停工；安全和不可逆删除仍不得用无证据假设扩大权限。

## 1. 实现前需要细化的产品规则

| 编号 | 已有边界 | 仍需明确的问题 | 处理时点 |
| --- | --- | --- | --- |
| Q-AUTH-01 | 邮箱密码、验证、找回，设备管理 | 是否支持改邮箱；原邮箱不可用如何恢复；会话有效期、改密码后其他会话如何处理？ | 账号设计 |
| Q-AUTH-02 | 首版超级管理员，强制 TOTP；服务端已按可调整工程默认实现本机创建/重置、一次性恢复码和 8 小时会话 | 是否接受当前创建、恢复与交接责任；正式管理会话期限；哪些敏感操作需再次验证 TOTP？ | 后台认证与运营定稿 |
| Q-AUTH-03 | 开放注册可切邀请制，用户状态管理 | 邀请有效期/次数、封禁和冻结 AI 的区别、对在途作业和申诉的影响？ | 用户管理设计 |
| Q-TASK-02 | 语音转文字、文本和链接、AI 变更预览 | 语音是否进一步解析多项任务与属性；转写校对、批量解析的确认粒度？ | 快速输入设计 |
| Q-PLAN-01 | 固定块、密度、15 分钟可调缓冲、超载解释 | 睡眠/用餐/通勤哪些为硬约束；冲突优先级、软偏好排序、短任务缓冲、周任务分配规则？ | 规划引擎设计 |
| Q-PLAN-02 | 生成/重排先预览，手工纠错 | 锁定、局部接受、拆合段、撤销/重做、历史恢复的具体范围；重排保护哪些未完成部分？ | 计划交互设计 |
| Q-PLAN-03 | 不强制课表、保留自由时间 | 无任务时如何呈现；默认打开哪一天/哪一周；无 AI 的规则排期是否需要？ | 规划交互设计 |
| Q-DATA-01 | 回收站 30 天、注销 7 天、完整导出；账号注销默认见 Q-DATA-02 | 任务等单项删除后关联计划/报告/困难如何保留或隐藏；回收站内恢复依赖；单项彻底删除的即时范围与导出内容？ | 后续对象生命周期 |
| Q-PRIV-01 | 正文日志 7 天、样本 30 天、默认质检可关闭 | 单项彻底删除是否同时清理日志和样本；运营主体和正式隐私文案；供应商数据保留与清除能力？ | 隐私与清理设计 |
| Q-ADM-01 | 用户、额度、AI、日志、审计、质检 | 具体支持动作、正文查看范围、管理操作审计期限；配置测试的调用内容与成本上限？ | 管理后台设计 |
| Q-UX-01 | 温和轻松、全尺寸响应式、主题和字号 | 具体色板、组件与密度；键盘/读屏/减少动效验收要求、Chrome/Edge 最低版本？ | 交互原型及 Web 验收 |

可由代理提出具体方案供对应模块评审，不因缺少某个参数就重新访谈已确认的产品方向。影响用户权益、数据删除或费用的规则必须在实现前明确。

## 2. 已采用的可演进默认

| 编号 | 采用规则 | 依据 |
| --- | --- | --- |
| Q-TIME-01 | 默认使用并保存用户浏览器报告的 IANA 时区；修改时区不改写既有时间点；日期型截止按当地日末；周一为周起点；夏令时异常不静默平移 | 用户明确“默认按照用户使用的时区”，并授权一般细节由代理决定 |
| Q-TASK-01 | 重复系列与 occurrence 分离；支持本次/本次及以后/全部；跳过保留事实，补做生成关联的一次性记录；任务进度仍以步骤事实和明确完成表达；不自动归档 | 可演进工程产品默认，见时间课表设计 |
| Q-CAL-01 | 识别和文件导入先形成可勾选候选；精确重复幂等合并、疑似重复人工选择；冲突事件可并存并警告；部分有效记录可确认 | 可演进工程产品默认，见时间课表设计 |
| Q-CAL-02 | 外部来源只读；来源删除保留历史并取消未来 occurrence；本地例外优先，来源变化与本地覆盖并存时展示差异 | 可演进工程产品默认，见时间课表设计 |
| Q-QUOTA-01 | 接单时按用户时区 04:00 活动日冻结并预留；结果校验通过且可查看即成功结算，业务提案后续拒绝/过期仍计费；只结算最终成功尝试，失败/取消和失败重试不扣；实际成功成本超出预留及迟到 usage 由平台承担且不追扣；AI 冻结只阻止新作业 | 用户明确禁止 goal 模式停下提问并授权代理自行决定；采用此前推荐的资源产出即结算方案 |
| Q-EXEC-01 | `running` 和 `paused` 均占用账号唯一开放专注；倒计时归零后继续显示超时但不自动结束或完成任务；陈旧会话只提示核对；已加载会话的离线动作按原操作号顺序重放，冲突保留本地队列 | 可演进工程产品默认，见执行与困难设计 |
| Q-DIFF-01 | 困难可独立记录或关联一个任务和一次专注；分类与情绪可选并允许自填；查询按日期、任务和分类；AI 帮助只带入可编辑对话草稿，不自动发送 | 可演进工程产品默认，见执行与困难设计 |
| Q-REV-01 | 同账号同活动日一个可恢复复盘会话；最多三轮单问题追问且可随时跳过；报告固定区分事实、用户说明、AI 推测、下一步和信息缺口；事实更正不覆盖历史版本；记忆可整体暂停，删除后立即停止检索并进入 30 天回收站 | 可演进工程产品默认，见复盘与记忆设计 |
| Q-MET-01 | 日/自然周/自然月按当前用户时区 04:00 聚合；当前范围只到当前活动日；当前计划版本、当前任务结果和专注最新有效值分别统计；完成、跳过、放弃、人工补记和修订单列；跨界时间守恒分配；不输出无可靠分母的百分比或综合效率分 | 可演进工程产品默认，见个人统计设计 |
| Q-SYNC-01 | 使用账号绑定的不透明增量游标和无正文失效事件；现有类型化 API 保持权威，不建立通用写入解释器。可见页默认 2 秒拉取，事件默认保留 30 天，过期先保留待传操作再刷新权威快照。离线查看限当前已认证且仍打开的页面；普通/重复任务步骤及已有专注操作使用账号隔离、最多 100 项、最长 7 天的类型化队列。不同步骤等独立字段可安全收敛，删除、终态及结构变化保留冲突；显式退出确认后清理本地队列和缓存 | 用户已确认同步边界并授权代理决定一般细节；可演进工程默认，见通用同步设计 |
| Q-DATA-02 | 注销申请需当前密码和完整邮箱；申请后立即锁定账号、撤销全部会话、终止在途/临时工作并清理浏览器本地数据。7 天内仅凭邮箱和密码明确撤销并新建会话；到期后租约 worker 物理删除本人数据，只保留无邮箱/正文的 HMAC 删除回执。同邮箱之后可注册为全新账号 | 用户已确认 7 天撤销和到期清理，并授权代理决定一般细节；可演进工程默认，见账号注销设计 |

## 3. 工程推荐与上线配置

以下是需要工程论证或实际资源信息的项目，不冒充用户尚未决定的产品方向。

| 项目 | 已确认约束 | 下一步 |
| --- | --- | --- |
| 后端/前端 | Python、Vue；框架由代理比较推荐 | 见 ADR；确定依赖版本、迁移和工具链，验证异步 I/O 与流式链路 |
| 服务器与域名 | 自有或租用；无指定地域；月总预算 200—1000 元 | 选规格、域名、TLS、邮件发送服务及访问条件，估算总成本 |
| 模型与价格 | OpenAI 兼容优先，分能力配置，允许备用服务 | 填写供应商、模型、能力、价格、币种、每日免费额度和平台总预算 |
| 外部请求 | 自动读公开链接；管理员配置 AI 端点 | 明确端点网络允许范围、网页抓取隔离、重定向策略 |
| 资源阈值 | AI 总等待约 3 分钟可配；在线同步约 5 秒目标 | 队列/单次调用/首字/空闲超时、重试次数、上下文和文件大小、并发/限流、订阅刷新周期 |
| 备份与恢复 | 每日备份、24 小时恢复目标 | RPO、备份保留及异地位置；验证恢复和删除标记重放 |
| 性能与质量 | 100—1000 注册、日活不超过 100 | 峰值并发、历史数据量、网络/设备与分位数指标；AI 评测数据和质量标准 |

## 4. 后续 App 阶段

REQ-APP-01 保留完整功能目标。Android 先于 iOS；最低系统版本、原生/跨平台框架、商店/内测分发、平板专门布局、后台与锁屏能力、提醒渠道、去重、静默、锁屏隐私和旧版本兼容在 App 阶段确定。

分享、协作、支付、用户自带 Key 等不属于当前首版；只有新增需求明确提出时才重新评估，不作为当前缺口强行补入。

## 参考方式

参考仓库：[ENOCH-lyn/Topilot](https://github.com/ENOCH-lyn/Topilot)，检查快照 `9a8606210c93d912d76f067d9cccb7e0b2e1c767`。

借鉴其 `agents.md` / `cloud.md` / `designer.md` 以及 `doc/需求、架构、设计、计划、测试、验收` 的职责划分，尤其是用例编号、输入输出、异常路径、阶段验收与真实证据的对应关系。

iTime 使用常见的 `AGENTS.md` 命名；macOS 默认文件系统大小写不敏感，不另建仅大小写不同的 `agents.md`。不继承 Topilot 的 Bot 技术栈、JSON 持久化、个人工具权限边界、项目工期或历史测试结果。

## 更新规则

每次答复写入问题记录，并更新相关需求与追踪矩阵。每个重要决策记录依据和影响；需求尚未确定时不伪造确定的数据库字段、API 路由、完成率、容量或发布日期。

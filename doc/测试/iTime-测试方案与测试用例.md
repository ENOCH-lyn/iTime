# iTime 测试方案与测试用例

版本：0.1；日期：2026-10-02。**当前无业务实现，以下产品用例均未执行。** 预期行为是建议验收口径，需随需求访谈确认。初始化验证结果另见 [验收记录](../验收/iTime-初始化验收记录.md)。

## 1. 分层与环境

- 单元/性质测试：时间区间、重复事件、任务状态、幂等、额度、统计口径等确定性逻辑。
- 服务集成与契约测试：真实测试数据库上的认证、所有权、事务、版本冲突、AI适配和外部回调。
- AI评测：固定数据集验证约束、事实引用、无解解释及建议质量；确定性校验与模型质量评估分开。
- Web端到端、App端到端及真机检查：真实用户路径、离线、锁屏、杀进程、重启、权限拒绝与跨端接续。
- 性能/故障/恢复：代表性负载、限流、上游断流、数据库不可用、队列重放与备份恢复。

仅在本地或隔离测试环境使用测试账号和合成数据；真实模型调用、付费渠道及压测预算先按用户确认范围配置。不得擅自对生产系统做破坏性、攻击性或高负载验证。

当前不选pytest、Vitest、Playwright、Maestro或其他产品测试框架；选栈后决定适用工具，不创建无意义的空测试充数。

## 3. 核心产品用例

| 编号 | 前提与操作 | 建议预期/待定点 |
| --- | --- | --- |
| AUTH-01 | 使用确认的注册方式验证、登录、另一端登录、退出 | 同一身份关联同一数据；会话及退出规则按C确认 |
| AUTH-02 | 用户A操作测试用户B的任务/报告/附件/AI作业 | 服务端拒绝跨用户访问，无额外数据泄露 |
| AUTH-03 | 验证码过期/重用、找回、改绑、撤销设备会话 | 错误明确，凭据生命周期符合C规则 |
| CAL-01 | 学期起始日、单双周、指定周、节次、假期例外 | 得到目标日期正确固定区间，不按简单每周误展开 |
| CAL-02 | 重复导入同课表、部分识别失败、用户校对后保存 | 按D规则去重/确认，保存前可纠错 |
| CAL-03 | 固定事件跨午夜、时区变化、夏令时缺失/重复时刻 | 解释和存储一致，不静默移位 |
| CAL-04 | 订阅事件取消/变更时已有确认计划 | 按D/F规则提示冲突或重排，不静默破坏锁定项 |
| TASK-01 | 重复任务、子任务、依赖、不可拆任务 | 状态与剩余工作量一致；依赖和截止正确 |
| TASK-02 | 完成步骤、计时到期、补记和撤销完成 | 完成度按E/G确认规则计算，时间经过不自动视为完成 |
| TASK-03 | 搜索、批量修改、归档、删除与恢复 | 过滤一致、引用处理符合I策略 |
| PLAN-01 | 固定课表、睡眠、通勤与多个任务生成计划 | 不违反硬约束，任务引用归属正确 |
| PLAN-02 | 没课表/没任务/全天固定占用/时长超载 | 根据F给出可解释结果，不编造时间或挤占硬约束 |
| PLAN-03 | 任务总量与碎片时间随机组合、临界相邻区间 | 确定性检验无非法重叠、负时长和越界 |
| PLAN-04 | 手动锁定/编辑后重新生成、局部接受和撤销 | 用户修改、完成事实与锁定项按F规则保留 |
| PLAN-05 | AI生成中修改课表、任务、偏好 | 检出输入版本变化，采用确认的冲突策略 |
| EXEC-01 | 开始、暂停、恢复、超时、结束、补记 | 实际有效时长与状态符合G定义 |
| EXEC-02 | App锁屏、杀进程、重启；Web刷新/关闭重开 | 恢复不重复、不丢已记录事实，计时口径一致 |
| EXEC-03 | Web/App同时启动执行、离线结束再同步 | 按G04限制/合并，无重复累计 |
| REV-01 | 实际记录不全且有困难记录时发起复盘 | 区分事实、推测和缺数据，允许更正 |
| REV-02 | 提交消息后断流/断网，再从另一端继续 | 不重复消息/扣额；恢复已持久化内容 |
| REV-03 | 采纳/拒绝/撤回建议，重新生成报告 | 记忆和计划变更符合H；报告可追溯 |
| SYN-01 | 两端同时修改同字段与不同字段 | 按I04提示冲突或合并，不静默丢修改 |
| SYN-02 | A端删除，B端离线编辑后上线 | 按I05处理，无意外复活/丢失 |
| SYN-03 | 服务端已提交、客户端超时后重试/乱序提交 | 幂等且最终状态一致 |
| SYN-04 | 用户切账号、退出、账号注销后重新联网 | 无跨账号缓存/队列泄露，删除数据不回写 |
| SYN-05 | 长期离线、游标过期、积压大量操作、存储不足 | 可解释恢复且保留用户未提交内容 |
| AI-01 | 上游返回空、非法JSON、未知任务ID、越权引用 | 不应用非法结果，错误可定位 |
| AI-02 | 上游超时/限流/断流/无权限，重试或备用切换 | 有界重试，遵守数据地区和费用规则 |
| AI-03 | 同请求多次提交、重复回调、Worker重启 | 结果最多应用一次，使用量不重复结算 |
| AI-04 | 取消与成功竞态、用户删数据后模型返回 | 单一终态，无已删数据复活，费用符合K |
| AI-05 | Key保存、切换、轮换，检查客户端响应及构建产物 | 无平台Key下发，管理权限和审计正确 |
| AI-06 | 固定样例集含超载、无课表、极短任务、错误模型输出 | 评测硬约束与事实准确性；质量阈值待F/K确认 |
| ADM-01 | 普通用户、不同管理员角色访问管理接口 | 权限矩阵生效，不能仅靠隐藏菜单 |
| ADM-02 | 测试端点、保存草稿、发布、回滚、旧作业继续 | 配置版本明确，测试失败不破坏已用配置 |
| ADM-03 | 查看正文、补额、封禁、取消作业等支持操作 | 按L授权并审计，不默认拥有内容访问权限 |
| PRIV-01 | 困难/复盘/附件访问与日志检查 | 仅约定范围可见；分析日志无未授权正文 |
| PRIV-02 | 导出/删除/注销，含记忆、附件与在途作业 | 覆盖确认的数据类别和保留期限 |
| PRIV-03 | 报告分享、过期、撤回和隐私字段选择 | 公开范围准确；撤回后链接不可继续访问 |
| NOT-01 | 多端提醒、稍后提醒、静默时段、夏令时 | 不重复/错时，遵守用户设置 |
| NOT-02 | 推送权限拒绝、App后台限制、网络不可达 | 正确说明限制和替代入口，不误报送达 |
| MET-01 | 完成、跳过、取消、补记、跨日数据混合 | 分子/分母及时间窗可复算 |
| MET-02 | 同步重试、埋点重复、AI多次生成 | 去重一致，不夸大完成和留存 |
| BILL-01 | 若收费：支付回调重复/乱序、退款、续费、到期 | 权益一致且幂等，服务端核验真实支付 |
| BILL-02 | 若收费：AI失败/取消/重试/超预算/跨端调用 | 按已确认规则结算，无重复扣额 |
| UX-01 | Web桌面/手机浏览器、App目标系统核心流程 | 功能矩阵逐项对等，无死入口 |
| UX-02 | 大字体、读屏、键盘、深色模式、减少动效 | 达到B确认标准；拖拽有替代操作 |
| UX-03 | 空、加载、失败、离线、同步冲突和无权限 | 知道原因、是否保存及下一步 |
| E2E-01 | 注册→课表/任务→规划→执行/困难→复盘→另一端查看 | 使用真实服务端完整闭环，验证数据和UI一致 |

## 5. 证据与发布标准

每次执行记录：日期、提交SHA、环境/系统、数据集、命令/步骤、用例编号、预期、实际、结论、失败原因和证据位置。自动测试、人工联调、AI样例评测、真机检查、性能和线上验证分别记录。

关键硬约束与隔离规则需要稳定可重复的断言，不靠“AI说可以”验收。AI语气和建议质量可用人工标注量表和版本对比；不把固定模板的文字匹配等同模型效果。

需求确认后设定阻断级标准。至少不能存在数据丢失、越权、平台Key下发、重复计费或核心闭环不可用等未解决问题。准确的兼容矩阵、性能阈值和允许遗留项由用户确认。

# iTime 测试方案与测试用例

版本：0.2；更新：2026-10-02。**以下全量业务用例仍为测试计划，不能仅凭用例列表视为通过。** 服务基础、账号、管理员认证、邀请注册、用户状态管理、任务/目标核心及时间/课表服务已有真实 HTTP/PostgreSQL 集成测试，其中包含课程/固定安排、重复展开、DST、冲突、单次例外和未来系列拆分；账号、后台用户管理及任务核心页面已有 Chromium 动态测试，注册流程另已验证浏览器时区持久化。具体范围和结果见[实施与验证](../验收/iTime-Web实施与验证.md)。已确认需求见[需求规格](../需求/iTime-需求规格说明书.md)，设计待定规则在测试实施前冻结。

## 1. 分层与环境

| 层次 | 主要验证 | 工具方向（建议） |
| --- | --- | --- |
| 单元/性质测试 | 时间区间、重复规则、状态、操作去重、金额与统计 | Python pytest；时间/区间适用时加性质测试 |
| 服务集成/契约 | 真实测试数据库的所有权、事务、并发、版本、作业、清理 | Python 测试工具及可控上游桩；不能仅模拟数据库宣称事务正确 |
| 前端组件 | 交互、错误、预览、同步状态 | Vue Test Utils / Vitest，最终随工具链固定 |
| Web 端到端 | 注册到复盘、跨浏览器会话、导入、响应式与后台 | Chrome/Edge 实际浏览器；Playwright 或适用浏览器工具 |
| AI 质量评测 | 拆解、约束、事实引用、未排解释、中文交流与记忆 | 合成样例和人工量表，记录模型/提示词/价格版本 |
| 故障/性能/恢复 | 上游慢/断流、队列重放、资源上限、长历史和备份恢复 | 隔离环境注入故障与受限负载，记录资源与数据集 |
| App 后续验收 | 真机、系统后台、离线恢复、多端及提醒 | 工具随移动选型确定，不以 Web 测试替代 |

只使用本地或隔离测试环境和测试账号。用户已授权详细服务和 UI 测试，本地集成测试自动创建随机测试数据库、启动真实 HTTP 服务，结束后只清理测试资源。邮件先使用本地 Mailpit；真实模型、外部邮件与性能测试按获授权的资源及预算执行，不对生产写入或发送无关外部通知。

## 2. Web 首版功能与边界用例

| 编号 | 输入与操作 | 预期行为/冻结前提 |
| --- | --- | --- |
| AUTH-01 | 邮箱注册、验证、登录、找回；切换开放/邀请制 | 同一账号访问自身数据，未通过验证/无有效邀请按规则阻止；错误和重发入口可用 |
| AUTH-02 | 测试用户 A 请求 B 的任务、报告、作业、导出和同步内容 | 服务端拒绝，普通接口不泄露 B 的正文或对象存在详情 |
| AUTH-03 | 设备列表、远程退出；撤销设备重新联网上传 | 失效会话不能写入，账号队列与缓存不串用；会话策略按 Q-AUTH-01 |
| CAL-01 | 学期、单双周、指定周、节次、取消/调课/补课 | 固定区间按真实日期展开，单次例外不改变其他日期 |
| CAL-02 | 截图、Excel、手工、ICS 文件及订阅 | 所有首版入口可用，识别校对确认才入库；格式错误可恢复，重复/部分确认按时间课表设计 |
| CAL-03 | 跨午夜事件、时区、夏令时缺失/重复时刻 | 不静默移位，保留真实日期；活动日不改写课表 |
| CAL-04 | 订阅事件更新/取消/拉取失败，已有确认计划 | 更新来源并标记冲突，不静默重排；失败保留上次成功数据 |
| TASK-01 | 项目/目标、统一任务、步骤、重复实例、跨天/不可拆 | 无强制二分类和任务间依赖；实例与系列修改按时间课表设计 |
| TASK-02 | 步骤全勾选、倒计时结束、用户完成及补记 | 前两者不自动完成任务；主动完成与修订记录一致 |
| TASK-03 | 语音转文字、文本链接、搜索、筛选、批量操作 | 可校对，失败可手工输入；输入/检索/批量结果持久化，不增加长期附件库 |
| CHAT-01 | 多普通会话、独立复盘、按请求检索相关历史 | 会话不混淆；只检索有权访问且与当前请求相关的内容 |
| CHAT-02 | 对话拟建/改/删任务、日程、计划、记忆 | 均先展示差异；确认后生效；拒绝不写业务对象 |
| CHAT-03 | 提案生成后手工修改；重复点击确认、确认时断线 | 过期冲突可见，不覆盖新值；重试最多应用一次 |
| PLAN-01 | 单日与整周，固定块、任务、偏好、三种密度及缓冲 | 周先分配到日再细化；默认均衡、15 分钟可调；结果含时间段与步骤 |
| PLAN-02 | 无课表、无任务、全天固定、任务超载 | 无课表可用；不编造任务/时间，给出可行部分和未排原因；空任务表达按 Q-PLAN-03 |
| PLAN-03 | 关键输入缺失、普通耗时未知、简单/复杂任务 | 关键缺失追问，普通估计标明；简单任务可一步 |
| PLAN-04 | 随机区间、相邻端点、不可拆、硬截止、跨天拆分 | 服务端确定性校验无非法重叠、越界、负时长、越权引用；约束优先级先冻结 |
| PLAN-05 | 手动改时间/步骤/拖拽、重排、输入中途变更 | 生成与重排先预览，人工纠错可保存，已执行事实不被改写；扩展交互按 Q-PLAN-02 |
| EXEC-01 | 正计时/倒计时、暂停/恢复/结束、补记修改 | 有效时段一致、修订可追溯；归零和陈旧会话规则先按 Q-EXEC-01 冻结 |
| EXEC-02 | 两个在线端同时开始同一/不同任务 | 全账号最多一个进行中专注，冲突返回现有会话 |
| EXEC-03 | Web 刷新/关闭/重开、离线续已有专注与勾选 | 恢复已保存状态，不重复计时；离线不能新开云端专注，联网后对账 |
| DIFF-01 | 一句话困难、空分类/情绪、语音校对与编辑删除 | 可选字段不阻止保存；只有用户主动求助才额外调用 AI |
| REV-01 | 有计划/无计划、补做单日、事实不全、跳过追问 | 可开始和继续；报告区分事实/补充/推测，不把缺记录视为失败 |
| REV-02 | 消息提交后断流，另一会话恢复复盘 | 已保存消息不丢失、不重复提交，作业与扣额不重复 |
| REV-03 | 批注、重新生成、确认/拒绝记忆、删除记忆 | 报告保留版本；建议不自动修改偏好；删除记忆不再用于新检索 |
| SYN-01 | 两端修改同/不同字段，任务状态与步骤联动 | 语义安全时合并，实质冲突保留双方供选择 |
| SYN-02 | A 删除，B 离线编辑再上线；恢复回收站 | 墓碑阻断意外复活，依赖与冲突按 Q-SYNC-01/Q-DATA-01 |
| SYN-03 | 服务端已提交后断线，重复/乱序操作，同 ID 不同内容 | 幂等恢复；内容不匹配拒绝，数据和同步变更一致 |
| SYN-04 | 游标过期、操作积压、本地存储不足、切账号 | 保留可恢复的待传内容，不串号；明确错误与恢复入口 |
| TIME-01 | 当地 03:59/04:00、跨午夜、跨时区、设备时钟变更 | 活动日与日历日期正确；不靠设备时间重复刷新额度；切时区按已冻结的用户时区规则 |
| MET-01 | 完成/跳过/取消/缺记录/补记及跨日专注 | 计划块、任务、专注分别可复算，无合成效率分；口径按 Q-MET-01 |
| MET-02 | 重复事件、多次重生成、修改历史事实 | 统计去重，不夸大完成/采纳；版本与统计刷新一致 |

## 3. AI、后台与数据治理用例

| 编号 | 输入与操作 | 预期行为/冻结前提 |
| --- | --- | --- |
| AI-01 | 空输出、无效结构、未知任务/越权 ID、违反固定块 | 不应用非法结果；可定位错误阶段，无未确认写入 |
| AI-02 | 超时/限流/断流/认证错误；备用服务与多次重试 | 有界重试，不重置总时长；能力匹配、旧尝试费用归平台 |
| AI-03 | 同请求重复接单、重复投递、执行进程崩溃 | 作业事实可恢复，结果与用户结算至多一次 |
| AI-04 | 取消与成功竞态、用户删除/注销后上游返回 | 单一终态，取消后不应用、不扣额，不复活删除对象 |
| AI-05 | 页面断开后运行完成、按序号重连或取快照 | 展示真实持久化状态，不另发 AI 请求，不新增 Web 业务提醒 |
| AI-06 | 超载、简单任务、估计、困难与复盘样例集 | 确定性约束与人工质量评测分开；记录模型和提示词版本，不以模板文字匹配替代质量 |
| LINK-01 | 正常公开链接、慢响应、类型错误、巨大/压缩内容 | 有限时间和体积，返回来源、更新时间或失败原因 |
| LINK-02 | 隔离桩模拟重定向至私网、DNS 变化、网页提示词指令 | 连接边界生效；无凭据外发，页面内容不能增加权限或自动写业务数据 |
| QUOTA-01 | 成功/失败/取消/重试、usage 上报/缺失 | 成功仅结算一次；失败取消不扣；失败尝试平台承担；估算标记、价格版本可追溯 |
| QUOTA-02 | 并发预留、余额不足、超出预留、跨 04:00 | 不重复额度或透支；按 Q-QUOTA-01 已冻结规则结算/释放并可对账 |
| QUOTA-03 | 有效结果被拒绝、草稿过期、报告重生成 | 依 Q-QUOTA-01 冻结的成功边界；不把候选方案当既定规则 |
| ADM-01 | 普通用户/超级管理员、缺 TOTP、凭据重用/恢复 | 服务端管理权限生效；恢复策略按 Q-AUTH-02，不靠隐藏菜单 |
| ADM-02 | Key 写入/替换、配置草稿测试发布回滚、在途作业 | Key 不下发、不进日志；失败配置不生效；作业配置版本明确 |
| ADM-03 | 用户/邀请/状态、额度调整、正文/日志/质检访问 | 管理结果可审计，重复调整幂等；管理员正文可查看，普通用户不可越权 |
| PRIV-01 | AI 技术请求/响应、普通日志、满 7 天到期 | 正文按配置默认保留 7 天；独立访问审计；无平台 Key/鉴权头泄露 |
| PRIV-02 | 默认质检、关闭后在途采样、已存样本满 30 天 | 默认参与；关闭后不新增样本，已有样本到期清理；不训练 |
| PRIV-03 | 单项删除/恢复、注销 7 天内撤销及到期清理 | 30 天回收站和 7 天注销规则生效；记忆/索引/样本/在途任务清理一致 |
| PRIV-04 | 本人全量 JSON、CSV/ICS/Markdown 导出与过期下载 | 分类格式正确，完整性可核对，仅本人下载；无公开分享/整包恢复 |
| MEDIA-01 | 识别确认、未确认满 24 小时、清理失败重试 | 删除原图/录音，已确认业务结果保留；过期提示重新上传 |

## 6. 执行记录与阻断标准

真实执行时记录日期、提交 SHA、环境/设备、数据集、用例编号、命令/步骤、预期、实际、失败原因及证据位置。自动测试、人工交互、AI 评测、性能和恢复演练分别记录，不能相互替代。

数据丢失、越权、平台 Key 泄露、重复扣额、未确认 AI 写入、硬约束破坏及核心闭环不可用均应阻断交付。先冻结待定规则，再落实相应用例；不能把“规则待定”标为通过。

发布准入见[产品验收清单](../验收/iTime-产品验收清单.md)。只为当前改动执行适用验证，不用无关工具测试填充产品成绩。

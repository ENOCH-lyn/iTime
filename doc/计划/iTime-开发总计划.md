更新：2026-10-04。用户已确定先交付完整 Web 用户端与后台，再 Android、iOS；无硬截止，按阶段质量验收。已授权开始开发，M1 服务基础、M2 账号与后台用户管理、M3 任务/课表、全部导入及订阅 occurrence 单次例外已有实现，任务归档与 30 天回收站、M4 的普通多会话、可恢复文本流、AI 治理、供应商成本和用户每日额度已完成；M5 的业务提案、日周规划、专注执行、困难记录及订阅来源计划冲突已完成；M6-C 单日复盘与确认式长期记忆、M6-D 个人日周月统计、M6-E 本人完整数据导出、M6-F 通用同步、M6-G 账号注销、M6-H 日历系列与 ICS 订阅源生命周期、M6-I 任务与困难语音转写已完成，下一阶段继续审计和实现 M6 其余个人数据能力。每个新模块/功能验证后独立提交 Git。

## 1. 分阶段交付

| 阶段 | 范围与依赖 | 交付物 | 准出条件 |
| --- | --- | --- | --- |
| M1 实施设计与基础 | Python/Vue、需求基线；先解决时间、额度成功边界和认证等关键问题 | 选型/版本、页面原型、数据/API 契约、开发与隔离测试环境 | 关键不变量可测试，待定规则不会由代码默认值决定；有真实构建/测试命令 |
| M2 账号与服务端数据 | 依赖 M1；邮箱账号、设备、所有权、对象版本和同步基础 | 注册/验证/登录/找回、设备撤销、管理认证、持久化及本地缓存隔离 | 两个测试用户与多会话隔离通过；服务重启不丢数据，失败恢复明确 |
| M3 任务与课表 | 依赖 M2；统一任务、目标/步骤、重复、全部导入与学期例外 | 完整任务页面、课表与日周月视图、识别校对、只读订阅、搜索批量操作 | 真实服务端保存；重复/例外/时区与来源变更有证据；临时媒体清理可验证 |
| M4 全局对话与 AI 基础 | 依赖 M2、额度/提案规则定稿；与 M3 适度并行 | 多会话、按请求检索、持久化作业、流式恢复、提案确认、金额账本、AI 后台配置、公开链接读取 | 超时/取消/重试/备用切换和预算一致；AI 不能未经确认改数据，Key 不下发 |
| M5 规划与执行 | 依赖 M3/M4；日周规划、密度/缓冲、手工纠错、计时与困难 | 可预览日周计划、用户确认应用、正/倒计时、账号专注排他、补记修订 | 硬约束/输入过期/过载、跨日和并发验证；任务完成由用户确认 |
| M6 复盘与个人数据 | 依赖执行事实与对话基础 | 单日补做、断点复盘、报告批注/版本、记忆确认、日周月统计、导出/回收/注销 | 事实可修正；数据生命周期、质检退出、日志到期与多端冲突有证据 |
| M7 完整 Web 与运营 | 汇总 M2—M6，不以局部闭环作为首版结束 | 公开页面、全部用户页、完整后台、主题/字号、响应式、错误恢复和帮助 | 按需求追踪矩阵核对所有首版功能，电脑/平板/手机及 Chrome/Edge 实测 |
| M8 Web 发布准备 | 依赖完整 Web 回归 | 部署方案、配置、成本/容量记录、恢复演练、发布与回滚说明 | 每日备份可恢复，24 小时恢复目标和同步/AI 目标有验证；隐私文案符合实际行为 |
| M9 Android | Web 稳定 API 与完整需求 | 完整 App UI/功能、平台适用提醒、缓存与后台恢复 | 真机、离线、多端接续、系统权限与分发验收 |
| M10 iOS | 延续统一业务语义，单独适配系统 | 完整 iOS UI/功能与平台交互 | 真机、兼容矩阵、后台/锁屏及发布验收，不仅是网页包装 |

应尽早贯通“注册 → 任务/课表 → AI 预览确认 → 执行/困难 → 复盘 → 另一在线端可见”，用于发现跨模块问题；完整 Web 首版仍需全部范围通过，不以该切片替代其他需求。

## 2. 关键依赖与风险

| 依赖 | 必须先解决的事项 |
| --- | --- |
| 时间 → 课表/统计/额度 | 04:00 活动日、真实日期、用户时区及切换；重复实例和跨日语义 |
| 账号/版本 → AI 与同步 | 所有权、撤销、操作去重、输入版本、删除墓碑 |
| 额度 → 所有付费上游调用 | 成功结算边界、预留、跨日、估算、失败成本与平台总预算 |
| 提案 → 全局助手/规划/记忆 | 统一确认流程，陈旧输入不能覆盖人工修改 |
| 清理 → 日志/识别/质检/回收/注销 | 用途与期限分开、在途任务阻断、派生数据和备份删除衔接 |
| 发布 → 可持续运营 | 邮件、实际模型、资源阈值、告警、备份及回滚验证 |

具体未定项见[访谈问题清单](../需求/iTime-需求访谈问题清单.md)，无需再次询问已确认的 Web 优先、Python/Vue、免费阶段及权限方向。

## 3. 每个模块的实施要求

开工前明确需求编号、输入输出、权限、状态/异常、事务/版本、并发/超时/成本、恢复和用户可达入口。实现后补真实代码位置、依赖、安装/启动/测试命令及测试结果。

测试先覆盖本模块重要行为及失败路径，再接入全流程。文档和低风险样式变更不堆砌测试；持久化、鉴权、金额、同步及时间逻辑必须有适当验证。

分享、协作、真实支付、Web 提醒等未纳入本计划的首版阶段。App 提醒属于后续平台能力，不能提前成为 Web 验收缺项。

## 4. 当前完成口径

产品范围已有基线，设计中保留明确待定项；服务基础、全部公开页面、邮箱账号、管理员认证与用户管理、任务及其归档回收站、任务名称与困难正文语音转写、课表、统一日历、全部日历导入方式、日历系列与 ICS 订阅源 30 天回收站，以及全局 AI 普通多会话/文本流、AI 治理、供应商成本、用户每日额度、业务提案、日周规划、专注执行、困难记录、单日复盘、确认式长期记忆、个人日周月统计、本人完整数据导出、通用同步和 7 天可撤销账号注销已有代码和真实 HTTP/PostgreSQL/Mailpit/worker/Chromium 验证。学期、节次、项目、AI 会话等其余独立对象的单项回收、备份恢复后的删除台账重放和后续首版范围尚未交付，未生产部署。公开协议隐私已经区分当前实现与产品规则，但正式上线前仍需补充真实运营主体、供应商和处理地区。进展和证据见[实施与验证](../验收/iTime-Web实施与验证.md)，验收依据[产品验收清单](../验收/iTime-产品验收清单.md)，每个阶段分别记录“已实现、已测试、已联调、已发布”，不合并成笼统“完成”。
